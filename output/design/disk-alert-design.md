# 磁盘与资源阻塞提示方案

本稿为设计，尚未接入生产页面。截图采用本次清理前后数据展示问题与恢复状态。

## 展示位置

- 全局顶部状态栏：增加「磁盘 94% · 下载受阻」入口，切换菜单仍然可见。正常时保持简洁；异常时突出状态和可用空间。
- 全局通知条：直接说明哪个实例、多少任务受影响、为什么没有执行。点击进入既有通知中心。
- 通知中心：复用「需处理／自动恢复／已解决」，一个磁盘一个事件，展示占用来源、执行条件、建议动作及受影响任务，避免逐任务刷屏。
- 下载工作台：列表直接显示「等待磁盘空间」或「等待临时预算」，附需要空间、可分配空间和下一次检查倒计时。
- 实例设置 → 空间与日志：增加「空间诊断」，分别展示文件系统空间、应用临时预算、测试残留、日志、部署文件。数据库日志若在其他服务器，应标出所属主机；同一磁盘不能重复计数。

## 触发与恢复

1. 文件系统使用率连续两次达到 80% 显示预警；达到 90% 显示严重预警；实际触发最低空间保护时，明确显示「下载受阻」。使用率预警与任务准入门槛分别判断。
2. 临时预算耗尽时单独说明分类预算、实际用量、尚未写入的预留、本次新增请求。真实磁盘尚有余量时，不写「磁盘已满」。
3. 已结束任务的测试临时文件超过 10 分钟仍未释放，形成清理异常。自动清理失败显示失败原因与重试次数。正在执行或等待补交的文件单独统计。
4. 账号等待原因与通知使用同一个资源诊断结果。倒计时只代表下一次检查，不能承诺到时一定启动。
5. 低空间达到既有恢复水位后恢复任务；纯使用率预警降到触发线以下 5 个百分点并连续两次确认后解除，避免频繁闪烁。
6. 恢复后通知移到「已解决」，保留释放空间、恢复时间、是否已有任务继续和处理记录。人工暂停期间，仅显示「空间恢复，任务仍处于暂停」。

## 占用来源与操作

- MySQL：显示 binlog 占用、保留天数、过期日志预计可释放量。生产操作使用 MySQL 正规清理命令；不得通过删除数据文件实现。
- 测试文件：区分已完成残留、进行中、待恢复。页面默认提供重新检查与查看明细；清理明确列出影响范围。
- 历史部署与镜像：显示未使用历史版本的可回收量，排除当前运行镜像及其共享依赖层；不能把各镜像虚拟大小相加。
- 数据库业务文件、正式素材、系统文件：展示用量，不与测试缓存混为一个清理动作。
- 获取失败显示「待检测／检测失败」，保留上次采集时间；不要把未知来源标记为 0。
- 普通账号只能查看；具有维护权限的账号才能执行清理。删除操作先展示实际可清理条目、影响任务和预计释放量，再确认执行。

## 采集边界

现有应用可直接读取文件系统余量及自己的预算、任务与临时目录；无法仅凭余量推断是 binlog 还是 Docker 占用。主机部署文件与 Docker 占用需要受控的主机采集器；MySQL 指标由数据库采集获取。后台按分钟缓存汇总，文件扫描放在后台按较长间隔执行，打开页面只读汇总，不运行全盘扫描。该功能不应依赖给 Web 容器开放 Docker 管理套接字。
