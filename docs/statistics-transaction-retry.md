# 下载完成后的统计事务重试

2026-11-08 22:46:37 的 MySQL 死锁报告显示，两笔事务对 `download_lists` 和 `schema_settings` 的加锁方向相反。两个任务在下载后的统计登记中收到 1213，异常被 yt-dlp 的 post hook 转成文本后，最终被判为任务失败。

`DownloadStatistics.record_file` 现在复用现有的 `transaction_retry`，仅重新执行完整的数据库登记事务。每次异常先退出事务并回滚，再开启新事务；不会重新下载、处理媒体、上传文件或发布完成回执。正常路径不增加数据库查询。

- 对 1213 死锁、1205 锁等待超时及 SQLite 锁冲突，最多共尝试 3 次，沿用短随机退避。
- 对连接丢失等提交结果可能不明确的异常，不自动重试。
- 每次重试重新检查任务状态、执行者及有效租约；旧执行者不能继续登记。
- 文件账本、会话合计、渠道统计、清单计数及实例计数仍在同一事务中更新；只有提交成功后才清除展示缓存。
- 原有文件身份去重继续有效，重复回调不会重复登记。此保护恢复可重试的事务冲突，不承诺数据库从此不再发生死锁。

同时补全 yt-dlp 原生下载器的短格式响应不完整诊断，例如：

```text
[download] Got error: 231816 bytes read. Giving up after 2 retries
```

这类错误现在识别为可重试的 `transient_failure / incomplete_response`，沿用现有任务尝试次数上限。匹配限定在下载错误/重试诊断中，普通字节数、URL 和敏感字段内容不会触发该分类；明确的 HTTP 403/429、内容限制、验证要求及本地异常保持原有优先级。

回归覆盖：数据库更新后的故障注入与完整回滚、正常和测试下载的账本及计数去重、重试耗尽、丢失连接、重试期间执行者变化，以及真实下载 post hook 的死锁恢复。真实下载测试验证下载器只调用一次、统计更新重试两次、任务成功且只记一个文件。

2026-11-09 验证结果：Windows 下失败分类与 SQLite 统计回归 28 项通过，另一个真实下载 post hook 测试通过。Linux 隔离容器运行 49 项回归通过，未配置测试数据库的 MySQL 回执测试类跳过；随后独立 MySQL 8.4 中的统计、渠道统计和任务管理回归 36 项全部通过。临时 MySQL 容器和内部测试网络已清理，生产容器身份及健康状态未改变。本次尚未部署。
