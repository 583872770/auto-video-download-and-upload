原先定义在 `throughput`、`parallel_http`、`youtube_pacing` 和 `cookie_pool` 中的公开辅助函数
保留导入入口，既有调用者仍可使用原路径。`pool_worker_limits` 保留资源采样与数据库预算读取，
将静态计算交给新模块。

新模块不获取数据库连接、不加锁、不读取 Cookie、不采样主机、不休眠。
容量计算结果本身不是下载授权。租约、实例启动代号、账号归属和实际许可仍在事务中核对。
实例全局任务上限继续通过 Fleet 的统一准入入口执行；自适应控制器继续负责采样历史、压力退避及缓慢恢复。
池内没有可用账号时仍可保留一个进程复查状态，该进程下限不代表有账号或传输额度。

## 一处已复现的边界修复

原 `_admit` 在资源恢复期间无条件写 `cap = 1`。
当一个有效的共享策略把额度限制为 0 时，页面诊断显示 0，准入却仍可发出一个许可。
现在恢复期间取 `min(1, limit)`，零额度继续关闭，恢复规则只会收紧额度。

使用 Git 中原有 `_admit` 方法运行同一组新边界测试，明确复现仅 `zero-recovering` 子场景失败；
整理后的实现通过该场景。日志：`.cache/baseline-repair/concurrency-original-recovery.log`。
该检查针对许可层边界，不表示正常页面能够配置零路的自定义渠道。

## 回归契约

新增三个测试方法，其中渠道准入的两个方法也由既有 MySQL 契约夹具复用：

1. 页面显示的最大传输容量与实际可获得的许可一致，覆盖正常、活跃/过期共享策略、冷却、恢复及零额度恢复边界。
2. 热下调连接预算后，已有许可继续存在；直到占用降至允许范围内才接纳新任务，释放后可再次准入。
3. 进程准备容量按上游组计算，新增别名不增加组容量；明确独立的上游才增加容量，关闭准备名额时进程数随之受限。

原有契约继续覆盖：等待者热读取额度、不重复解析；跨进程原子准入；过期租约和旧执行者隔离；
Cookie 独占实例绑定；重复导出共享账号容量；共用间隔设置为零仍保留账号间隔、冷却和已预留的窗口；
资源压力降低进程后不会在下一轮采样立即反弹；MySQL 行锁不阻塞其他准入或清理。
