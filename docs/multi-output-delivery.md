# 多类型交付：实现与使用

本次完成代码与页面实现，并于 2026-11-13 部署至洛杉矶服务器。此前的交互原型和设计方案见 [设计文档](multi-output-delivery-design.md) 与 [页面原型](design/delivery-prototype.html)。本文以实际实现为准。

## 使用流程

1. 任务中心新建任务时勾选交付内容：字幕、无声视频、纯音频、音视频成品。支持任意非空组合，共 15 种。默认只交付音视频成品。
2. 设置字幕语言、SRT/VTT、人工/自动字幕来源及语言完整性要求；按需选择画质上限、MP3、MP4 或 MKV。
3. 添加或导入来源，在下载工作台选择任务及实例后开始。新要求使用 yt-dlp，实例必须安装 FFmpeg 和 FFprobe。
4. 在任务概览、视频清单及交付账单查看要求版本、逐类型/语言完成情况、文件数与大小。视频清单可以单独按交付状态筛选。
5. “交付文件”页面按类型、语言、来源筛选，预览字幕、试听音频、播放视频或下载。浏览器不支持某些原始编码时，可下载后播放。原视频素材库保留为历史入口。
6. 缺项可逐条或多选补交。多选补交明确选择“沿用原要求”或“使用最新要求”，并可取消。已校验、可读取且语义要求相同的正式文件可以复用。
7. 来源没有所需字幕/音轨时显示“待确认缺失”，不会冒充全部交付。只有用户填写原因并接受缺失，才变为“已按约定结束”；确认行为留在任务历史中。

“执行已完成”和“交付已齐全”分别显示。单纯缺少字幕不会删掉已完成的媒体文件。仅字幕时不获取媒体轨道；音频、无声视频和成品同时选择时，共用一次画面和一次音频获取。

## 要求版本与兼容

- 修改任务要求使用现有 `edit_version` 乐观锁，过期编辑返回 409。
- 来源首次领取时固定要求版本，已固定的来源继续使用原版本。修改影响尚未开始的来源；显式按最新要求补交可以切换版本。
- 历史已开始、没有新交付快照的来源继续历史行为；显式选择最新要求补交后才采用新流程。
- 新页面始终显式提交 `delivery`。兼容旧 API 客户端：`POST /api/jobs` 未提供 `delivery` 时仍创建历史行为任务，不自动改变其渠道、可选字幕或账单口径。
- 所有已登记的下载实例（worker/hybrid，包括离线登记）必须先升级到支持 `delivery_schema_version=1` 的版本，才能创建/修改新要求，避免旧执行代码误处理。实例卡片显示能力。
- 新要求第一版仅使用 yt-dlp。未启用该渠道、缺少 FFmpeg/FFprobe 时明确阻止执行；第三方下载器仍供历史任务使用。
- 全局设置可保存之后新建任务的默认要求，仅管理员或未初始化账户时的本机访问可以修改。

## 文件、恢复和账单

- 每个正式产物由客户任务、来源、类型、语言、有效质量/格式规范确定语义 ID。要求版本号和随机尝试路径不参与去重；不同客户任务独立计费。
- 校验实际媒体流及有效时长。无声视频必须没有音轨，音频必须没有画面，成品必须同时有画面与声音；字幕必须含时间轴条目。
- 发布使用独立文件路径；每次状态更新及账单登记校验任务所有者与租约。停止后失去租约的旧执行者不能登记新交付或费用。
- 已验证但尚未上传的正式文件先保存为不可下载的待发布记录，不计费。OSS 失败后在同一实例重试可直接复用该文件上传；跨实例无法读取本地暂存文件时重新获取。
- OSS 或本地转换/资源错误不触发来源渠道失败切换，也不污染 YouTube 会话健康。Cookie 拒绝警告会立即终止，403、429 和账号限流继续进入原有分类与保护流程。
- 补交先检查本地文件或 OSS 对象是否仍可用。本地损坏/删除的文件会重新生成；修复相同语义产物不重复计费。
- 费用按实际已交付文件的字节累计，多语言字幕逐文件登记。共用原料的下载网络量和多个成品的交付量是不同指标。
- 测试产物记录在原测试账本，不收费，也不出现在正式文件页；测试结束删除文件。崩溃恢复只有在固定要求全部完成时才允许整条任务完成，部分回执不能冒充完整交付。切回正式模式会重新取得正式文件。
- 不回填或重算历史字幕、音频费用。新旧任务都使用现有账单汇总，避免重复叠加两份账本。

本地/OSS 文件接口支持 HTTP Range，便于播放定位。跨实例读取通过限定的节点 GET/HEAD 协议，节点令牌不获得全局文件列表或客户管理权限。文件接口不接受浏览器提供的本地路径。

## 代码与数据

新增五张表：`job_delivery_contracts`、`delivery_runs`、`delivery_requirements`、`delivery_artifacts`、`delivery_totals`。迁移 `20261113_delivery_outputs` 只增量建表，不扫描或改写整个来源队列。

继续复用 `download_deliveries` / `download_test_files` 作为原子账单回执，以产物语义 ID 去重。产物状态、客户/会话汇总和账单回执在同一个有租约保护的事务中登记。没有另建独立 `delivery_receipts` 表。

`webapp/delivery/contracts.py` 校验要求及语义变体；`executor.py` 合并计划、下载、复用、转换和发布；`verify.py` 校验；`artifacts.py` 负责版本、产物和汇总；`routes.py` 提供交付 API；`storage.py` 代理跨实例文件。没有另建计划器或工作进程，仍使用现有队列、账号池、限流、磁盘预算及本地处理限制。

共享页面组件为 `static/delivery_options.js`；新文件页为 `/delivery-files`。任务中心、任务设置、工作台、系统默认设置、实例卡片、分类账单与 CSV 均已接入。

## API

| 接口 | 行为 |
| --- | --- |
| `GET/PUT /api/delivery/defaults` | 获取/保存新任务默认要求 |
| `POST /api/jobs`、`PUT /api/jobs/<id>` | 在现有请求中提交 `delivery`；编辑携带 `edit_version` |
| `GET /api/jobs/<id>/videos?delivery_status=review` | 分页查看逐来源交付状态/要求 |
| `GET /api/delivery/artifacts` | 正式可下载文件列表，游标分页 |
| `GET /api/jobs/<id>/artifacts` | 客户任务文件列表 |
| `GET/HEAD /api/delivery/files/<artifact_id>` | 鉴权预览/下载，`?download=1`，支持 Range |
| `POST /api/jobs/<id>/redeliver` | `ids`（1–1000 条）、`use_latest`（默认 false） |
| `POST /api/jobs/<id>/requirements/<task_id>/<key>/waive` | 接受来源缺失，必须提交 `reason` |
| `GET /api/jobs/<id>/artifacts/export` | 流式导出分类交付 CSV |

接口沿用现有用户登录、CSRF 和管理员/操作员/只读权限。

## 验证

测试入口为 `tests/test_delivery.py`，22 项均通过：使用本地 HTTP 服务与 FFmpeg 生成真实画面、音频及字幕，只模拟上游元数据解析；实际执行 HTTP 传输、FFmpeg、FFprobe、API、数据库和账单登记。覆盖全部 15 种组合，并核对源文件请求次数。

还覆盖多语言缺失策略、明确格式转换、字幕缺失确认、无重复下载/收费的补交、合同升级复用、上传失败后直接上传、字幕限流保留媒体、损坏文件修复、租约失效、完整/部分测试崩溃回执、测试转正式、403/429/账号限流分类、Cookie 拒绝、历史条目显式升级、OSS Range 与编辑冲突。

旧任务、下载、OSS、统计、管理登录及磁盘预算回归：98 项运行，95 项通过、3 项按原测试环境条件跳过。实例/工作台回归另覆盖 52 项；其中两项沿用账号改造前的测试假设，本次同步为“拒绝无账号 Cookie 上传”和“展示只读取元数据”，单独复测。桌面 1440px 和手机 390px 浏览器验证通过，新建/修改、文件页、默认设置均无脚本错误。未使用真实客户账号请求 YouTube，也未向真实 OSS Bucket 写入文件。
