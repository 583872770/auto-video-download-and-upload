# 自动吞吐与多服务器部署

在所选实例的“系统设置 → 资源与日志”选择“自动适应服务器资源”。传输并发上限支持 1–64；自动模式把它作为上限，按实际 CPU、内存和运行压力选择当前额度。公网带宽目标填写 Mbps，0 表示在资源允许范围内探索。浏览器数量仍为独立上限，不超过 16。

新 Docker 配置默认自动模式、传输上限 64、带宽目标 0。已有持久化配置保持原值，升级不会自动覆盖；可在页面选择自动模式。每台实例独立保存设置，配置较弱的机器会选择较小额度。代理健康冷却对已有配置也生效。

## 调度行为

- 文件解析、转换和传输继续归属于同一任务和租约。自动模式在传输额度之外增加少量准备任务，并限制所有工作进程总量，最多 96 个；就绪地址仅留在持有租约的工作进程内，不写入共享数据库、不跨实例传递。
- 同时传输由跨进程操作系统锁控制。进程退出自动释放；降低额度让已有传输完成再接收新传输。准备好的地址最多等待传输名额 120 秒，超时按资源等待重新排队，不消耗视频重试次数或影响其他实例。
- 等待传输时关闭该进程空闲浏览器，防止已经准备好地址的任务继续占住浏览器名额。浏览器解析仍受独立容量和磁盘预算约束。
- 每 5 秒采集资源与接收流量，以最近最多 6 次采样计算接收速率。调节间隔至少 30 秒；传输名额持续繁忙且资源允许时逐步探索增加并发。增加后无明显吞吐收益则退回并等待 120 秒再探索；资源压力升高则降低额度。没有足够解析供给时不会仅因带宽未满而无限增加进程。
- 识别 CPU affinity、cgroup v2 CPU/内存限制及可见祖先限制，并兼容常见 cgroup v1 限制。公网带宽目标独立配置，不把千兆网卡协商速度当成公网带宽。
- 实例页显示传输额度、准备与传输总额度、浏览器额度、容器/主机当前可见接收速率及调节原因。接收速率包含浏览器和重传流量，最终收益应结合成功视频及成功字节统计判断。

## 代理故障处理

记录“节点 × 下载器”的连接/TLS 故障。单个下载器连续 3 次连接故障进入冷却；同节点短时间内累计至少 3 次、涉及至少 2 个下载器的连接故障，触发节点整体冷却。轮换时跳过冷却节点；同节点仅个别下载器冷却时，其他已选下载器仍可使用。所有候选不可用则短暂退避，任务保留，不作为坏视频计费或耗尽重试。

基础冷却为 120 秒，单下载器重复故障逐步延长、最多 900 秒；节点整体冷却期满只放行一个恢复任务。恢复任务连接仍失败则重新冷却，成功传输后清除相应冷却。视频不存在、普通 404、网页验证失败以及磁盘资源问题不会被当作节点连接故障。签名 URL、Cookie、代理凭据不写入健康记录。

手动选择的固定节点不会自动替换成未选择节点；自动轮换只在用户配置的候选集合中选路。最高画质、下载器选择和原有优先级保留，跳过暂时冷却的下载器会记录事件。downmp3 的 best 仍是该接口当前最高 1080p，不与其他来源的 4K/8K 等同。

## 数据库与集群

全局任务上限支持 0：只按各实例额度执行。正数仍额外限制集群所有在途任务，包含解析与转换；已有 32 等配置不会被升级覆盖。新集群默认 0，方便增加服务器后使用各自额度。

工作进程由已完成数据库初始化的调度器签发与当前数据库及数据库源码匹配的启动标记，避免每次启动都竞争结构升级锁。普通 Web 启动仍执行原有迁移检查；标记不匹配时照常检查。

本机磁盘预算 SQLite 使用 WAL，并保留 FULL 同步及原子预留；读预算快照不会阻塞写入提交。业务任务、账本及去重继续使用原 MySQL。MySQL 5.7 共享领取锁仍然存在，升级到 8.4 和重新设计集群名额租约可另行实施；本次未升级数据库引擎。

## 运维与回退

配置切回手动模式即可恢复按进程数控制；已有任务完成后生效，不强制终止传输。控制文件是实例状态目录中的 `throughput.json`、`transfer-slots/` 和 Clash 目录的 `route-health.json`。这些文件不包含签名下载地址。每台服务器必须保持独立状态卷。

自动模式不保证源站或代理供应商能提供目标带宽；多服务器共用出口仍可能共享限速。普通 MP4 没有因分片并发参数自动变成多连接；本次没有对尚未验证 Range 能力的源启用并行分段，也没有改变画质来换取表面速度。
