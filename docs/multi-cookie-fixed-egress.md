# 两组 Cookie 与固定 IPv6

通过两个独立执行实例同时使用两份 Cookie。每个实例固定一个出口、一个 Cookie，分别记录进度和登录状态。上传多份 Cookie 本身不会增加并行账号数量，也不证明它们属于不同账号。

推荐先按每实例 2 路、每实例至少 60 秒启动一个视频验证，解析并发 1、分片并发 1，并启用 yt-dlp sleep 预设。两个实例均将内置渠道传输上限设为 4、连接上限设为 8；这是源站共享预算，每实例实际并发仍设为 2。使用手动调度与手动吞吐模式，可避免自动模式额外准备任务占用对照试验的名额。限流保护仍有效。

## 部署

在 Docker 主机已配置两个可用公网 IPv6 的前提下，创建两张固定 SNAT 网络。以下地址参数需替换为自己的已配置地址，不要照抄为新的网卡地址：

```powershell
python scripts/setup_ipv6_network.py --source <IPv6-A>
python scripts/setup_ipv6_network.py --source <IPv6-B> --name video-fixed-ipv6-b --subnet fd42:76b7:2027::/64
docker compose -f compose.local-mysql.yaml -f compose.ipv6.yaml -f compose.account-b.yaml --profile account-b up -d --build
```

第二个实例 ID 默认为 `us-account-b`，内部管理地址为 `http://account-b:5000`，不额外发布公网端口。主实例与第二个实例使用同一 MySQL，但配置、状态及视频卷彼此独立。首次创建的新实例保持暂停；不会继承全局任务选择。

在管理页面分别选择两个实例，为每个实例上传并选用自己的 Cookie，设置 `youtube_source_address: '::'` 以固定使用该实例网络的 IPv6。检查各自的登录、出口及视频下载，再分别选择同一个目标任务并启动；任务领取通过数据库协调，避免同一任务被两个实例同时领取。

## 使用边界

- Cookie 只保存在上传时选中的实例。主实例中修改或删除某份配置，不会自动同步第二个实例；更新第二组 Cookie 时应先选择第二个实例。
- 「停止当前实例」只停止所选实例。需要全部停止时，请在实例管理中分别停止两组。
- 每个实例保持固定账号与出口，不按失败自动轮换。明确账号限流、机器人验证或登录失效时应停下检查；切换账号不应清除已有冷却。
- 源站渠道与限流状态仍共享，一组出现明确源站限流可能使另一组也等待。这样保留保守保护，不能把两组解释为两份独立额度。
- 同一账号的不同 Cookie 可能共享限制；同一个 /64 的 IPv6 也可能共享限制与带宽。增加地址不能保证增加容量。
- 本次服务器仍使用 `storage_mode=test`，完成下载及校验后删除文件。若需保存视频，应先规划磁盘容量。

重建时应一直携带三个 Compose 文件及 `--profile account-b`，否则可能遗漏第二实例或固定 IPv6 网络。不要删除 MySQL、Cookie 或状态卷来处理限流。
