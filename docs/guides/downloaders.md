# 下载器与兼容任务

新建多类型交付任务当前只使用 **yt-dlp**，并要求 FFmpeg / FFprobe；它可以获取字幕、音频、无声视频和音视频成品。使用方法见 [交付要求](delivery.md)。

历史兼容任务仍支持 yt-dlp、yt5s、downmp3、yt1d、Bergung / Cobalt 的尝试顺序。各下载器使用自己的画质和超时配置；第三方接口的“最高画质”不等同于 YouTube 原始最高画质，解析成功也不代表文件最终通过校验。

## 设置顺序

在系统设置选择实例，勾选所需下载器、排序并保存。也可通过该实例配置文件的 `download_methods` 指定，例如：

```yaml
download_methods:
  - downmp3
  - yt5s
```

至少选择一个，不能重复。兼容任务在领取时读取当前实例策略，运行中的任务保留执行快照；切换下载器后重新下载，避免拼接不同编码的残留文件。新交付任务的能力检查不会因这里勾选第三方渠道而绕过。

yt-dlp 的账号准备见 [账号管理](accounts.md)、[YouTube 登录](youtube-login.md)。网页渠道的 Chromium、显示环境和人工验证入口见 [浏览器环境](../deployment/browser.md)。

## YouTube 字幕请求

字幕交付按所选语言先选人工字幕，再选该语言的原始自动字幕（如 `en-orig`），最后使用 YouTube 自动翻译轨道。不会用其他语言原文代替约定语言。原始自动字幕和翻译字幕仍受任务的“字幕来源”选项约束。

解析和字幕请求共享同一个内存 Cookie 会话；只有实际 URL 带跨语言 `tlang` 的 YouTube 翻译轨道才等待会话预热约 75 秒，列表显示“翻译字幕会话预热”和倒计时。会话标识轮换后重新计时。短字幕排队间隔保留已解析信息及会话，长限流冷却退回队列，已交付语言继续复用。上传的登录 Cookie 文件不会被覆写。

75 秒等待来自上游尚未合并的 [#15709 草案](https://github.com/yt-dlp/yt-dlp/pull/15709)，属于缓解策略，不能保证所有出口均成功。相关限制见 [#13831 维护者说明](https://github.com/yt-dlp/yt-dlp/issues/13831#issuecomment-3712613129)。本项目保留共享字幕串行间隔和 429 退避。

当所选客户端需要字幕专用 PO Token 时，可选择启用官方 Wiki 列出的第三方 BgUtils Provider。它会按当前视频和请求上下文生成 `subs` Token，不配置固定 Token。启用方式：

```shell
docker compose -f compose.local.yaml -f compose.subtitles.yaml up -d --build
```

远程数据库部署将第一个文件替换为 `compose.remote.yaml`。该覆盖文件通过 `WITH_SUBTITLE_POT=1` 安装锁定版本的插件，并启动同版本私有服务，不发布服务端口。自定义部署需安装 `docker/requirements-subtitles.lock.txt`，并设置 `VIDEO_SUBTITLE_POT_URL` 指向可信 Provider 服务。插件与服务版本应一致；Token 不保证解决翻译字幕会话限制，也不替代有效 Cookie。原始部署不默认启动额外服务。

## yt5s

使用服务器浏览器完成验证、解析和转换，再由现有传输模块下载。它不接收用户的 YouTube Cookie，与 yt1d、Bergung 共用浏览器并发预算。接口变化、网站验证及格式限制可能导致失败，按当前实例的渠道顺序继续尝试。


## downmp3 API

在系统设置选择实例后勾选 downmp3，调整优先级并保存下载策略。例如只勾选 downmp3、yt5s，顺序设为 downmp3 → yt5s，失败后就自动尝试 yt5s，无需 Cookie；勾选 yt-dlp 后，开始前还会检查 YouTube Cookie。下载设置默认“尽可能最高画质”（当前请求 1080p），也可指定 360p、480p、720p、1080p；转换等待上限默认 300 秒，可设为 30–1800 秒。支持视频 ID 清单和 TXT / CSV 批量导入，暂不支持播放列表。

根据 [downmp3 接入文档](https://downmp3.yt/api-documentation) 中嵌入组件的实际调用流程，后端请求 `p.savenow.to/api/v2/download` 创建转换任务，轮询 `/api/progress` 获取 MP4 链接，再使用现有传输模块保存文件、封面和元数据。转换阶段单独显示进度；下载阶段显示实际下载字节数、速度和剩余时间。所有请求使用任务当前代理节点，不向第三方发送 YouTube Cookie；不占用 yt5s 浏览器并发名额。

下载后用 ffprobe 确认文件含音视频，再登记实际字节数。下载统计按 `downmp3` 独立统计成功率、失败数、计费大小和测试大小；测试模式删除成品前保留大小记录。临时网络错误和 429 / 5xx 按队列规则退避重试，转换等待有超时上限。

该站公开文档主要描述嵌入组件，后端接口来自组件当前实现，可能发生变更、限流或要求网站验证。遇到转换或下载失败时，按页面配置继续尝试下一下载器；没有后续下载器时报告失败。停止下载、磁盘已满、权限不足及缺少运行环境不会触发切换。它没有官方批量吞吐保证，建议先验证自己的节点和清单再扩大并发。

## yt1d 网页下载

在系统设置选择实例后，勾选 `yt1d` 并保存优先级，例如 `yt1d → downmp3 → yt5s`。只影响所选实例后续领取的视频。它使用 [yt1d.lol](https://yt1d.lol/) 当前网页的正常验证、解析和转换流程，无需 YouTube Cookie。执行结果与下载大小按 `yt1d` 独立统计。

实例下载设置支持 `yt1d_quality`：`best`（默认，网站实际提供的最高档）、`360`、`480`、`720`、`1080`、`1440`、`2160`。指定档位必须由网站提供，不会把请求值当成实际成品分辨率。`yt1d_timeout` 默认 180 秒，可设 30–1800 秒，分别限制网站验证/解析和转换等待；网页导航、表单和画质查找另有短超时。保存后后续领取和重试使用新策略，在途视频保持原配置。

运行需要 Chrome/Chromium、Playwright 和 ffprobe，Linux 需要显示环境（如 Xvfb）。使用任一正式 Compose 构建即可，无需新增 Python 依赖或数据库表。yt1d 与 yt5s **共享** `yt5s_browser_count` 浏览器并发上限和磁盘预算；解析完成后由现有传输模块保存视频、封面与元数据，并用 ffprobe 检查音视频后登记交付。测试模式同样先登记实际字节再清理，不计费。

网页、验证、解析及文件传输沿用当前任务代理出口，浏览器支持无账号密码的 HTTP(S) 代理或直连。网站可能要求人工验证，可通过现有远程桌面完成；验证或转换失败会按顺序切换到下一个下载器，临时 HTTP 错误和超时使用现有退避重试。缺少浏览器、磁盘资源不足等实例环境问题保留原有等待/隔离规则。

本地验证覆盖真实 Chromium 的模拟网站表单、画质选择与转换轮询，以及实际 MP4 传输、测试清理、错误文件回退和交付去重。线上探测可打开网站，但本机无头浏览器未完成网站验证，因此尚未验证该出口上的真实 yt1d 下载成功率。

## Bergung 网页下载

在系统设置选择实例后，勾选 Bergung 并保存下载顺序。它通过 `https://bergung.hoffnungfuerdiezukunft.net/` 的正常网页流程解析单个 YouTube 视频，不使用 YouTube Cookie；画质和验证等待上限按实例配置。最高画质请求网站可用的最高档，优先 AV1，成品可能是 WebM。yt5s、yt1d 和 Bergung 共享浏览器并发名额。

网站可能要求在远程桌面手动完成 Cloudflare Turnstile 验证。超时、验证失败或网站返回不支持的选择/本地处理结果时，本次下载按已保存的顺序尝试下一下载器；不能保证无人值守成功。解析出的地址交由现有传输流程下载，成品须通过 FFprobe 音视频校验后才登记交付和计费。测试模式会先登记大小再删除文件。
