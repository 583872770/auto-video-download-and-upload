# 下载与本地处理

客户任务保留一个来源任务、同一份交付要求和交付账本。网络下载与本地处理使用不同的进程池，通过 `delivery_work` 交接，避免后处理占用账号和下载名额。

1. 下载进程获取来源资料、画面、音轨和字幕。请求并发、账号启动间隔、限流与冷却仍由同一套下载调度管理。
2. 网络结束后持久化本地处理计划和工作目录，释放账号及下载进程名额。任务显示“等待后处理”。
3. 独立处理进程取得原任务租约，接管同一个临时目录。它不登录 YouTube、不领取账号、不消耗源站传输名额；处理文件、发布产物以及 OSS 上传均在这个进程中执行。
4. 全部结果登记并提交任务状态后删除处理计划，按留样设置整理测试文件，再回收工作目录。崩溃后依据计划与交付账本续做，已经登记的产物不重复下载、计数或计费。

## 在任务中心核对结果

任务中心提供“任务列表”和“全部视频与文件”。每个任务的视频清单也能直接查看结果，执行状态和文件状态分开显示。结果详情逐项列出字幕、无声视频、纯音频、音视频成品、封面和视频信息：未选择、等待处理、上游缺失、处理失败、已校验但已清理或文件可查看。原独立素材库页面已移除。

本地和 OSS 产物可预览、下载；测试样本直接使用已经下载和验证的真实文件，同盘移动保存，不额外转码、不再次请求源站。字幕显示实际全文，视频和音频使用浏览器播放器，编码不被浏览器支持时可下载核对。播放器读取实际尺寸与时长，不额外启动 FFprobe。

“测试样本与观察”可设置快速测试或循环保留。默认每任务、每实例最多 3 份、3072 MiB、24 小时，任一限制先达到先回收；实例全部样本另有默认 3072 MiB 的共同上限和 200 份硬上限，包含在测试临时文件额度内。空间不足时可提前回收旧样本，正在下载、处理和查看的文件受保护；预览关闭后查看保护最多延续 2 分钟。

可以标记验收通过或发现问题、延长 24 小时、手动清理或重新下载并留样。验收结论与操作记录不会因删除样本丢失。“补交缺项”复用已登记的测试回执；“重新下载并留样”明确重新获取原选内容，不复用已清理的测试文件，也不重复计算已登记产物的数量和字节，且继续遵守正常账号间隔、冷却、暂停和选择规则。单独重新留样仍受数量、容量与空间保护限制。

测试观察从启用后记录，按小时展示最近 30 天的最终结果和请求异常；超过 7 天时以 6 小时汇总。403、429、登录或网页验证分别统计，支持按实例、账号和时间筛选，不直接认定账号被风控。异常明细由定期维护收敛到最近 7 天及每实例最近 2000 条，页面显示符合筛选的最近 100 条；最终成功率不把重试中的请求异常当作最终失败。当前实时下载速度单独展示，不冒充历史网络测速。

封面与 JSON 视频信息的小文件在下载阶段登记；媒体校验、媒体或字幕转换及大文件发布交给本地池。若后续字幕请求失败，已取得的媒体先进入本地队列，页面保留下载失败通知。处理完成后按下载阶段的失败策略结算：可重试且次数未用尽时，遵守原冷却截止时间重新进入下载队列，只补缺项；不可重试或次数用尽时，保留已交付产物和缺项，任务标记失败。源站与本地处理分别计算重试次数，本地重试不会重置源站次数，本地错误不会冷却 YouTube 账号。

## 什么时候使用 FFmpeg

FFprobe 检测到解析错误、文件截断或必需轨道缺失时，本地处理立即以“需要重新下载”结束，不再对同一损坏源文件重复转换，也不因此冷却账号。可在“实例设置 → 空间与日志 → 失败测试处理”重新下载缺项，或放弃并清理；其他转换和存储环境错误仍使用原有限次数重试。完整操作及统计保护规则见[磁盘管理](disk.md#在页面处理失败测试)。

以 FFprobe 的实际音轨、画面、编码、容器和有效时长判断，不能仅凭扩展名跳过校验。

- 原始无声视频或原始音频满足要求时直接交付，保持文件字节不变。
- 同一原始文件已有画面与音轨且满足成品容器要求时，也可直接作为音视频成品交付。
- 独立轨道需合并、需要从音视频中提取单轨、需要更换容器、转 MP3、将 VTT 转为 SRT 时才启动 FFmpeg。兼容的编码使用流复制；确需转码时限制为一个编码线程。
- 同一来源文件的探测结果在本次处理中复用。转换生成的新文件单独验证，发布时复用该验证结果。

先处理共享轨道的消费者，再移动仍被引用的源文件。例如独立画面和音轨先合成成品，再分别移动为无声视频、纯音频；包含画面和音轨的单个来源文件则先提取单轨，再移动为成品。

## 发布与容量

同一文件系统使用重命名移动。跨文件系统才复制：先写隐藏临时文件，完成同步后原子改名，最后删除源文件；失败时不暴露半成品。计划先保存目标路径，进程在移动后、登记前中断，也能从目标位置继续登记。

等待处理的文件继续计算实际占用，交接时释放尚未写入的下载预留。转换前申请新增输出所需空间；磁盘压力下允许直接移动已有文件。本地队列仍受临时文件预算限制，不会无限堆积源文件。正常清理保留待处理、失败待重试的工作目录；移除来源、清空素材会取消对应处理计划。

本地处理并发使用实例设置“本地后处理并发”（`postprocess_limit`，默认 2），同时计入数据库连接预算。下载容量和账号运行状态不再计入本地任务；下载工作台分别显示本地运行数、排队数和并发上限。调整连接预算时需给主服务、辅助进程、本地处理池和下载池都留出连接。

本地处理进程完成任务后继续接手下一项工作，短暂空闲时最多保留 60 秒，减少反复启动 Python、导入模块和初始化数据库的 CPU 开销。空闲期间显示为空闲，不代表仍有任务在执行，也不占用账号、任务租约或下载空间预留；数据库事务在等待前已结束。新处理计划提交通知唤醒进程，漏掉通知或任务延迟重试时最多每 2 秒重新检查队列。连续空闲 60 秒后退出，之后有任务再按需启动。

暂停、停止或实例被新进程接管后，空闲进程在下一次控制检查时退出（正常情况下不超过 2 秒）；缩小本地后处理并发时，多出的进程完成当前任务后退出。任务执行中仍遵守原有暂停、停止和租约规则，异常退出后由监督进程按原退避规则恢复。

验证涵盖本地 HTTP 下载与真实 FFmpeg、直接交付零复制、组合交付、跨文件系统复制失败、交接后崩溃恢复、处理中断与重试、跨实例隔离、容量限制、测试模式清理及独立处理子进程。达到服务器 1 Gbps 的实际吞吐仍需部署后用宿主机公网网卡采样验证。
