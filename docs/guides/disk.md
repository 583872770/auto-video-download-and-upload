# 长期运行的磁盘容量管理

## 页面空间告警

顶部状态栏显示当前实例的磁盘使用率，点击进入“实例设置 → 空间与日志”。全局通知条在任意菜单保留空间问题；通知中心展示具体实例、受影响任务、实际剩余空间、未写入预留、占用来源及恢复情况。下载工作台的账号任务列表保留退回队列的磁盘等待任务，显示预算或空间等待、最近一次申请量与当时可分配量，以及重新检查倒计时。等待列表每次最多读取 100 条已记录的磁盘事件，不扫描历史任务。

实际使用率连续两次达到 80% 提醒、90% 严重提醒，采样至少间隔 30 秒，恢复有 5 个百分点的回差；使用率提醒本身不改变任务准入。实际空间水位、总预算和单次分类预算不足立即记录资源受阻。预算不足与物理磁盘不足分别解释，未写入的预留不会重复计入实际磁盘使用率。资源满足条件后恢复通知会区分“等待调度继续”和“仍需手动启动”，不会解除人工暂停。

测试任务结束超过 10 分钟仍有受管文件，或最近自动清理失败，也产生检查提醒；运行中及待核对任务单列展示。测试目录中超过 1 MiB 的未登记文件持续 10 分钟会提示核对，保留文件；清理失败显示最近原因及连续失败轮数。通知与顶部使用后台缓存，实例空间采样超过 90 秒不再作为当前状态；主机分类超过 15 分钟显示待更新。分类数据采样时间不同，不应当作同一时刻的精确账目。

## 主机占用采集

应用容器内无法直接获知宿主机 binlog、历史部署和 Docker 镜像占用。宿主机运行只读采集脚本，结果原子写入应用状态卷中的 `host-disk-usage.json`。Web 只读分类汇总，不挂载 Docker socket、不执行主机命令。未知项目显示“待检测”；其他文件系统的分类标注“其他磁盘”，不混入当前磁盘合计。数据库容器必须与应用配置的 `MYSQL_HOST` 对应，远程数据库不归因到本机磁盘。

在 Linux Docker 宿主机、当前发布目录中安装（容器名或部署目录变化时调整 service 参数）：

```sh
sudo install -d -m 0755 /opt/frameflow
sudo install -m 0755 docker/collect_disk_usage.py /opt/frameflow/collect_disk_usage.py
sudo install -m 0644 docker/frameflow-disk-usage.service /etc/systemd/system/
sudo install -m 0644 docker/frameflow-disk-usage.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now frameflow-disk-usage.timer
sudo systemctl start frameflow-disk-usage.service
sudo systemctl status frameflow-disk-usage.service frameflow-disk-usage.timer
```

后台每 5 分钟采集数据库已分配文件大小、binlog 保留天数、部署目录和 Docker 共享层去重用量。Docker 可回收量为未使用镜像独占层的估算，不包含构建缓存等所有可回收项。网页现有“清理可回收文件”仍只清理已核实可回收的应用临时文件和日志，不直接删除 binlog、部署或镜像。MySQL 的 binlog 在 Compose 中保持开启，默认保留 3 天；已有数据库需由运维设置持久化保留策略，修改配置不会直接删除正在使用的日志。

升级后重启服务，在工作台“实例与环境”的“磁盘容量管理”中设置并保存。多实例部署先选择实例；每台下载机器分别管理自己的磁盘，不共享本机配额。配置修改可用于后续准入和运行中的容量检查，不会修改客户任务的下载策略。

## 默认预算

| 内容 | 默认上限 |
|---|---:|
| 可丢弃运行文件合计 | 20 GiB |
| 测试视频、分片及合并输出 | 16 GiB |
| 下载浏览器配置和缓存 | 1024 MiB |
| 所有任务与实例技术日志 | 新配置默认 64 MiB |
| 导入原文件及上传临时文件 | 1024 MiB |
| 诊断及其他运行缓存 | 256 MiB |
| 单条技术日志 | 新配置默认 2 MiB |
| 单次清单上传 | 256 MiB |

成功任务日志默认保留 24 小时，其他结束任务日志默认保留 7 天；总量预算可提前淘汰旧日志。已有配置中的单条日志上限继续生效，可在原日志设置中修改。运行日志在写入时保留末尾内容，读取接口会说明早期内容已清理。

空间有限时，可把“全部日志预算”设为 16～64 MiB；升级保留已明确保存的预算，不会擅自覆盖。任务日志在写入时按单条上限与总预算的 1/64 中较小值轮转；最多保留 1024 份，容量清理预留一半预算供并发写入、实例日志和文件元数据使用。每 30 秒自动检查，下载暂停时照常清理；数据库不可用时仍会按本地日志年龄和容量清理。低于磁盘暂停水位时，提前清理已结束任务日志。

`logs/instance/` 使用固定数量的进程日志，每份不超过 256 KiB（小预算时进一步缩小），闲置日志最长保留 7 天。每次任务尝试记录执行编号、实例、尝试次数、实际生效的配置、节点、下载器切换、耗时、错误类型和重试决定；这些记录与任务日志一起轮转和到期删除，不新增无限增长的数据库明细表。完整日志在任务详情查看；实例日志记录进程启动、退出和任务开始前的错误。

磁盘容量管理中的“查看实例运行日志”可读取当前所选实例的近期日志。downmp3 沿用已有 FFprobe 校验并记录实测分辨率、编码与时长，避免把接口请求的画质当作实测画质；其他下载器记录所选格式及来源报告的分辨率，不额外启动探测进程。

日志输出统一清理凭据及 URL 查询参数；浏览器错误只保留内存中的 8 KiB 输出尾部，失败时写入受限日志，不保存页面、响应正文或截图。yt5s 每个进程的 `last-failure.json` 仍只保留最近一次，历史原因以受限日志为准。日志写入失败会尝试更新一份固定大小状态，在磁盘页面显示近期告警；磁盘完全写满时连状态文件也可能无法写入。

文件系统剩余空间低于 **10 GiB** 时停止新增下载，清理后恢复到 **15 GiB** 才解除这一等待。素材目录在其他磁盘时，也会检查其剩余空间。页面用量展示的是状态目录所在文件系统及受控文件；正式素材所在其他磁盘需另行监测。

以上数值是初始配置，按机器实际容量调整。总预算和分类预算同时生效；配置 10 并发表示最多 10 个，空间不足时实际并发会下降。未知大小的测试执行先预留 1 GiB，随后按大小扩展；yt-dlp 还会为合并预留空间。

## 自动清理什么

- 测试成品：完整下载并登记实际大小后立即删除。分片、中间文件和同次执行的工作文件一并回收。
- 异常退出残留：默认经过 5 分钟宽限，核对进程身份、子进程、目录锁及任务状态后回收。服务重启和下载暂停时仍会检查。
- 浏览器：新建的下载浏览器配置位于受控目录，退出后清理；缓存参数同时限制浏览器自身缓存增长。
- 日志：按单条大小、保留时间、全部日志预算轮转和淘汰。
- 导入：原 TXT/CSV 在视频 ID、检查点及导入计数提交后删除；取消导入的源文件在确认不再使用后清理。仍需恢复的导入源文件保留。
- 诊断和缓存：只清理受控目录中确认不再使用的工作文件。Cookie 原件、登录资料、部署配置及密钥不属于清理对象。

清单导入后，视频 ID 可继续从数据库导出；原 CSV 中未入库的额外列不再保留，请自行备份源文件。历史版本在系统临时目录产生、无法确认归属的浏览器目录不会被盲目删除。

“清理可丢弃文件”按钮执行相同的安全清理规则；它不会为了腾空间删除正在使用的文件，也不会提前删除仍需保留的导入源或待核对成品。

## 统计和任务如何处理

完整测试文件先登记实际字节，再删除；不使用进度估计值充当成功大小。累计统计、成功率依据、任务清单、交付账本、预计费用和去重记录保留在数据库。删除技术日志只减少可展开的排障文本，简短错误原因继续保留。

磁盘不足进入“磁盘等待”，不会记作下载器失败，不消耗普通下载重试次数，也不会改变任务的运行意愿。扩展空间失败时退出当前执行，停止子进程后清理未完成文件并稍后重排；其他能容纳的执行可继续。系统记住大视频已知需求，避免每次都用很小的预留重新下载。调度前读取本机容量快照，已知需求仍无法满足的任务不再反复领取、退出；预算或空间释放后自动重新参与调度。中断次数只用于诊断，不再额外要求实际磁盘空闲量增长 1 GiB。快照过期时由执行入口重新核对并原子申请，容量保护始终生效。

本机容量协调锁短暂繁忙时，SQLite 在单次操作内最多等待约 5 秒；仍无法完成检查则进入资源等待，下载任务约 60 秒后重新评估，不计下载失败。正常的已有预留检查和页面查询使用只读事务；水位、预留或子进程列表未改变时不重复写入。目录扫描在数据库事务外完成，由独立扫描锁避免多进程重复扫描，新增和扩大的空间预留仍在短写事务内原子检查并登记。

监控异常会通知执行停止并记录原因。退场清理遇到协调锁繁忙时保留容量登记，不覆盖已完成结果或原始错误；若暂时无法移交登记，维护流程在确认原进程退出后再核对回收。

空间恢复不会解除人工暂停。待统计确认的完整测试文件保留并显示待核对数量；新执行取得任务所有权后会先尝试恢复单视频完整结果，避免直接重下。无法确认或与账本不一致的结果保留，需要核对，不会当垃圾删除。文件删除失败也会保留已提交统计，并在后续清理中重试。

多类型测试下载按每种内容独立确认。已校验并登记的字幕、音视频、封面和视频信息在重试时复用完成记录，只补做缺失内容；测试文件删除不使这些记录失效，正式交付仍核对真实文件。已登记的部分测试产物及其旧工作目录可清理，不必等待整个任务完成。重复执行导致元数据或媒体大小变化时，旧目录按任务、视频、类型、语言和交付参数对应的产物身份核对，以首次成功登记的统计为准，既不重复计数，也不把旧文件重新覆盖到新记录。尚未登记的崩溃产物仍先恢复、确认后再删除。

保留结果文件不等于保留执行预留。确认执行监控与子进程均已停止后，立即释放尚未写入的空间预留，只继续计算保留文件的实际占用；异常退出的执行由维护清理和重试恢复入口执行相同核对。子进程仍在运行或无法确认是否停止时继续保留预留，避免超额启动。保留文件不再计为活动执行，也不会遮住同一任务的磁盘等待提示。

## 容量边界与部署

这是**软件容量控制**：空间预留在多个下载进程间原子协调，正常扫描约每 5 秒、运行监控约每秒、后台清理约每 30 秒。浏览器、FFmpeg 等突发写入可能短暂超出预算；严格的字节上限需要宿主机文件系统配额或独立容量卷。

需要硬限制时，可将状态目录下的 `test-downloads`、`runtime`、`logs`、`imports` 放入同一有配额的文件系统，并保持应用可写；配置和数据库留在保护范围外。先停机备份和验证挂载，避免覆盖已有文件。Docker 普通命名卷没有通用的容量参数，必须在宿主机配置配额。本次没有修改现有挂载或机器配额。

本机 `disk-budget.sqlite3` 仅保存容量协调元数据，设有约 128 MiB 的页数上限，等待需求最多 10000 条；它不属于业务数据库，也不计入上表可丢弃文件预算。配套配置和锁文件只占少量空间。

**正式视频、业务 MySQL、Docker 镜像和构建缓存、依赖工具及其他程序的数据不包含在 20 GiB 中。** 应用不会自动删除业务数据库。长期保留全部历史明细时，数据库仍会增长，需单独规划容量、备份和 binlog 保留；远程 MySQL 使用的是远端磁盘。

已有独立命令行下载、登录浏览器及人工调试文件不等同于 Web 实例下载工作进程，本次预算针对 Web 实例运行目录。Docker 桌面辅助服务日志另按每份 2 MiB 截断，容器标准输出沿用 Compose 的日志轮转配置。

## 验证范围

自动化测试覆盖跨进程空间争用、剩余空间预留、异常目录清理、统计保留、结果恢复、资源等待、上传和日志限额。新增 16 个独立进程同时执行 128 次申请、写入、扩容和释放，并交错运行 20 次强制用量核对；另覆盖慢扫描期间新增预留、扫描中目录变化、无变化时零行更新、真实锁冲突不污染失败统计，以及监控和退场异常。`scripts/verify_disk_budget.py` 使用临时实例验证设置保存、清理、桌面及手机页面，以及真实 Chromium 配置目录创建和回收。

本地验证未做长时间第三方真实下载压力测试、真实 MySQL 集成或宿主机硬配额测试；部署严格容量限制时需在目标文件系统单独验证。
