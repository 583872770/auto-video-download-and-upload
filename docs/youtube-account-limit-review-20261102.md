## 建议

- 先以单会话单任务、单路解析、单分片、每 60–120 秒启动一个视频作为保守观察起点，保持 yt-dlp sleep 预设。当前设置校验最多允许 60 秒，若支持 120 秒需同步调整设置校验、页面及调度等待逻辑。
- 显式约束传输和连接预算，先使用手动上限，避免机器资源充足时自动放大请求压力。限流恢复后不因少量成功立即加速。
- 为所有执行模式统一维护按核心会话的节奏、滚动小时及日总量预算、冷却和恢复状态；切换单 Cookie / Cookie 池或重启不应丢失保护。阈值需根据长期观察调整，不标注为平台官方安全额度。
- 保留明确账号限流即熔断、停止新领取、遵守冷却和人工复查的行为。反复限流应延长退避；登录有效不等于视频访问已恢复。
- 连续观察至少 24 小时的首次限流时间、视频启动数、失败数和实际完成吞吐，先求稳定再决定是否提速。其他程序共用同一账号时，应合并考虑其请求压力。

暂不建议为此次账号限流增加 IP 或 Cookie。相同账号重复导出的 Cookie 不增加额度，不同会话也不能证明独立账号或独立配额；更多同网段 IPv6 不能保证增加源站容量。更换 IP 或 Cookie 继续重试不能替代冷却和节流。任何建议配置都不能保证永不触发限制。
