# 多实例 Cookie 归属与实例页调整

## 行为

- Cookie 配置库仍按实例 ID 隔离；共享数据库新增 `youtube_cookie_bindings`，登录凭据摘要为主键、实例 ID 为唯一归属。上传和绑定在同一事务内完成，并发导入只允许一方成功。
- 校验 SID、1PSID、3PSID、SAPISID 等核心凭据的重合；改文件名、行序、注释或辅助 Cookie 无法创建另一实例的归属。相同实例的重复导出继续兼容原有会话合并。
- 新增、传统上传、浏览器登录、选用、自定义路径、保存账号池和执行前恢复均检查归属。冲突不会发起登录检测或下载请求，提示绑定实例，不显示凭据。
- 绑定不会因删除 Cookie、实例离线或重启而解除，避免旧任务持有凭据快照时被另一实例重新使用。本次未增加跨实例迁移/解绑入口。
- 历史配置按保存时间、实例 ID、配置 ID 排序建立归属；重复项保留，允许查看、导出、删除，非归属实例无法继续执行。迁移可重复运行且不改写任务表。
- 只保存摘要作为绑定索引；正常运行读取已存在的绑定，不重复写入绑定记录。Cookie 内容仍保存于原有配置库。

归属协调要求实例连接同一个数据库，并全部运行支持该规则的版本。独立数据库、旧版程序无法参与统一限制。不同登录会话是否属于同一 Google 账号，无法仅凭 Cookie 文件可靠证明；本规则限制相同核心登录凭据跨实例使用。

## 实例页

默认卡片保留名称、在线/运行状态、所选任务、处理数、传输数、速度、Cookie 模式及启动/停止操作。离线指标显示未知。视频明细、Cookie 格子、历史统计、完整诊断留在对应工作台，实例 ID 和素材目录移入折叠配置。

配置随模式切换：

| 模式 | 并发配置 |
| --- | --- |
| Cookie 池 | yt-dlp 传输上限、每核心会话并发上限、共用启动间隔 |
| 手动 | 视频处理并发上限 |
| 自动 | 自动调度传输上限 |

名称和磁盘预留均保留；只有实际使用浏览器下载器时才显示浏览器并发。编辑中的草稿不会被轮询覆盖，实时状态和控制按钮仍持续更新。

池参数沿用已有字段 `builtin_transfer_limit`、`youtube_cookie_session_limit`、`youtube_cookie_pool_start_interval`；实例页写入该实例资源覆盖值，完整设置、调度和重启读取同一覆盖值。通过完整设置再次保存这些字段时同步覆盖值，避免两个页面互相覆盖回旧值。降低上限不强制中断已开始的任务。

## 多实例建议

1. 每个实例使用独立实例 ID、状态目录、浏览器资料目录和 Cookie 集合；下载临时目录也独立，成品统一归档。
2. Cookie 尽量绑定稳定的实例出口。多个实例共用同一出口时，增加实例数并不会增加源站额度，应限制总请求速率。
3. 共享 MySQL 管理任务和绑定，沿用任务租约与原子领取；不要让多个实例同时挂载同一个 MySQL 数据卷启动不同数据库容器。
4. 全局视频处理上限控制服务器总负载，各实例传输上限控制局部资源；会话预热、启动间隔和冷却仍独立生效，上限不代表始终跑满。
5. 扩容先观察带宽、CPU、内存、磁盘余量、账号冷却和排队原因，再逐步增加容量；保留现有轮询节流、读缓存和隐藏页面停止刷新。

## 验证

新增跨实例并发导入、重新导出、部分凭据重合、传统 Cookie、自定义路径、删除后保留绑定、历史重复迁移、错误实例池 ID，以及设置与调度一致性测试。部署前在服务器隔离容器中通过 247 项 Linux 回归测试，另在随机独立测试数据库中通过 9 项真实 MySQL 合约测试，包含并发归属争用；未改动生产业务表。

浏览器脚本 `scripts/verify_instance_cards_ui.py` 验证三种调度模式、池参数保存、实例隔离、草稿保护、离线状态、桌面及手机无横向溢出。原有实例执行和 19 个 Cookie 工作台浏览器验证也通过。

回归中发现原有 `test_remote_strategy_persists_in_file_registry_and_after_restart` 将渠道自动选择误认为自动并发；在未修改的 HEAD 副本也复现。修正该断言，保留两种设置独立的现行行为。
