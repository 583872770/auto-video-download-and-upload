# Cookie 连续异常保护与领取前等待（2026-11-06）

本次仅处理 `workbench-smoothness-observation-20261106.md` 中的两项：异常 Cookie 持续接任务，以及大量领取后因 Cookie 间隔未到又放回。没有提高并发、连接预算，也没有缩短源站请求间隔、登录保护或冷却。

## 单会话保护

- 仅统计 YouTube 媒体传输阶段、分类为 access_denied 的真实 HTTP 403。OSS、内容权限/DRM、解析阶段失败不纳入这项计数。
- 同一会话 15 分钟内 3 个不同任务发生上述失败，暂停该会话新请求 15 分钟。同一任务的重复包装或重复报告不累计。
- 停止范围仅为该会话及共享同一凭据/账号组的 Cookie 文件；正常会话继续调度。不会因此设置整个池的 halt，也不会将 403 失败视频自动交给其他账号重试。
- 该会话在冷却后以单并发、至少 180 秒间隔恢复观察；恢复中再次出现同类失败，冷却依次延长为 30、60 分钟，最高 60 分钟；尊重更长的 Retry-After。
- 恢复成功 3 次且满 10 分钟后可降至 120 秒间隔，5 次且满 30 分钟后恢复配置并发，间隔仍至少 120 秒。稳定恢复后清除本轮递增冷却次数。
- 正常成功只有在任务准入时间不早于最近异常时才清除累计 403；较早已在执行的任务结果不能清除或再次延长较新的保护。
- 状态、计数与恢复进度使用已有的持久化会话资源记录，重启、换 worker 或选择同凭据的另一个文件不会重置保护。无需迁移数据库。
- 实际证据分类仍为 access_denied/HTTP 403；本地措施标为 repeated_http_403，不伪造明确限流或验证码证据。

页面沿用 Cookie 会话状态展示，在工作台并发面板和 Cookie 管理处显示保护性冷却、原因、截止/剩余时间、最近异常和可用会话数量。冷却结束显示低频恢复。登录检测继续遵守已有冷却检查。

## 领取前等待

新增实例本地 `DownloadStartGate`，读取已有 5 秒容量快照，在 Cookie 启动窗口未到时让空闲进程等待。等待不持有任务租约、数据库事务或下载临时工作区。

接近启动窗口时，仅一个本地进程通过文件锁取得一个有所有者标识、最长 60 秒有效的领取提示，随后执行原来的数据库 claim。Cookie 原子准入成功后立即发布下一启动间隔，释放本地提示，再开始实际下载；若准入遇到背压，则将实际等待时间通知其他进程。

本地提示只减少无效领取，不能授权下载。最终 Cookie 并发、间隔、冷却、任务所有权和跨实例竞争继续由原数据库事务校验。进程退出后可识别失效所有者，过期提示可回收；旧 token 无法覆盖新 token。缺失/过期的容量快照回退原数据库准入路径。配置策略变化会重新计算本地提示。

导入和字幕专用通道不经过该等待；regular 通道等待下载窗口时仍能领取检查任务。任务领取失败或无任务时会释放提示。

## 验证

- 本地 Cookie、领取等待、登录和风险诊断相关 55 项测试通过；随后补充更长 Retry-After 响应头测试，并连同局部冷却、递增冷却两项再次验证通过。
- 其他相关套件运行 82 项：80 通过、1 跳过、1 个既有失败。失败为 `SQLiteConnectionTests.test_worker_and_resume_preflight_receive_effective_connection` 中 resume 预检 mock 未被调用；单独加载修改前的 HEAD worker 后同样复现，未更改该独立预检行为。
- 隔离 MySQL 8.4 容器运行 Cookie 保护与渠道准入合同，共 38 项通过。测试创建/删除随机测试数据库，没有在生产库运行测试套件。
- 复核中补齐普通 403 响应头包含更长 Retry-After 时的等待：7200 秒头部必须优先于本地 900 秒默认值。该项在 SQLite 和隔离 MySQL 均通过。最终 r2 版本包含此补充。
- 单元测试模拟 24 个并发领取者，只有 1 个成功领取，其余 23 个任务保持 queued、attempts=0；等待期间不调用数据库 claim。
- Linux 候选镜像实际启动 24 个独立进程争用本地提示：1 个取得、23 个等待。
- 验证冷却跨实例对象重建、重复任务去重、15 分钟窗口、旧成功/失败结果、局部恢复、冷却递增、其他会话不受影响，以及领取提示不替代最终数据库保护。
- 三个 JavaScript 文件语法检查通过；运行实际提示生成函数，验证保护原因、倒计时、最近异常、局部暂停提示及 Cookie 名称 HTML 转义。
