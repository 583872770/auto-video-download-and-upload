# 下载进程自动缩容开关发布

## 功能

“实例设置 → 并发与资源”增加“自动降低下载进程上限”（`download_auto_reduce`），默认开启，只作用于所选实例。保存后在下一次资源采样生效，通常不超过 5 秒，无需重启应用。

关闭后，不再因 CPU、可用内存或 I/O 压力降低动态下载进程上限；已经缩容时恢复到常规上限，不等待逐步扩容。账号容量、配置上限、静态内存容量预估、数据库连接容量、磁盘空间保护和账号冷却/启动许可继续生效。关闭不代表所有名额立即实际下载。

策略摘要使用配置的有效默认值：省略 `download_auto_reduce` 与显式 `true` 表示同一策略，避免实例完整配置与页面读取的配置在默认值上不一致，导致新鲜运行状态被隐藏。

重新开启后按最新采样继续保护。工作台显示开关状态；关闭时清除旧的缩容记录与恢复预测，资源指标继续采集。配置按严格布尔值校验，并纳入实例配置、运行时配置与吞吐策略摘要，使切换不复用旧额度快照。接口和页面的保存回执提示下次资源采样生效。

## 验证

本地 43 项后端测试、4 项前端设置测试、前端类型检查与生产构建通过；后续新增的数据库容量断言也单独通过。浏览器使用隔离 SQLite 验证默认开启、布尔提交、保存读回、刷新保留、键盘切换、1440/390 像素布局和工作台关闭提示，浏览器错误为 0。

候选镜像基于线上 r64 的不可变镜像构建，仅覆盖五个后端文件及构建后的前端资源，保留其余运行代码和依赖。上传内容按 SHA256 清单验证；线上五个基线文件与 Git 内容一致，CRLF/LF 差异按实际线上摘要核对，不将换行差异当作代码变化。

Linux 隔离容器不挂载业务卷、不连接业务网络，限制为 0.75 核、1 GiB。首版 49 项控制器、配置契约、设置保存、多实例隔离和数据库连接预算测试全部通过；后续针对线上验证发现的默认值策略摘要问题补充回归，最终 50 项全部通过，耗时约 73.1 秒。本地相应 31 项控制器、吞吐、配置与数据库预算检查也重新通过。

首轮 Linux 检查发现旧数据库预算测试将控制器资源模拟为 16 GiB，但 `runtime_limits` 二次容量核对读取了实际 1 GiB cgroup，导致预期 31 与实际 2 不一致。已修正该测试为两次计算使用同一模拟资源；没有放宽生产容量限制。配置契约 fixture 同步补入新开关及之前遗漏的已有留样额度字段。
