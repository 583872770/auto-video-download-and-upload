# 下载进度、留样查询与性能验证

本次发布仅针对洛杉矶实例 `216.227.169.90`。发布名 `download-efficiency-20261123-r62`，基于已运行的 r61 不可变镜像；不调整下载并发、分片并发、账号节奏或本地处理并发。服务器证据保存在 `/opt/frameflow/releases/download-efficiency-20261123-r62/`，本地私有证据位于同名 `.runtime/deploy/` 目录。

## 改动

- 下载参数统一设置 `progress_delta=1` 和 `noprogress=True`。限频针对终端进度格式化，原生结构化回调继续提供下载字节、速度、剩余时间和完成事件。
- 增加 `ix_delivery_artifacts_task (task_id)`，留样仍核对客户任务、测试标记和文件所属实例。已有就绪留样直接返回；关闭留样的快速测试不再读取文件回执；中断续做复用已保存清单。
- 页面使用同一事件的数值字节计数计算当前文件百分比，优先采用回调的速度与 ETA；估计总大小标“约”，未知大小不编造百分比，不使用可能因终端限频而滞后的格式化文字字段。
- 工作台、任务概览、执行日志展示当前文件大小、速度和剩余时间。多文件切换时分别展示各文件进度；原有累计下载字节、空间预留估计、任务完成率、交付大小和计费口径保留。
- 进度持久化间隔仍为 2.5 秒或阶段边界，缓存与前端轮询节奏沿用原设置。`progress_delta=1` 不表示网页每秒必刷新一次。

## 验证

前端 18 个测试文件、67 项测试通过，TypeScript 检查与生产构建通过。

Windows 运行 121 项回归，唯一错误为本机缺少 `oss2`，另有 11 项 FFmpeg 媒体测试因缺少工具跳过；未把该轮描述为全部通过。Linux 候选首轮实际加载镜像内的 118 项旧测试，117 项通过，1 项因旧的多轨平均百分比期望失败。修正挂载为当前测试文件后，30 项专项全部通过，覆盖当前文件进度、字节累计、无效数值、0 速度和 ETA、字幕、留样查询跳过、真实 HLS 下载及最终文件内容。原有 HTTP Range、取消、重试、403/429、媒体校验、交付和 OSS 重试案例已在首轮 Linux 验证通过。

另外 7 项隔离 MySQL 集成测试通过：新建当前结构、已有结构核验、错误结构拒绝，以及 12,000 条同客户任务回执中按单个任务取 4 条记录并命中任务索引。各案例使用随机临时数据库，运行结束自动删除。

## 测量方法

优化前后各采集 600 秒，每 5 秒记录宿主机、应用和 MySQL 的 CPU 计数及媒体接收速率。CPU 百分比均以整机四核总容量为分母；MySQL 为共享容器整体占用。任务、文件和交付字节使用洛杉矶实例小时累计表的窗口增量；完成产物大小包含交付输出，不能直接当作网络流量。

基线采集结束后才执行构建、测试、备份和索引 DDL；发布后的业务与浏览器验证完成，至少热身 3 分钟，再采集后测窗口。两个测量窗口内均不运行测试、备份或构建。业务队列顺序推进，视频、账号冷却和资源保护可能变化，属于连续时段观察，不能把全部差异都归因于补丁。

整机平均 CPU 降低 16.40 个百分点，MySQL 降低 11.87 个百分点；平均媒体接收速度提高约 14.7%，网卡接收速度提高约 6.9%。同样窗口内交付体积增加约 9.1%，每 GiB 产物的应用 CPU 时间降低约 16.9%。留样查询计划的改善已直接验证，CPU 与速度的业务观测均有收益。

后测视频的平均产物体积大约增加 16.2%，成功任务数量实际减少约 6.1%；原有资源保护将进程上限从基线平均 18.28 恢复至后测 20，账号可用容量也有变化。因此不能宣称单个视频或全天吞吐必然提高 14.7%，也不能把全部收益都单独归于 `progress_delta`。应用 P95 未下降、整机仍有接近 100% 的短时样本；解析和媒体处理的 CPU 压力仍存在。

后测请求异常记录为 3 次仅 DRM 内容限制、1 次上游 HTTP 403；终态失败总量仍为 4。未发现本次补丁引入的本地处理异常，遗留音轨校验失败的处理计划早于此次发布。最终实例保持运行，配置、账号与凭据核对一致，自动重启和 OOM 均为 0。原始窗口、查询计划、测试日志、发布核对与异常分类已取回到本地私有 `results/` 目录。
