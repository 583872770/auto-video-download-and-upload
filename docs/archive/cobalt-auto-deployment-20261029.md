# Cobalt 多入口自动调度：验证与发布记录

## 本次实现

新增 `scheduler_mode=auto`，将所有已启用下载方式视为候选，不使用下载器优先级。按统一参考文件的预计处理时间、成功率 EWMA、入口负载及上游组负载择优；未知入口每实例同时只允许一个解析试探。解析就绪后释放试探名额，原任务和后台名额保留到文件结束。每入口默认 4 个在途任务，每视频每轮最多 3 个入口。

下载任务、解析、媒体连接、本机资源和共享后台许可分别约束；相同 API 强制共享后台额度，未确认独立的媒体后台继续共用 `unverified-media`。只有运行观测证明增益且资源允许时才逐步增加传输额度；增加并发未带来收益就回退。自动配置不是域名数与并发数的乘法。

支持 Cobalt 的 `redirect`、`tunnel`、YouTube 双流 `local-processing + merge`。双流来自同次解析，由 yt-dlp 下载、FFmpeg 合并，再验证音视频轨。没有启用跨渠道拼接、未验证的 Range 并行或跨编码追加续传。媒体 HTTP 会话没有新增跨任务复用承诺，复用的是受本机额度约束的解析浏览器。

浏览器支持自动验证流程；视频本身不可用、本机磁盘、租约、环境及数据库错误不会直接熔断媒体上游。入口临时错误指数退避；429/Retry-After 按发生阶段传播至相应共享作用域。不同 Cobalt API 的代理健康分别计算。

## 验证

Windows 完整回归为 531 项，502 项通过、29 项因独立 MySQL 测试环境等条件不足跳过。三处旧夹具直接执行未领取任务，已调整为具有合法 owner 和有效租约的执行状态；没有降低生产租约校验。

真实浏览器的自动策略设置、候选目录去重、配置往返、局部保存、多实例界面及任务中心状态回归全部通过。JS 语法、Git 空白检查通过。

Linux/Python 3.13 隔离完整回归覆盖 531 项，初次有 10 个错误报告、19 项跳过。错误来自未使用生产容器的浏览器环境，以及两处已有测试夹具的跨平台行为：POSIX 共享计数器在子进程恢复前被释放；全局修改 `sys.platform` 让 Linux 的 `shutil.which` 调用 Windows 私有接口。修正夹具并使用 Xvfb 和容器浏览器参数后，覆盖所有失败用例的 10 项复测全部通过；相同两处夹具在 Windows 的 10 项专项复测也通过。完整日志与逐项复测对应记录均保留，没有把初次 Linux 全量结果写成一次性全绿。

发布镜像为 `youtube-downloader-app:cobalt-20261029-r1`，发布目录为 `/opt/youtube-downloader/releases/cobalt-20261029-r1`。最终镜像内 168 个代码、资源与测试文件已按 SHA-256 清单校验。隔离 Linux 测试不挂载生产卷、不连接生产数据库。独立 MySQL 合约环境未配置，未用生产库写入测试任务。

## 发布范围和资源配置

只暂停当前主实例的新领取，等在途任务完成后停止旧容器、更新配置及 heartbeat，再创建新容器。新版本健康和只读状态验证通过后恢复原运行意愿。保留其他两个实例的暂停、停止意愿，保留主实例原任务、代理、画质与测试存储模式。私密目录保留旧镜像、Compose、完整配置与意愿备份，启动或校验失败时恢复旧镜像和旧配置。

主实例采用自动调度、自动吞吐，传输上限 16、浏览器上限 3、媒体连接预算 32、每轮最多 3 个入口。这些是上限，控制器按 CPU、内存、I/O 压力及实测增益决定实际额度。公网套餐速率尚未核实，带宽目标保留 0（探索）。数据库池按进程预算，沿用主服务 5+2、工作进程 2+0 及工作进程总连接预算 48。

## 上线后稳定观察

第一段 17:18:49～17:24:49（北京时间）连续 6 分钟包含启动后准备阶段：网卡接收平均 `35.75 Mbps`，5 秒峰值 `76.68 Mbps`，成品字节折算吞吐 `4.95 Mbps`，完成 4 个任务，最终失败 `0`。CPU 平均 `70.7%`，内存峰值 `2423.4 MiB`，没有 OOM，数据库未新增连接失败。

第二段 2026-10-29 17:26:43～17:30:43（北京时间）连续 240 秒观察结果：网卡接收平均 `81.74 Mbps`，5 秒峰值 `127.40 Mbps`；5 个任务完成并校验，成品字节折算吞吐 `41.46 Mbps`，最终失败 `0`。CPU 平均 `76.7%`，内存峰值 `3326.5 MiB`，磁盘剩余最低 `30.43 GiB`，I/O 压力平均/峰值 `8.07/15.4`；没有 OOM，MySQL `Threads_connected` 首尾采样为 `20/21`，`Aborted_connects` 未增加。成功任务来自 Cobalt girlskissing 2 个、yt1d 1 个、Bergung 1 个和 yt5s 1 个；窗口内另记录到 Bergung 和 girlskissing 各 1 次入口尝试失败，最终失败为零不代表没有重试。观测结束时控制器因 CPU 压力收敛到 3 个传输、6 个工作进程和 2 个浏览器，媒体接收窗口约 `73.05 Mbps`。

这组数字说明自动调度和入口回退已经工作，但不能宣称持续吃满公网带宽：接收流量包含解析、代理和重试，成品吞吐只在任务完成时计入，且公网套餐上限未核实。当前限制仍可能来自上游准备/验证供给、源站带宽、CPU 与媒体处理；继续加域名或并发数不保证增益。
