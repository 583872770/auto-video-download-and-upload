# 字幕失败后的部分产物交付修复

## 修复结果

下载进程取得画面、音轨后，字幕失败会留下本地处理计划。原先失败结算直接将父任务标为失败，本地处理池只领取排队任务，导致这些文件无法交付。

现在失败结算先持久化下载失败原因、重试决定、冷却截止时间和下载尝试次数，再将父任务交给本地处理池。处理完成后恢复原下载失败的结算：允许重试时只补缺项；不可重试或次数用尽时保留已经交付的内容，并显示失败和缺项通知。本地重试不会增加或重置下载尝试次数。

保留真实出错阶段和账号信息，直到完成失败归类。后处理不占用源站账号。手动补交会清除上一轮待结算的失败决定，重置尝试额度并复用已下载文件。正式交付后释放临时目录；测试模式保留产出统计并清除临时文件及预留。

## 验证

- 新增 5 个回归场景：字幕无文件时仍交付媒体；429 后按冷却重试且只补字幕；本地重试不重置下载上限；手动补交清除待结算失败；测试模式失败后正确登记和释放空间。
- 主回归运行 117 项，结果通过，跳过 1 项。覆盖交付、文件发布、租约、账号恢复、通知和统计。
- 最终补充运行 79 项，结果通过，跳过 2 项。覆盖上述新场景、调度等待、账号恢复和磁盘预算。
- Python 编译检查与相关文件差异空白检查通过。
- 两次运行有交集，数量不能相加作为独立用例总数。

扩展检查还修正了 `tests/test_test_receipt_recovery.py` 向全局设置提交已移除的 `storage_mode` 的测试夹具。该文件仍有以下 2 项测试失败，本次没有修改它们对应的运行逻辑：

- `test_cleanup_preserves_queued_completion_until_worker_settles_it`：已确认登记的回执对应文件被清理，测试期望排队期间保留。
