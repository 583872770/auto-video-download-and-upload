# lixinhao 实例接入共享 MySQL 与 Redis

## 部署与访问

新服务器管理入口为 `http://lixinhao.asia:8000`，使用原管理账号登录。新实例 ID 为 `lixinhao`，名称为“lixinhao 服务器”，提供管理页面和下载能力，初始保持暂停且未选择任务。洛杉矶实例继续运行原任务。账号、任务和计费使用洛杉矶现有 MySQL；目录、浏览器、Cookie、代理及实例身份保持独立。

新服务器原有服务占用 5000 端口，8080 端口从外网不可达，最终使用已验证可达的 8000 端口。项目目录为 `/opt/frameflow`，编排为 `compose.yaml`，连接配置为仅 root 可读的 `app.env`，配置、状态和下载目录分别位于 `config/`、`state/`、`videos/`。浏览器桌面仅映射宿主机 `127.0.0.1:6081`。

最终镜像为 `youtube-downloader-app:remote-ui-20261120-r61`，镜像 ID 为 `sha256:ae89e100f39f9feacd4233a3bd5077f0d7edd4c18bf65c695cf674f7fbda1880`，发布记录目录为 `/opt/frameflow/releases/lixinhao-20261120-r61`。运行文件清单 SHA256 为 `ebd8a50c56f88d60212a9fcd9b4ec56713d5a6ada09fa51f52b41c7519edc028`，199 个运行文件逐项核对一致。

## 网络与跨地区适配

MySQL、Redis 通过新服务器的 `frameflow-data-link.service` 建立 SSH 加密转发，不发布洛杉矶数据库端口。专用 SSH 用户为 `frameflow-link`，密钥限制目标地址，服务已启用开机启动、断线重连与心跳。新服务器使用独立 `frameflow-net` 网络，网关为 `192.168.240.1`；MySQL 转发监听该网关 3306，Redis 转发监听该网关 16379，防火墙只允许对应 Docker 网段访问。新服务器原有 Redis 及其他业务服务保持原配置。

应用内 `mysql` 通过主机映射指向转发网关，保留与洛杉矶相同的 MySQL URL，避免共享 Redis 却使用不同进度命名空间。两端实际数据库 UUID、库名、Redis 命名空间及账号加密密钥摘要均核对一致。洛杉矶补齐实例地址 `http://216.227.169.90:8000`，持久化配置及共享注册记录已更新，未重启洛杉矶应用。原地址记录保存在洛杉矶发布目录 `lixinhao-20261120-r58/la-address-before.json`。

本次按实际延迟做三项调整：Redis 建连和读写超时支持 `VIDEO_REDIS_SOCKET_TIMEOUT`，默认仍为 0.2 秒，新实例设为 2 秒；启动表结构检查复用同一连接，避免 NullPool 对每个表检查反复建立跨地区连接；页面普通读取超时从 15 秒调整为 45 秒，顶部状态及通知调整为 30 秒。表结构及数据库校验规则没有变化。新实例主连接池为 5，溢出为 2。

这几项适配只发布到新实例；洛杉矶仍运行 r58，双方共享相同数据结构与实例协议。跨地区查询仍有明显延迟：最终一次采样中认证、实例列表、任务列表及工作台接口约为 8.8、19.0、8.8、10.1 秒，不能将调整等待时间解释为查询已经提速。

## 维护与回退

在新服务器执行 `docker compose -f /opt/frameflow/compose.yaml ps` 查看应用；使用 `systemctl status frameflow-data-link` 检查加密通道。连接配置及账号密钥仅在服务器上保存，禁止将 `app.env` 或发布目录中的环境备份加入仓库。

仅回退新实例时，使用 r61 发布目录中的 `compose.before.yaml` 恢复 r60 镜像配置后启动；不恢复共享数据库备份，不删除其他实例的任务。完全停用新实例时先停止其下载、停止应用和加密通道，再处理该实例记录。源数据库容器地址变化时应同步更新转发目标及受限密钥允许的地址；新服务器出口 IP 变化时应同步检查洛杉矶专用密钥的来源限制。
