# 本地处理进程复用与性能验证

## 发布内容

北京时间 2026-11-19 11:24 完成洛杉矶部署，镜像 `youtube-downloader-app:processing-pool-20261119-r53`，发布目录 `/root/deployments/processing-pool-20261119-r53/`。基于 r52 不可变镜像，只更新 `webapp/worker/queue.py`、`webapp/delivery/processing.py`，新增 `webapp/worker/idle.py`，不变更数据库结构或依赖。

本地处理进程完成工作后复用，连续空闲最多等待 60 秒，再退出；新计划提交后写本机唤醒通知，漏通知、尚未结算的交接及延迟重试由每 2 秒的队列检查兜底。空闲时不保留任务租约或数据库事务，不领取账号或下载空间预留，每 10 秒报告一次空闲心跳。暂停、停止、实例接管及处理并发缩减仍有效，多出的进程完成当前任务后退出。监督进程保留原有异常重启退避。

## 验证与备份

- 本地新增生命周期测试通过，覆盖通知、漏通知、连续空闲期限、等待前释放数据库连接、实例控制隔离、接管校验、缩容前停止领取、存活进程复用及异常重启。
- 真实 FFmpeg/HTTP 测试验证同一个独立处理进程在空队列间隔后接手第二个任务，并在暂停后正常退出；本地处理失败后仍能继续处理其他任务，失败源文件保留用于重试。
- Linux 共验证 118 项：首轮 117 项通过，另 1 项因隔离测试目录缺少相对入口路径失败；修正测试以已导入程序的绝对路径启动子进程后，该项重跑通过。运行补丁未因该测试路径问题改变。
- 独立 MySQL 临时库 10 项集成测试通过，包括真实交接、进程复用、失败继续、容量限制、崩溃后续做与源文件清理；临时连接环境文件已删除。
- Windows 首轮 94 项回归有两项环境问题：缺少 `oss2` 依赖、WebP 系统 MIME 映射差异；这两项均在 Linux 回归中通过，不以 Windows 首轮全绿描述结果。
- 上线验证 12 个页面、3 个静态资源及相关业务 API，3 个运行文件的 SHA-256 与清单一致。切换前后实例标识、配置/限制摘要、账号与 Cookie 绑定数量、凭据摘要和全局暂停设置一致，按原实例意愿恢复下载。
- 数据库一致性备份 319,862,140 字节（约 305 MiB），gzip 完整性验证通过，解压 SQL 1,663,944,419 字节；配置、运行密钥与原容器信息另行保留。
- 上线后容器健康，自动重启 0、未发生 OOM；首次复查两个处理进程已连续存活约 90 秒，各约 87 MiB RSS，空间等待、清理失败、已完成待清理及未归属文件均为 0。

## 测量口径

优化前窗口为 11:02:45–11:12:45；优化后在发布完成后热身三分钟，再取同长 10 分钟窗口。测量期间不运行构建、测试或备份。应用 CPU 取容器 cgroup 累计 CPU 时间差，除以窗口秒数及四核容量；整机 CPU 取每 5 秒的宿主机采样均值。下载速率取媒体接收计数的滚动速率采样均值。完成任务及产物字节取实例 `download_runtime_hours` 的同窗口增量，产物字节包含交付输出，不能直接当作公网下载流量。

处理进程启动数来自窗口内日志去重。首轮优化前测量因汇总脚本变量名错误无有效结果，已弃用并重新采集；最终两组测量使用修正后的同一脚本，并持续保存中间样本。

前后是同一业务队列的连续不同时段，视频大小、账号冷却及资源保护可能变化，不是同一批视频的随机对照实验；短窗口仅用于验证当前收益，不能保证全天固定比例。

整机平均 CPU 观测下降约 11.50 个百分点，任务完成数增加约 6.8%；但平均产物体积减少约 21.2%，每 GiB 产物 CPU 时间只减少约 1.8%。因此不能把全部 CPU 降幅或任务数变化归因于进程复用，更不能宣称稳定提速。平均媒体接收速率实际下降约 17.0%，此次未证实下载字节速度改善；最终瞬时媒体速率约 599.66 Mbps，也不能替代窗口均值作为提速证据。下载并发、账号策略和解析并发未作配置调整，进程上限变化来自原资源保护机制。

优化后四条失败记录均来自来源获取阶段：一条来源解析未知错误、一条视频分块 HTTP 403、两条仅有 DRM 格式限制。该窗口未发现本地处理失败、监督调度错误或工作进程非零退出。上游失败仍需按原策略处理，进程复用不解决这些限制。
