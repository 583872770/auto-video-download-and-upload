本次仅发布洛杉矶实例，首次发布名 `player-cache-20261123-r63`，最终修订版为 `player-cache-final-20261123-r64`。基于正在运行的不可变镜像，更新 `webapp/player_cache.py`、`webapp/downloader.py`、`webapp/parallel_http.py` 和 `webapp/disk_budget.py`。依赖、数据库结构、前端资源和下载并发配置沿用现有设置。方案依据见 [Node 排查与隔离实验](2026-11-23-node-cache-review.md)。

## 实现

每个任务继续创建独立下载器、Cookie 会话和 Node provider。项目只缓存版本化公共播放器源码和预处理代码，不缓存请求挑战、求解结果、临时媒体 URL 或用户身份。普通 yt-dlp `cachedir` 继续关闭，避免引入未纳入额度管理的其他缓存；项目按实例目录管理本次两类公共代码。

缓存目录为实例 `runtime/cache/youtube-players`，计入“运行缓存”。包含源码、预处理结果和自身目录/锁文件开销，合计不超过 128 MiB；最多 16 个完整 URL 对应的播放器版本/变体，24 小时过期。有效额度还受当前缓存分类额度、其他运行缓存占用及最低磁盘剩余空间限制。配额不足、缓存不可写时仍按原流程求解，缓存不是开始下载的必要条件。

按播放器键的跨进程锁避免首次重复构建；同任务内重入不会死锁。固定 16 个锁条目，避免版本更换导致锁文件无限增长。全局额度锁只保护写入、原子发布和淘汰，不跨网络或 Node 计算持有，也不持有 MySQL 事务。后台现有维护线程约每 30 秒清理过期、超额、遗留写入文件；低空间时回收未使用缓存。正在读取或构建的条目暂时跳过，下一轮重试。

命中时先将完整且验证过的代码读入当前任务内存，随即释放播放器文件锁，再执行 Node；同一播放器的不同任务可以并发求解。仅冷构建和损坏重建串行。缓存命中后即使磁盘条目被回收，当前任务仍使用已经读入的完整代码。

读取校验结构、TTL 和代码摘要，预处理兼容标识包括项目协议、yt-dlp、EJS 与 Node 版本。命中的预处理代码运行异常或结果校验失败时，丢弃该条目并回退原路径重建一次；继续失败则按原有错误策略处理。原有 403/429、任务租约、停止、账号冷却、输出校验和留样流程保留。

Windows 首轮 79 项中有一项旧测试仍要求测试文件在结算前立即删除。该期望与现有留样后清理契约冲突，已修正为验证有效交接、保留结算后处理信息及清除迟到的磁盘告警。修正后 10 项专项和 71 项磁盘/下载回归通过；部分需要 FFmpeg 或创建链接权限的案例在 Windows 跳过。Linux 候选 185 项回归通过，其中 4 项 Windows 专用测试跳过；覆盖真实 FFmpeg、HTTP/HLS、留样和多类型交付。

另增加需要公开脚本 fixture 的真实 Node/EJS 回归：不携带账号和网络连接，比较关闭缓存、首次构建、新下载器命中结果，并用摘要合法但执行错误的代码验证真实 Node 回退重建。验证容器使用同一个不可变基础镜像及当前测试文件，网络禁用，CPU/内存有界。

首次线上复核发现 r63 将命中求解也放在播放器文件锁内，会意外串行同播放器任务。已修正，并新增两个命中任务必须同时进入求解的并发回归；Windows 10 项缓存检查通过，最终 r64 的 58 项缓存/真实 Node/进度/HTTP/HLS 检查全部通过，无跳过。最终镜像再次执行上述磁盘额度与维护集成验证。r63 的首次后测已停止并明确归档为无效窗口，不用于最终性能结论。

## 最终前后结果

优化前窗口为 14:12:51–14:22:51，最终 r64 后测为 15:06:50–15:16:50（北京时间），两组均约 600 秒。CPU 以整机四核总容量为分母；媒体接收和网卡接收为不同口径，交付产物体积还可能包含多个输出，不能互相代替。

整机平均 CPU 减少 7.35 个百分点，应用平均 CPU 减少 8.82 个百分点；媒体接收速度增加约 9.2%，网卡接收速度增加约 6.9%。窗口内交付产物总量增加约 20.1%，每 GiB 产物的应用 CPU 时间减少约 27.0%。缓存内容复用和功能正确性有独立验证，本次业务窗口也观察到 CPU 与平均接收速度改善。

两个窗口的配置和限制摘要在开始、结束时均一致，没有手动调整并发或账号策略。但账号容量自然恢复、自动资源保护使实际工作进程数不同，后测平均产物体积也增加约 21.9%。这是顺序队列的不同时段观察，不能把全部差异单独归因缓存，不能保证全天固定提速 9.2%。短时 CPU 仍可能较高，缓存不消除媒体传输、解析其他步骤和本地处理的开销。

后测终态失败为 7，异常记录对应 6 个仅 DRM 格式限制及 1 个视频不可用；已单独核对未分类事件的原始原因是 YouTube 返回 `This video is unavailable`，发生在解析阶段。未发现缓存异常、损坏重建或新增本地处理失败，不能用这一窗口的失败率直接判断账号风控变化。

最终服务健康、重启次数 0、未发生 OOM，实例配置、账号及凭据保持一致。采样后最近保留日志中的 78 次求解全部命中预处理缓存，无重建、写入或容量异常；样本墙钟中位数约 0.688 秒。缓存仍只有一个条目，分配空间 7,626,752 字节。磁盘等待、自动清理失败和未归属文件均为 0；旧的 324 KiB 失败处理计划继续保留。

原始前后采样、比较 JSON、最终验证、异常归因及测试证据已取回本地私有 `results/`。两个验证容器均已自动移除，r63 和 r64 各 3,060,278 字节的公开播放器 fixture 已在摘要核对后删除；公共脚本摘要和测试日志保留。此次不修改前端，复用已运行的 r62 前端资源，并验证业务页面和接口。
