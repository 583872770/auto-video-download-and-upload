# 测试下载完成结果恢复修复

## 问题及修复

同一单视频任务的不同尝试使用不同临时目录。统计文件账本按任务逻辑标识去重，恢复和清理却只按原路径核对，造成“已有账本、不再插入”和“新路径未登记”的冲突。任务反复进入 disk_wait，每次约 60 秒后再领取。

修复将统计文件标识计算统一为 `DownloadStatistics.file_identity()`，登记与恢复复用同一规则。原路径和大小能够对应的凭据继续按原规则处理；跨尝试路径的恢复还要求：

- 单视频下载任务、单个完整结果凭据、单条同任务账本。
- 凭据、任务、账本的视频标识均非空且一致。
- 正数文件大小与账本一致，现存文件实际大小也一致。
- 账本标识符合该任务原有的文件去重规则。
- 现存文件位于该凭据控制的目录内，经过原有路径及链接检查。

核对通过后由原有执行器恢复流程结束任务，保留原账本、原归属会话和原文件统计，不再次请求源站。传统按路径计数的任务不会因同大小、同视频而自动复用另一路径的记录。文件缺失、残缺、视频不符或凭据不完整时继续保留证据。

同时，维护清理不会在任务仍排队时抢先删除已完成文件，避免执行器失去恢复结果后重新下载。只有任务执行器完成恢复，或任务已经终止且凭据核对通过，才清理相应临时结果。
