## 页面职责

- **账号资料**：全局邮箱、备注、绑定实例、关联摘要。支持新增、编辑、删除、搜索、筛选和分页。管理员按需查看或复制密码、附加信息、接码网址，关闭详情会清除已显示的密钥。
- **Cookie 与登录**：所有实例的 Cookie 列表，支持实例、关联、登录检测筛选。上传时选择已绑定实例的账号并确认归属；新 Cookie 不会自动入池。历史未关联 Cookie 可继续使用。
- **账号池与节奏**：顶部明确当前管理实例，成员、开关和节奏统一点击“保存账号池与节奏”，无需再到系统设置保存。不同实例独立，有草稿时阻止切换实例。

系统设置保留下载策略、进程容量、存储与诊断；直连源地址移至网络与代理。实例页保留运行控制、负载、显示名称与管理入口。工作台仍按 Cookie 展示格子，关联资料后使用邮箱作为标题；点击可进入统一详情和恢复记录。

## 导入

粘贴或选择 UTF-8 TXT，最多 1 MB、1000 行，支持 BOM、CRLF、空行：

```text
demo@example.com----password----附加信息----接码网址：https://example.com/
other@example.com----password
```

密码和附加信息原样保留，第三段不推断用途。邮箱忽略大小写去重；批内重复或格式错误会阻止整批提交。预览仅显示掩码；默认跳过重复，显式更新只修改密钥资料，不覆盖既有绑定、备注和 Cookie。省略第三、四段时保留原值。预览有效期 15 分钟，提交时检查内容及资料版本，发生冲突须重新预览。

已有账号编辑时密码留空表示保留；附加信息、网址需勾选修改开关，允许明确清空。删除资料会擦除其密文并保留 Cookie、归属及无密钥审计；关联凭据仍在池或当前使用、实例仍有任务执行时拒绝删除。

## 多实例与登录状态

账号资料和 Cookie 列表从共享数据库读取，不随工作台所选实例转发。上传、检测只在账号或 Cookie 的实际所属实例执行，离线不回退访问入口。通用浏览器登录仍可从账号池打开；资料列表的“登录”使用下述账号定向流程。

同一邮箱关联的所有 Cookie 只允许在同一实例。资料删除、解绑、重新导入不会释放已登记归属。Cookie 的核心凭据独占规则继续由原绑定模块执行；本功能不新增跨实例迁移操作。

关联已有文件由管理员确认，系统不能通过现有登录探测核验真实 Google 邮箱；账号定向浏览器登录另外核对当前账号头部邮箱。登录检测和下载冷却分别显示；页面刷新只读取记录，不探测 YouTube。有效结果过期、Cookie 或出口配置变化后不再标为近期验证通过。自动轮换代理时，历史成功只证明记录出口通过，当前出口显示待确认。冷却期间沿用原规则阻止登录检测。

默认列表每 30 秒刷新且只刷新可见页签，隐藏页面不刷新。普通资料和 Cookie 查询在 SQL 中分页；需要冷却等衍生状态筛选时批量读取匹配候选，避免每账号一条查询或跨实例网络请求。单份 Cookie 详情和账号关联选择当前支持每实例前 100 份 Cookie；目标规模为每实例约 20 份。

## 从账号资料登录

管理员点击列表右侧“登录”，或详情中的“登录此账号”，打开专属登录面板。已绑定的账号固定使用原实例；未绑定账号须先明确选择在线实例。开始登录时保存归属，其他实例不作为离线替代。每实例同时只允许一个浏览器登录，关闭面板不中断浏览器，重新打开会继续显示状态。

默认勾选“自动填写邮箱、密码并接收邮件验证码”，可取消改用手动登录。自动填写只在 HTTPS 的 `accounts.google.com` 标准端口执行，每个字段最多提交一次，失败不会循环尝试密码。短信、身份验证器动态码、图片验证码、手机确认或不兼容页面仍由用户在实例浏览器继续操作；第三段附加信息不用于自动生成验证码。Google 拒绝自动化浏览器时仍终止并提示导出 Cookie，不修改浏览器安全策略。

邮件接码使用账号资料中保存的 `fbvjdjcf.asia` 接码网址；HTTP 地址自动升级为 HTTPS。目标实例使用独立、短期网络会话，仅向该网站的单邮箱入口提交当前邮箱，不发送 Google 密码、附加信息或 Google Cookie。开始 Google 登录之前先刷新收件箱，记录已有验证码；识别到 Google 的邮箱验证码输入页后每 30 秒刷新一次，最多等待 3 分钟。只接受当前邮箱中新出现且能确认来自 Google 的六位验证码，旧码、已知过期邮件、其他来源或多封无法区分的新码不自动提交。网站或跳转地址不受支持、收件失败或超时则保留浏览器供手动接管，不循环尝试错误验证码。Google 未提供邮箱验证方式时不会自动改用其他类型验证。

兼容 Google `/challenge/selection` 验证方式选择页：仅自动点击明确显示当前账号完整邮箱的“Get a verification code at …”或兼容中文选项，同一邮箱有重复选项时仅点击第一项一次；其他邮箱、掩码地址、短信和设备选项交由用户选择。邮箱验证码输入页同时识别 `/challenge/ipe` 和实际出现的 `/challenge/ipe/verify`。登录状态保留最近 24 条步骤记录，便于排查接码准备、选择方式、提交验证码及最终保存，记录不包含密码、验证码或收件箱会话链接。

已明确选中当前邮箱后，如果 Google 转到 `/challenge/ipe/consent` 发送确认页，会等待可见、可用的“Send/发送”按钮并点击一次。页面持续加载、按钮不可用，或发送后超过 30 秒仍未转到输入页，会显示具体原因并保留浏览器供手动继续；不会强制点击隐藏按钮或重复发送验证码。直接进入且未确认目标邮箱的发送页仍需手动确认。

接码网址、收件箱会话标识、邮件正文和验证码只保留在目标实例的登录会话内存中，不写入状态文件、任务日志或数据库。取消登录会关闭浏览器和收件会话。关闭管理页面的弹框仍沿用原规则，后台登录继续；每实例同时只有一个浏览器登录，不为账号列表持续检查邮箱。

密码仅在目标实例解密后交给登录线程，不经前端或节点请求传送，不写入登录状态文件。请求使用独立的账号登录 RPC 路径；旧版实例不支持时明确失败，不会降级启动普通登录。状态面板仅在打开且页面可见时每 2 秒读取当前账号一次，不为列表中每一行轮询。

登录成功后读取 YouTube 当前账号头部的邮箱，与所选账号忽略大小写核对，再导出 Cookie。同一短事务新增凭据、持久邮箱归属及账号关联，保留原 Cookie、账号池和下载参数。资料版本或归属在登录期间变化、邮箱不一致、邮箱无法确认时不保存 Cookie。新 Cookie 可在“账号池与节奏”启用；浏览器登录成功不替代下载出口的独立登录检测。通用浏览器登录入口沿用原行为。

## 首次部署配置

所有可管理账号资料的实例必须配置**同一个** `VIDEO_ACCOUNT_ENCRYPTION_KEY`，为随机 32 字节的 Base64。生成一次后安全备份，再配置给各实例：

```shell
python -c "import base64,secrets; print(base64.urlsafe_b64encode(secrets.token_bytes(32)).decode())"
```

两套 Compose 均已透传此变量，部署入口见 [DOCKER.md](../DOCKER.md)。开发未修改现有 `.env`。部署时在服务环境配置该变量并重建应用容器即可，数据库和 Redis 地址沿用现有部署设置。

洛杉矶实例的原密钥环境文件位于服务器 `/opt/youtube-downloader/secrets/account-encryption.env`，权限为 `600`，已注入当前应用容器，并在本次受限发布目录备份。以后使用 Compose 重建时，需在现有环境文件之外加载这份文件，或向容器显式传入相同值；只保留文件而没有传入容器不生效。新增实例应安全分发原密钥，不要各自生成新值。

密码、附加信息、网址使用 AES-GCM 加密后入库。密钥不存入 MySQL；普通列表和下载不需要解密。缺失密钥时可以查看既有摘要及继续使用 Cookie，新增、导入及读取密钥会明确拒绝。密钥与库内 key_id 不一致时拒绝写入或解密，不能通过生成新密钥“修复”。目前没有在线轮换密钥功能；恢复备份需同时恢复数据库和原密钥。

启动时自动创建五张独立表：`youtube_accounts`、`youtube_account_owners`、`youtube_account_cookies`、`youtube_account_audit`、`youtube_profile_auth`。不修改已有任务大表，不自动关联或导入真实账号。首次上线前按现有流程备份数据库，升级所有管理实例，保留原密钥备份。

账号资料变更和密钥读取仅对已登录管理员开放。viewer/operator 可查看摘要；节点 RPC 令牌不能调用资料密钥接口。审计只记录操作人、对象、动作和时间，不记录原始密码或导入行。

```shell
python -m unittest tests.test_account_library tests.test_account_library_fleet tests.test_mysql_schema
python scripts/verify_account_library_ui.py
python scripts/verify_cookie_profiles_ui.py

```

浏览器脚本使用临时 SQLite、虚构 Cookie 和模拟源站，不访问实际 YouTube 或生产库。自动填写专项脚本使用真实 Chromium 和完全拦截的模拟 Google 页面，覆盖文本类型邮箱框、隐藏密码框、单次提交、验证码交接和来源限制；不提交真实账号。另已执行实例管理、独占绑定、下载判定、登录和冷却相关回归。服务器候选镜像通过 121 项 Linux 回归和 19 项真实 MySQL 8.4 账号与多实例集成测试；MySQL 集成使用随机独立测试库并在测试后删除。MySQL 5.7/8.0/8.4 的索引定义通过离线编译校验，5.7/8.0 未做真实数据库运行验证。

邮件接码专项验证使用本地 HTTP 收件箱和真实 Chromium 的模拟 Google 页面，贯通邮箱、密码、验证方式选择、发送确认、新验证码、邮箱身份核对及 Cookie 导出，并检查旧码排除、取消与会话关闭。实际接码网站已通过仅提交邮箱的连接与刷新检查，实际邮件页面的 Google 验证码解析也已核实。上线后同一账号真实复测未经过填码步骤，最后只读检查确认邮件选项显示 `Unavailable because of too many attempts. Please try again later.`，已停止继续尝试；真实新邮件的自动提交与后续登录放行仍未验证通过，不能推测 Google 的恢复时长。
