# 页面功能与操作顺序

导航按日常工作、运行与排查、配置与维护分组。

| 页面 | 主要用途 |
| --- | --- |
| 任务中心 | 创建客户任务、导入视频清单、维护任务资料 |
| 下载工作台 | 选择实例和任务、启动或停止、查看处理进度；下方查看实时等待与风控提示 |
| 素材库 | 查询、预览和下载成品，按需同步或清理 |
| 交付与账单 | 查看交付数量、费用与导出记录 |
| 下载实例 | 多实例部署时查看运行状态和全局额度 |
| 执行日志 | 排查具体视频和后台操作的结果 |
| 网络与代理 | 先选择连接方式，再管理订阅、节点和连接测试 |
| 系统设置 | 按下表配置当前实例 |

## 设置分类

| 分类 | 功能 |
| --- | --- |
| 下载策略 | 下载方式与优先级、已启用下载器的画质和超时、保存方式、重试、字幕 |
| Cookie 与登录 | Cookie 账号管理、浏览器登录、当前登录检测；高级区包含源地址、请求节奏及冷却参数 |
| 并发与渠道 | 任务数、分片并发、带宽目标、浏览器并发、渠道策略、解析与连接预算 |
| 存储与清理 | 正式目录、文件组织、临时空间预算、暂停水位、日志大小与保留期限 |
| 运行诊断 | 工具和数据库状态、已保存策略的实时额度、限流、验证、资源占用及完整风控说明 |

分类切换保留未保存修改，表单底部统一保存。Cookie 上传、账号切换、登录检测、网络应用及清理按钮各自执行对应操作，不依赖设置表单保存。修改只影响当前实例，已有任务遵守原有执行规则。

未启用下载器的专属参数隐藏，重新启用后显示原值，不清空设置。详细风控、渠道上限与排查说明保留，工作台先展示操作区和进度，再展示实时诊断。

## 运行模式与渠道策略

“并发与渠道”中的运行模式统一为“自动调节 / 自定义”，分别对应配置 `throughput_mode: auto / manual`。自动调节在实例最高值内参考下载器媒体计数、资源压力和 Cookie 会话容量；自定义保持指定工作进程数。两者都遵守会话准入、渠道、连接预算、限流和验证规则。

渠道选择策略 `scheduler_mode` 单独决定用哪个入口，保存和运行时均不会覆盖运行模式。只使用 yt-dlp 也能开启自动调节；自动选渠道也能配合自定义并发。原有显式配置值保留。

启用 Cookie 池时，后台每约 5 秒读取核心会话额度和有效任务租约；自动模式不额外创建超出会话容量的准备进程。没有新鲜会话采样时最多保留 1 路控制进程，诊断额度显示待确认；整个池拦截时不新增下载，仍需原有人工恢复流程。该容量是本地策略估算，不是 YouTube 官方配额。

“当前限制说明”显示设置上限以外的瓶颈、核心会话数量、启动窗口和任务阶段。文件数、会话数、登录结果和账号身份分别表达：核心凭据不同不能证明账号不同，当前未核验 Google 账号身份。

自动控制不使用整机网卡流量作为增加并发的证据；媒体计数缺失时不因其他服务产生流量而加速。已有媒体统计、解析统计及资源压力退避继续生效。

## 常见操作

- 开始下载：任务中心导入清单 → Cookie 与登录确认凭据及出口 → 下载工作台选择任务启动。
- 下载太慢：运行诊断查看实际等待和额度 → 并发与渠道调整有关上限。
- 登录失效：Cookie 与登录打开账号管理，逐行检测并更新；不会自动清除限制。
- 空间不足：顶部磁盘状态直达存储与清理。
- 视频失败：执行日志查看单条原因及重试状态。

验证脚本：`scripts/verify_cookie_profiles_ui.py` 验证五类设置、跨分类保存、手机布局与 Cookie 操作；`scripts/verify_concurrency_ui.py` 验证限流、冷却、离线、资源等待、诊断与设置保存。
