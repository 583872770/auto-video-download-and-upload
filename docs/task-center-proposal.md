# 任务中心改造方案

日期：2026-10-26。本文覆盖整体设计，其中当前已实现范围见 [TASK_CENTER.md](../TASK_CENTER.md)。同目录 `task-center-prototype.html` 仍为独立演示草图，按钮只修改页面内状态；真实任务中心入口为 `/jobs`。

## 1. 产品模型

将“待处理清单”升级为“下载任务”。每次从任务中心导入 TXT/CSV 或粘贴 ID 创建一个新任务；任务详情内的“追加视频”只更新当前任务。创建空任务后再添加视频也受支持。

- 业务任务：一个客户的一张清单，拥有基本信息、视频条目、下载策略、独立概览、执行控制和账单。
- 视频条目：业务任务中的一个 YouTube ID，具有自己的状态、执行尝试和交付记录。
- 导入记录：首次导入和后续追加分别记录来源、时间、读取/新增/重复/无效数和错误行。
- 执行尝试：一个视频可以重试或切换下载器；尝试次数与视频数分别统计。

界面中的“任务”始终指业务任务，现有单视频技术任务统一称“视频条目”；运行日志和开始/暂停区间降为执行记录。

## 2. 导航与页面

侧栏建议保留：全局总览、任务中心、素材库、下载实例、系统设置。

原“下载统计与计费”迁入各任务详情。全局总览保留跨任务的账单汇总和导出，不再并列展示两套可被误相加的计费口径。

### 任务中心

使用表格展示，适合大量任务。字段包括：任务名称/编号、客户、状态、视频总数、交付/失败/待处理数、处理进度、交付大小、预计费用、创建时间、操作。

支持按客户、状态、名称和编号筛选；默认显示未归档任务。任务编号唯一，名称允许重复。可勾选多个任务开始、暂停或归档；批量操作展示每项成功/失败结果。

新建任务表单：客户、清单名称、备注、粘贴 ID 或导入文件、每 GB/GiB 单价、下载策略。客户与清单名称必填；文件导入时名称默认取文件名。单价允许暂不设置，显示“待设置”，不可与 0 元混淆。

创建后不自动下载；即使其他任务正在下载，新任务也保持“待开始”。重复点击提交通过请求幂等键避免意外创建两单；有意再次导入同文件仍可形成新任务。

### 任务详情

固定显示任务名称、客户、编号、状态；主操作为“开始/继续”“完成当前后暂停”“立即停止”。更多操作中放编辑信息、导出、归档、删除。

详情含五个页签：

1. 任务概览：业务进度、当前执行、交付与费用、异常提示。
2. 视频清单：追加、查找、状态筛选、批量操作、导出。
3. 统计与计费：本任务交付账本、测试数据、下载器统计、账单。
4. 执行记录：开始/暂停、导入/追加、失败重试、配置修改和视频日志。
5. 任务设置：基本信息、计费规则、下载策略。

## 3. 独立概览

顶部始终展示“当前任务：客户 / 清单名称”，切换任务时所有指标、视频、文件、导出与执行记录统一切换，不沿用上一任务的数据。

第一排四组指标：

| 指标 | 定义 |
| --- | --- |
| 清单规模 | 当前有效视频数；同时列出累计新增、累计移除数 |
| 处理进度 | 交付成功、测试成功、跳过、最终失败、待处理、执行中分别展示 |
| 累计交付 | 可计费成品文件数、精确字节数及 GB 显示值 |
| 预计费用 | 本任务实际交付字节 / 计费单位字节 × 单价；未设单价时不显示虚假的 0 元 |

进度区分别显示：处理完成率（交付成功 + 测试成功 + 跳过 + 最终失败）/ 当前有效视频数、交付成功率（交付成功 / 当前有效视频数）。空任务显示“尚无视频”；全部失败也可以处理完成 100%，但必须标注“完成但有失败”。

运行区：当前视频、执行阶段、速度、阶段耗时、执行实例；任务速度只汇总本任务实际传输，排队/远端转换不计传输速度。剩余时间仅在样本和速度足够时估算，否则显示“估算中”。

辅助区：最近交付、失败原因分布、最近操作、导入结果。清单为空但保留既有交付账本时，明确显示“当前清单为空，历史交付仍保留”。

全局总览只汇总任务数、执行任务数、总传输速度、累计交付、未结算预计费用及已结算金额。已结算额与未结算额分开；同一任务不会两次进入费用合计。可按客户/时间查看，并注明时间筛选按创建、交付或结算事件中的哪一项生效。

## 4. 视频清单管理

表格字段：选择、视频 ID/链接、标题、状态、下载器、成品大小、执行实例、错误原因、更新时间、操作。按游标分页，支持 ID 查找和服务端状态筛选；批量操作明确“当前选中”与“全部匹配”的范围。

| 操作 | 行为与限制 |
| --- | --- |
| 追加视频 | 粘贴或上传文件；展示新增/重复/无效数；同任务内去重；下载中允许追加，新增项进入本任务队列 |
| 移除视频 | 单条/批量移除待处理或最终失败条目；保留操作记录，可重新追加；移除后不计入当前有效视频数 |
| 移除执行中视频 | 先取消该条执行、使租约失效并等待停止，再移除；不能先删行再让进程继续写结果 |
| 清空视频清单 | 默认“移除未交付条目”，保留成功/交付记录；提供“移除全部条目（保留历史账本）”选项。先暂停本任务并取消未完成导入，待执行与导入退出后完成；需输入任务名称确认 |
| 重试失败 | 单条或全部失败重试，复用原逻辑条目；每次新建执行尝试，不能追加重复视频行或重复计费 |
| 导出 | 全部 ID、待处理 ID、失败 ID（附原因）、交付文件清单、导入无效行 |

已交付条目通过“移出当前清单”隐藏或移除其有效成员关系，交付账本与历史执行记录保留。清空后再次追加已交付 ID，应恢复原条目和既有交付状态，不自动重新下载或再次收费；确需再次交付时创建新业务任务。

导入校验：统一 11 位 ID 和完整 YouTube 链接；剔除空行；重复/无效行分别计数；保留原始文件名和错误明细。大文件仍使用分块导入和断点记录，避免全量载入浏览器。

## 5. 任务状态与执行控制

将三类状态分开，避免“下载完成”等于“已经结算”：

- 生命周期：有效、已归档、已删除。
- 执行状态：空任务、导入中、待开始、排队中、执行中、暂停中、已暂停、已完成、完成但有失败；阻塞原因另列，如全局暂停、实例离线、Cookie 失效、磁盘不足。
- 账单状态：未结算、已结算。

任务中所有有效视频都到达终态，且没有未完成导入，才判定处理完成。已完成但未结算任务可追加视频并重新进入待处理状态。最终失败由“重试失败”重新入队。

领取条件必须同时满足：系统允许领取 + 任务已开始且未暂停/归档/删除 + 实例可用 + 全局/实例/任务并发未满。开始任务不解除全局暂停；界面应提示“系统已暂停，任务将排队”。解除全局暂停只恢复原本已开始的任务，不启动新建任务。

“完成当前后暂停”停止本任务新领取，正在执行的条目继续；“立即停止”仅取消当前任务的执行并把未完成条目留在本任务队列，其他任务继续。任务阻塞与全局阻塞分别提示。

任务共享实例资源，建议按同优先级任务轮流领取，防止大任务长期占满队列；全局、实例仍有并发上限，任务可设较小并发上限，不预留独占资源。优先级和限速可放后续迭代。

## 6. 下载策略

系统设置提供默认模板；新任务创建时复制下载器顺序、画质、重试上限、正式/测试模式等到任务设置，后续系统模板修改只影响新任务。编辑任务策略只影响后续执行尝试，运行中的条目保留自己的策略版本。

Cookie、代理、浏览器可执行路径、磁盘目录、实例并发仍属于实例环境，不复制为任务中的机器绝对路径。

正式/测试模式在首次开始后锁定，避免同一任务中的同一 ID 先测试成功后无法解释正式交付状态；提供“复制为正式任务”入口。正式任务按独立任务子目录组织成品，显示客户/任务名称，但磁盘标识使用稳定任务 ID，改名称不移动文件。

## 7. 去重与跨任务文件策略（关键决策）

同任务内必须去重。同一 ID 的重复导入、并发追加和失败重试不得创建重复有效条目。

当前实现采用“各任务独立下载、独立计费”：任务 A 的成功、失败、暂停、去重和归档不能阻止 B 录入或执行相同 ID；任务隔离的目录避免同名覆盖。预约去重和下载归档均按任务隔离，仅改页面或仅修改预约键无法实现该行为。

备选“复用成品”：必须按画质/格式、文件存在性与可用性匹配，并向目标任务登记独立交付来源。是否对复用交付计费需明确；首次迭代建议不加入，以免把“新下载流量”与“客户交付量”混为一谈。

## 8. 独立统计与计费

以任务为唯一业务账本维度，视频尝试、下载器切换、暂停、服务重启和跨实例接管不创建新业务账单。保留全局执行会话作为技术记录，不再当作另一张客户账单展示。

- 按合格成品的实际字节计费；封面、字幕、元数据、失败残留、测试文件均不收费。
- 每份逻辑交付幂等登记；重试和重复回调不重复计费。
- 视频成功数、文件数、下载器尝试成功率分开，不能把多次尝试当多个视频。
- GB = 10^9 字节，GiB = 2^30 字节。存储精确字节和高精度金额，按整单累计后四舍五入至分，不先逐文件四舍五入。
- 未结算时修改单价/单位会重算本任务全部交付预计费用，保存前显示旧/新金额；保留修改记录。
- 结算生成固定账单快照（单价、单位、计费字节、金额、交付明细、结算时间），已结算任务锁定计费设置和清单，补充视频通过“创建补充任务”完成。归档与结算独立；未执行完、存在执行中/导入中内容时不能结算。
- 失败视频可明确标记放弃后结算已有交付；无交付不能伪造费用。免费任务用显式 0 元单价。

任务账单页提供：交付视频数/文件数/大小、失败数、测试数据、预估/结算金额、下载器尝试统计、交付明细 CSV、任务汇总 CSV。素材被删除时只标记“文件已删除”，不倒扣历史交付和费用。

## 9. 归档、删除与素材

三类操作范围清晰分离：

1. 清空视频清单：改变任务中的有效成员；保留任务、账本和磁盘文件。
2. 归档任务：停止执行并从默认任务列表隐藏，历史与文件仍可查看。
3. 删除任务：逻辑删除并停止领取，隐藏任务；后台保留交付、结算和审计记录，可在回收站恢复，不执行物理级联删除。

删除素材是独立入口，需要展示文件数量、字节数、所属任务与实例，并对运行中的任务禁用。原全局“清空素材库”保留在系统维护区，任务页中只出现本任务范围的删除入口，不能复用全库清空接口。

全局素材库增加客户/任务筛选和所属任务标签；每个任务也有“查看本任务素材”。归档/删除任务后，素材仍能通过保留的任务编号追溯。

## 10. 技术落地与兼容

沿用 `download_lists.id` / `batch_id` 作为业务任务身份，不另造一套平行计费主键。

- `download_lists` 补充备注、生命周期、领取状态、停止版本、配置版本、任务并发、更新时间、归档/删除时间、账单状态；不要用一个 status 字段混装所有状态。
- 视频成员、执行尝试、不可变交付账本分离。成员的唯一约束使用任务 ID + 视频 ID；移除成员不删除账本关联行。下载源 ID 与任务去重键分开存储。
- 导入记录新增独立 ID 与所属任务 ID，一任务可多次导入；现有“导入 ID 就是清单 ID”的一对一关联必须拆开。导入任务、追加请求都带清单版本，清空/删除后旧导入不得继续插入视频。
- `store.py` / `tasks.py` / `web_worker.py` 的领取、停止、重试、续租和提交同时检查任务及执行版本，防止暂停/清空后旧进程晚到的完成事件污染状态。
- `statistics.py`、`statistics_methods.py`、`catalog.py` 和概览接口均支持任务过滤。素材关联交付/任务，不能仅按目录猜归属。全局聚合用任务账本口径，避免与会话统计相加。
- 所有新增索引、状态操作继续兼容 MySQL 5.7.9+ / 8.x；队列、批量追加和计数更新在事务中完成。大列表使用数据库分页和后台批处理，清空期间给出状态和可恢复结果。

建议接口使用 `/api/jobs` 区分现有技术 `/api/tasks`：任务 CRUD、任务内 `/videos`、`/imports`、`/start`、`/pause`、`/stop`、`/retry-failed`、`/overview`、`/statistics`、`/settlement`。暂停请求带模式，批量操作返回受影响范围与任务版本；后台清空返回操作 ID 供查询进度。旧 API 保留兼容层，不能再默默放行所有新任务。

历史升级：原每个清单/批次映射为一个任务；无客户信息显示“待补充”；无法可靠归属的历史数据单列“历史未归属”，不凭路径或名称猜测。旧独立账本继续沿用，无完整账本的旧任务明确“历史未完整统计”，不补造费用。保留旧归档数据供兼容读取，新任务使用任务级去重空间。

## 11. 实施次序与验收

第一阶段完成核心闭环：任务中心/详情、独立开始暂停、追加/移除/清空、任务级去重与策略、独立概览账单、历史迁移、归档。第二阶段加入结算快照、回收站、优先级/公平调度细化、客户维度报表、批量交付导出。

必须通过的验收场景：

1. 连续导入两次形成两个任务，客户、名称、视频及账单分开；同文件的重复点击不意外创建两单。
2. 向已有任务追加不新建业务任务，重复 ID 计为重复，新增项只归当前任务。
3. A 暂停、清空、删除、重试不改变 B 的领取和统计；全局暂停仍阻止所有领取。
4. 按最终选定的跨任务策略验证同 ID；同任务并发追加只保留一个有效条目。
5. 清空与后台导入/下载并发时，没有清空后重新冒出的旧视频和失效执行结果。
6. 多次暂停、失败重试和跨实例接管后，每份交付只登记一次，费用只累计一次。
7. 追加/移除后的进度与历史交付账本均可解释；处理 100% 且全失败不显示为交付成功。
8. 切换任务时，概览、视频、下载器统计、素材、导出和账单全部保持同一任务范围；不存在旧请求覆盖新任务页面的数据。
9. 清空清单/删除任务不删除素材或冲减历史费用，删除素材不影响历史账本。
10. MySQL 5.7/8 上迁移可重入，历史无归属数据不伪造；新旧接口不互相绕过任务暂停。
