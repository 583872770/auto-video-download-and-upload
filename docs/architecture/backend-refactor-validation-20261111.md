# 核心后端整理与验收（2026-11-11）

## 范围与行为契约

本轮将大型入口文件中的实现按职责拆开，保留已有调度、退避、冷却、领取与租约语义，不重新设计算法。实例配置仍分别保存；Cookie 的实例归属与独占校验继续由原领域模块和数据库约束处理。任意实例前端切换目标实例时，配置、部署设置与操作仍使用所选目标。

没有迁移 `.cache/web`、Cookie、视频、配置文件或 Docker 持久卷，也没有执行数据库结构迁移。根目录 Compose、Dockerfile、`Utils/`、模板和静态资源路径保持可用。

## 实现职责

| 模块 | 职责 |
| --- | --- |
| `app.py` | 保留 `create_app` 签名、可覆写适配器和 CLI 入口 |
| `webapp/application.py`、`middleware.py` | 应用装配、扩展初始化、路由注册、后台启动；认证、CSRF、安全头与错误映射 |
| `webapp/routes/` | 页面、配置、工作台、YouTube、素材和任务 HTTP 输入输出 |
| `webapp/services/` | 配置保存与回滚、Cookie 操作、下载预检、任务控制、工作台组装和跨实例业务 |
| `webapp/repositories/` | 任务编解码、写入、查询、队列、租约、历史，以及工作台数据库快照 |
| `webapp/store.py` | 组合 repository 的 TaskStore 兼容门面，保留所有调用方接口 |
| `webapp/worker/` | 动作分派、单次下载流水线、工作区和磁盘租约、心跳、异常结算、结果归档与交付 |
| `webapp/adapters/` | 单渠道执行、下载器报告桥接和实例 HTTP RPC |
| `webapp/runtime/supervisor.py` | 后台进程监督、领取唤醒与退出管理 |
| `webapp/config/` | 字段与默认值唯一实现、配置验证与保存 |
| 原 settings/config_schema/tasks/web_worker 模块 | 显式兼容导出或调用包装，保留原入口和已有覆写点 |

每次下载使用独立的 `DownloadSession` 保存失败阶段、字节计数和输出结果。原 `app.py` 的 39 个路由路径、HTTP 方法与 endpoint 经 AST 对照保持一致。

工作台查询现在先取得数据库快照并释放连接，再进行本机资源健康检查和诊断组装，减少这部分本机检查占用连接的时间。新增契约测试检查健康检查开始时没有仍占用的连接；本轮未测量吞吐提升比例。

## 验证脚本修复

验证实现移动至 `scripts/verify/`，内部引用更新到新路径；旧路径导入只导出符号，直接运行时仍进入对应脚本，避免导入辅助类时意外执行整套验证。浏览器检查使用现有 `browser_options` 选择已安装浏览器。

页面断言同步当前产品：工作台视频处理进度区已移除；账号池与节奏在账号管理中保存；冷却账号单独筛选。保留后端任务状态、跨实例读回、Cookie 归属及启停隔离的验证。
