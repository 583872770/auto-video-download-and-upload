# 三项配置支持 0 表示不限制

`youtube_cookie_pool_worker_limit`、`youtube_hourly_start_limit` 和 `youtube_daily_start_limit` 接受 0；默认值仍为 20、30 和 720。负数继续拒绝保存。系统设置与账号管理中的输入范围、说明、保存重载、预算预览和运行诊断同步支持该语义。

Cookie 池下载进程上限设为 0 时，仅移除配置的进程数量限制。常规进程容量仍取账号会话容量、渠道与连接容量（含准备余量）、内存估算、数据库预算的最小值，执行器原有 64 路边界和动态资源保护继续生效。首次启动和读取新鲜采样使用相同规则，不把 0 收紧成一个进程。

数据库自动核算按所选 Cookie 文件数乘以配置的每会话并发估算进程需求，最多 64；不因临时冷却或预热而减少预留。实际账号准入继续去重并核验归属。显式设置的部署连接硬上限继续生效；移除进程配置上限不代表移除数据库部署限制。

两个滚动启动预算独立生效：0 只关闭对应的小时或二十四小时次数检查。账号池的固定、渐进模式以及非池渐进模式都遵循此规则。关闭期间仍记录启动时间、保留最近二十四小时历史；以后恢复正数时按保留历史重新限制，不重置计数。账号间隔、任务结束休息、已有启动窗口、冷却、登录验证、任务租约和重试规则继续生效。
