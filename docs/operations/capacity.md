# 容量与扩容

正式部署使用 MySQL 和 Redis，可与应用一起部署，也可连接远程服务。任务、账号、队列及账单存储在 MySQL，Redis 用于实时进度缓存；文件存储在实例本地目录或配置的 OSS。

## 并发模型

Web 服务负责页面、接口与调度，下载工作进程持有独立任务和租约。浏览器解析、传输、合并、账号会话和数据库连接分别受限，配置进程数不等于同时传输数，也不代表源站允许的额度。

账号池的进程上限可设置 0，表示不施加该配置上限；实际仍受账号容量、执行器边界、数据库预算和资源保护限制。普通自动模式与账号池模式的区别见 [自动吞吐](throughput.md)、[账号池](cookie-pool.md)。

## 大清单与数据库

TXT / CSV 导入采用分块事务和断点记录，不一次性把全部视频载入内存。任务、文件及账单明细采用索引和分页；先用小批量确认账号、出口、保存目录及要求，再导入大清单。

数据库和媒体目录应使用可靠存储，并保留合并、缓存和临时文件余量。共库实例需合计连接预算；MySQL 5.7 在高并发领取中更容易产生锁等待，调整前先区分连接耗尽、行锁、磁盘 I/O 和下载渠道等待。连接配置及迁移见 [MySQL](../deployment/mysql.md)，日常限制见 [数据库预算](database-budget.md)、[资源保护](resources.md)。

## 多实例扩容

每台机器都提供管理页面并可参与下载，共享同一 MySQL 和 Redis，使用独立实例身份、状态目录和文件目录。无需单独部署 manager 角色；只作管理的实例保持暂停领取即可。

同一个任务可由多个实例执行，数据库协调租约、归属和全局限制。不要复制或共用状态卷来增加实例。部署与升级见 [多实例](../deployment/instances.md)。

## 容量验证

连接测试通过、单次下载成功或短时模拟完成均不能证明长期承载能力。观察成功交付字节、失败率、冷却、CPU / 内存、I/O 压力和数据库等待，分阶段增加负载。

隔离模拟方法见 [容量测试](../development/capacity-testing.md)。MySQL 集成测试使用测试专用管理员连接创建随机测试库，不使用生产账号和业务库。最近服务器检查保存在 [发布与检查记录](../archive/README.md)，只代表该次采样窗口。
