# 账号池与资源调度

下载执行链：任务中心生成交付任务 → 下载进程检查开工条件并领取视频 → 准备工作目录 → 账号池分配账号 → yt-dlp 解析 → 按视频计划检查并预留空间 → 顺序获取缺少的资源 → 独立本地处理队列 → 发布与核对缺项。

首次空间检查同时核对磁盘最低保留空间和本视频的临时额度。空间不足时，持有该视频的进程显示“等待磁盘空间”，复查后继续同一视频。预留成功后启动写入监控，本地处理进程接手时按处理计划检查所需空间。

已算出空间计划的下载在等待中只复查磁盘。可以重新申请预留时，原进程按当前账号会话刷新来源并继续同一视频。媒体轨道优先于封面和字幕获取。自动降低下载进程上限启用时，持续至少一分钟的本地处理积压达到临时总预算的四分之一（最低 2 GiB），按资源保护节奏减少新下载，为已下载文件留出周转空间。

## 唯一任务上限

实例设置 `download_task_limit` 为本机下载任务上限，0 表示自动。实际进程数取账号会话容量、配置上限、静态内存容量和部署数据库连接容量的最小值；CPU、可用内存和当前实例的 I/O 压力进一步控制新任务数。账号池已知容量为零时不领取新任务。

不再设置下载器顺序、全局媒体连接预算、独立解析额度或独立传输额度。已准入任务可以在资源保护降低上限后完成，空闲进程在下次领取前退出。后处理使用 `postprocess_limit` 的独立进程池，不占账号下载名额。

每个网络任务持有账号许可与任务租约。解析和所有文件传输阶段校验所有者及账号冷却；转移所有权的旧进程不能继续交付。许可持有期间不占数据库连接，数据库事务内不等待网络、浏览器或磁盘。

短请求阶段不再反复写入、删除 SQL 传输许可，也不争用请求路由写锁；活动记录保存在 Redis，到期清理，正常结束主动删除。Redis 不可用时暂缓新请求并重试。账号分配、启动预算、冷却与任务租约仍以数据库为准；这些任务级操作需要持久化，不以临时活动记录替代。解析真正开始时提交启动预算消费，避免等待或取消任务错误地消耗、退回账号请求次数。

单文件分片数独立取 `fragment_concurrency`，不会因为更多账号运行而被整除。内存容量预估按每下载进程 160 MiB 基础开销加每分片 10 MiB 缓冲计算，并保留主服务空间。

## 冷却与恢复

可归属的 429、账号限流及连续不同视频的媒体 403 只保护对应账号；登录失效或验证只暂停该账号，重新检测通过后恢复。不存在历史全池人工拦截。

同一分钟三个不同任务返回源站 5xx 时，短暂保护来源服务；单条任务重复反馈不会累计成三次，账号限流、内容权限、代理和本地资源错误不会误判为来源整体故障。其他失败按任务有界退避处理。

吞吐显示网卡接收、实际媒体接收和已交付文件产出速度。数据口径不同，短时不必相等；源站供给、账号间隔和磁盘保护可能令带宽低于线路上限。
