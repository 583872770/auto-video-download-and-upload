# 下载并发与吞吐

下载只使用 yt-dlp，账号由实例账号池分配。字幕、视频、音频、封面和视频信息使用同一条任务执行链。

## 页面配置

- 账号管理：配置参与下载的账号、每账号并发、任务启动间隔、结束后休息、小时与每日启动预算。
- 系统设置 → 并发与资源：`download_task_limit` 控制本机下载任务上限，0 表示自动；`fragment_concurrency` 控制单文件分片上限，不随任务数平均分摊。
- 同页“自动降低下载进程上限”（`download_auto_reduce`）默认开启；关闭后停止按 CPU、可用内存和 I/O 压力动态缩容，并在下次采样恢复常规上限。账号容量、静态内存预估、数据库连接与磁盘空间限制仍生效。
- 系统设置 → 下载策略：`youtube_sleep_preset` 控制 yt-dlp 请求等待，不替代账号任务启动间隔。
- `postprocess_limit` 控制独立本地处理队列。下载完成后释放账号，不在账号下载名额内等待转换和文件交付。

## 资源保护

实际下载进程数由账号容量、任务上限、静态内存预估及数据库连接容量共同决定；开启自动降低上限时，CPU、可用内存和实例 I/O 压力进一步控制新任务。已准入任务在资源保护降低上限后可以完成。

不再提供媒体总连接预算、独立解析额度、独立传输额度和下载浏览器额度。数据库连接用于数据库读写，与媒体下载连接不同，详见 [数据库连接容量](database-budget.md)。

## 冷却与观察

明确限流、429 和符合条件的连续媒体 403 保护对应账号，其他健康账号继续。来源服务短时间连续对多个不同任务返回 5xx 时，暂停来源新请求；普通网络故障仍按任务重试。

观察带宽时同时记录公网网卡接收速度、任务实际媒体接收和已交付文件产出速度。这三者口径不同，不能将瞬时文件进度速度直接视为公网带宽。404 等内容错误不会通过增加并发解决。

1 Gbps 线路能否持续跑满还取决于源站供给、账号可用数、请求等待、磁盘写入和本地处理速度；应结合工作台等待原因与服务器采样判断瓶颈。
