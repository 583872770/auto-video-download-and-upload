# 页面管理数据库连接预算

系统设置 → 并发与性能 → 数据库连接预算，按所选实例独立保存，可通过任一实例的前端切换后管理。

- **自动核算（默认）**：按目标下载进程数计算连接预留。Cookie 池使用“Cookie 池下载进程上限”，普通自定义模式使用“实例并发上限”，普通自动调节模式另外计入有界准备进程。
- **手动指定**：保存固定连接预算，默认输入值 64。低于目标需求时仍可保存，并明确显示最多支持的进程数；不足以容纳主服务、辅助进程及一个下载进程时拒绝保存。
- 页面显示的是连接预算，不是当前已建立连接数。它不修改各进程的连接池大小，也不修改 MySQL 的 max_connections。

Cookie 池下载进程上限设为 0 时，该项不限制进程数；自动连接预算按选中的 Cookie 数量乘以每会话配置并发估算需求，最多 64 个进程。实际准入仍核验账号去重、可用容量、渠道、内存和数据库部署硬上限。其他零值语义见 [账号池与节奏](cookie-pool.md)。

默认主服务池为 5 + 2，辅助预留为 4，每下载进程为 2。目标 21 个进程时需要 21 × 2 + 11 = 53 个连接。手动预算 48 时仅支持 18 个进程。

页面保存后，后续调度和新任务采用新预算，无需重建连接池或重启应用。降低额度不终止已有任务，多余进程完成任务后退出。配置哈希包含预算方式和数值，不沿用旧配置的进程采样。账号、渠道、本机媒体连接、内存和资源压力保护仍独立生效。

工作台展示进程目标、常规上限、当前动态上限及实际占用，并列出账号、配置、渠道与连接、内存、数据库五项计算依据。数据库信息展示目标所需预算、有效预算、最多支持的下载进程和部署硬上限。

## 与旧环境变量的关系

未显式设置旧预算环境变量时，运行调度不再套用隐含的 48 个连接默认上限。显式设置的以下变量仍作为部署硬上限，并在页面显示：

- VIDEO_DB_CONNECTION_BUDGET：实例总连接预算硬上限。
- VIDEO_WORKER_DB_CONNECTION_BUDGET：下载进程连接预算硬上限。

两套主应用 Compose 均不再默认注入 `VIDEO_WORKER_DB_CONNECTION_BUDGET=48`，因此自动预算可以随目标进程数增长。已部署容器需要移除此变量并重新创建才能解除旧限制；单独删除 `.env` 中的值不会改变现有容器。旧的按账号独立容器模板已移除，当前部署方式见 [部署手册](../deployment/docker.md)。

例如自动计算需要 53，但显式部署硬上限为 48，实际仍只支持 18 个进程。需要调整部署环境并重新创建应用容器；页面不会静默覆盖该限制。主服务池、下载子进程池和辅助预留的环境变量继续参与公式。引擎初始化及旧的无配置调用保留原部署预算校验。

## 多实例边界

预算及运行计算由目标实例执行；管理入口不使用自己的环境变量替远端计算。远端未升级或采样过期时，页面显示信息待更新，不猜测其预算。

本阶段只管理每实例预算，没有实施全局自动分配或自动修改 MySQL 上限。共用数据库的实例必须合计预算，并为管理、维护和其他应用预留容量。后续集群分配需要统一登记、事务分配及离线实例回收规则，不能只按 MySQL 瞬时空闲连接发放额度。

## 验证

单元及接口测试覆盖自动公式、自定义连接池、两种显式部署上限、预算降低与恢复、无效保存不落盘、多实例切换隔离及配置快照失效。

运行 scripts/verify_database_budget.py 可在临时 SQLite 库和 Chromium 中验证自动/手动切换、保存和重载、错误保留草稿、工作台限制说明与窄屏布局，不访问真实账号或生产数据库。
