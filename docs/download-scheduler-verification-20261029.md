# 下载调度优化部署与验证记录

2026-10-29 已将优化代码部署到现有 Docker 服务，保留当前画质、下载方式顺序、代理选择与测试下载模式。吞吐优化版本为 `youtube-downloader-app:throughput-20261029-r4`，镜像标识前缀 `sha256:d523d247db26`；随后任务状态修复更新至 `youtube-downloader-app:throughput-20261029-r5`，吞吐逻辑沿用 r4。原有两个暂停实例继续保持暂停。

## 已生效的行为

- 解析与传输分开取得额度；Bergung 通过本机解析池复用浏览器，提前准备少量待下载文件。
- 按上游而非渠道名称分配带宽容量。同一后台的多个入口共用限制；只有确认独立的后台才能设置独立组。兼容渠道之间可以给不同视频分流，下载方式之间继续按原顺序回退。
- 依据媒体接收、校验成品吞吐与 CPU、内存、I/O 压力逐步调整容量；增加并发没有收益就退回。网页解析失败不会直接减少媒体上游额度，HTTP 限流按实际发生阶段退避。
- 共享 MySQL 协调已升级实例的上游许可，本机解析池、状态、磁盘与资源控制仍各自独立。任务租约、停止、媒体校验、磁盘预留和幂等统计继续生效。
- 主服务数据库连接池为 5+2；下载子进程默认 2+0，自动模式另设下载进程总连接预算 48。等待解析、上游或网络时不持有数据库事务。

当前配置是自动吞吐、传输上限 16、浏览器上限 3、媒体连接预算 32、带宽目标 0。上限不等于实际并发；控制器会根据本机情况缩减或探索。

## 代码与数据库验证

完整 Linux 容器回归共 134 项，133 项通过、1 项跳过，包含真实 Chromium 跨请求复用和代理冷启动检查。最后的失败归因修正又验证 72 项，69 项通过、3 项跳过。测试使用隔离网络与资源限制，没有向生产队列添加测试视频。

最终容器内逐文件核对 72 个发布文件的 SHA-256，全部一致。发布前后使用真实 MySQL 进行事务内检查，验证整型聚合返回 Decimal 的兼容处理、共享入口额度、独立组和原子准入；事务回滚后没有遗留测试任务。可选的独立 MySQL 合约套件因未提供测试管理员连接而跳过，未把生产库当作测试库使用。

## 发布期间问题与恢复

首次发布出现 MySQL 整型求和返回 Decimal 与浮点评分混用的兼容错误，导致 1221 个任务在解析前被错误标记失败。发现后暂停执行，修正类型转换，并将这 1221 个任务恢复队列、退还对应尝试次数，纠正任务、下载方式、实例及相关代理失败计数。原始记录已在服务器私密发布目录备份；复核没有未恢复的同类失败。

最终更新先暂停新领取，在途任务全部完成后再替换容器；更新后通过健康检查和真实数据库准入检查，再恢复原运行意愿。

## 现场观察口径

最终版本按每 5 秒采样、连续 10 分钟观察。使用完成任务记录中的校验文件字节计算有效吞吐；另记录网卡接收、媒体接收、CPU、内存、I/O 压力和数据库连接。当前是测试下载模式，文件经过真实传输和校验后自动删除，不计作正式交付或上传成果。

观察窗口为北京时间 **12:44:48～12:54:48**，121 次采样、实际 600.09 秒：

| 指标 | 观察结果 |
|---|---|
| 完成任务 | 成功 23 个，其中 Bergung 21 个、yt5s 2 个 |
| 校验成功文件 | 4,870,575,959 字节，约 4.87 GB |
| 完成文件有效吞吐 | 平均 64.93 Mbps，约 8.12 MB/s |
| 网卡接收 | 平均 71.81 Mbps；最高 5 秒区间平均 222.70 Mbps |
| 最终失败任务 | 1 个，已达到 3 次尝试上限，错误记录包含超时及 SSL EOF；窗口内已结束任务失败占比 1/24，约 4.2% |
| 已结束渠道尝试 | 本地计数记录 23 次成功、9 次失败；同一视频的多个回退失败会重复计入渠道尝试，不等于 9 个失败视频 |
| 媒体 HTTP 429/503 | `upstream_failed` 计数增量为 0 |

| 内存 | 可用内存最低约 3210 MiB；容器内存最高约 2640 MiB；没有 OOM 事件 |

| 磁盘剩余空间 | 最低约 32.81 GiB |

CPU 压力出现后，浏览器从 2 减为 1；上游传输额度先降为 1，资源恢复后逐步试增至 2、3。窗口结束仍有 5 个任务在途，不能提前把它们计为成功。最后采样同时存在浏览器等待和验证等待，解析供给与网站转换、出口稳定性仍值得继续观察；尚不能认定纯下载带宽是唯一瓶颈。

更新后容器保持健康、未重启，当前实例运行意愿正常，另外两个实例仍暂停。检查没有新调度启动异常、数据库连接池异常或未恢复的 Decimal 兼容性失败。

这是正常队列的现场观察，没有固定视频样本的同条件前后对照，不能据此宣布提速百分比或已持续跑满服务器公网带宽。网卡协商速度也不代表已核实的公网套餐速率。

## 后续使用边界

新增 Bergung 兼容渠道仍需真实网站/API 地址，以及验证网页流程、画质和后台限额。默认将未确认的媒体后台归为共享组，避免仅换域名便虚增容量。其他网站前端需编写适配器。

普通 MP4/WebM 没有启用尚未验证的 Range 并行，也没有跨渠道拼接。媒体 HTTP 会话不承诺跨任务复用；目前明确复用的是 Bergung 解析浏览器。带宽目标用于停止扩张，不是严格的字节限速器。

多台服务器共用同一上游/账号/出口时，总能力仍受共享限额约束。已升级实例必须使用一致的资源组；每台保持独立状态卷，同机多容器应分配明确的 cgroup 资源。

配置与实现见 [下载调度的使用与实现](download-scheduler.md)，完整设计及后续能力见 [多上游设计](multi-upstream-download-scheduler-design.md)。服务器保留原始基线回滚镜像、上一稳定版本镜像、Compose 和私密配置备份。

## 后续任务状态修复（r5）

现场确认任务中心仍使用旧的共享 `released` 字段判断暂停，而按实例启动的工作台不会修改该字段，造成实际有视频运行却显示“暂停中”。r5 按实际选择此任务的实例汇总运行意愿，列表和详情共用同一读模型；工作台保留当前实例的局部状态。离线、停止标记和磁盘等待也按本任务实际分配的实例判断，其他任务的在线实例不会掩盖等待原因。旧版全局控制仍兼容，未通过修改共享开关或视频记录修补显示。

相关 Linux 隔离回归共 78 项，77 项通过、1 项因未配置独立 MySQL 测试管理员连接而跳过。真实浏览器使用临时多实例数据库验证列表、详情、自动刷新、暂停排空、多实例共同执行和完成状态；没有向生产队列添加测试任务。另以只读事务在真实 MySQL 上检查新读模型，75 个发布文件的 SHA-256 全部一致。

更新先仅暂停当前实例新领取，等待其在途任务全部结束，再替换 Docker 容器、验证健康并恢复原运行意愿。两个原暂停实例保持原状态。维护备份、r4 回滚 Compose 和镜像、r5 验证结果保留在服务器私密发布目录。本次仅修复状态读模型，未重复进行吞吐基准测试；上文的 10 分钟性能数据对应 r4。
