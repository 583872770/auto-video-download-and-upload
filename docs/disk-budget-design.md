# 长期运行磁盘容量控制设计

状态：核心控制已实现；使用与实际边界见 [DISK_MANAGEMENT.md](../DISK_MANAGEMENT.md)。范围：下载实例本机的临时文件、缓存和技术日志；兼容 Windows、Linux、Docker、多实例及测试模式。本文记录设计目标，验收项不代表全部已做真实部署验证。

当前实现说明：

- 扩展预留失败时退出申请扩容的当前执行并清理，不进行跨执行“最接近完成优先”的全局抢占排序。
- 实际目录是 `test-downloads/<task_id>/<attempt_id>`、`runtime/browser-profiles`、`runtime/uploads`、`runtime/cache`、`logs` 和 `imports`；诊断目录兼容原 `yt5s`。
- 使用本机 SQLite、进程身份和目录锁协调；元数据页数约 128 MiB、等待记录 10000 条上限。业务统计仍保存在原数据库。
- 页面展示状态目录所在文件系统、分类实际用量、预留和等待记录、清理失败及待确认结果；素材在其他盘时运行中独立检查剩余空间。跨文件系统完整仪表、清理预览、数据库增长预测和冷归档留待后续。
- 默认约 5 秒扫描、每秒运行检查、30 秒后台清理；完整结果恢复优先处理有完成凭据且能核对的单视频任务。模糊结果保留，不自动补造成功。
- 硬配额需部署者配置；没有自动修改宿主机挂载或数据库保留策略。测试范围和限制见使用说明。

## 1. 目标与边界

让服务可以长期运行，磁盘压力出现时自动清理或停止新增写入，并保留累计统计、任务意愿、交付依据与计费数据。

- 测试成功必须按完整成品登记实际字节，不能通过少下载、提前截断或删除账本维持容量。
- 清理临时文件和技术日志不删除任务、执行结果、下载器统计、测试大小、客户交付、单价、预计费用或去重记录。
- 空间不足属于实例运行条件，不记作视频下载失败，不增加下载器失败数，不消耗视频重试次数。
- 每个实例单独配置、计算和执行清理；共享 MySQL 不意味着共享本机磁盘配额。
- 正式视频不自动删除。正式素材持续增长时，在容量不足前停止本机领取，等待交付搬迁、人工清理或扩容。

“无限运行、无限保留全部历史明细、固定总磁盘空间”不能同时保证。第一阶段限制可丢弃文件并保护数据库；历史明细与数据库容量见第 9 节。

## 2. 改造前代码依据

- `Utils/download_storage.py`：测试视频写入状态目录 `test-downloads/<task_id>`，`cleanup()` 删除整个任务目录。
- `web_worker.py`：正常执行退出通过 `finally` 清理；强制停止、`os._exit()` 或断电可能跳过清理。
- `webapp/statistics.py:record_file`：完整成品的大小先写入数据库，再清理文件；已有幂等登记逻辑，应保持。
- `webapp/maintenance.py`：现有日志默认长期保留，单条大小仅在任务结束后截断；没有日志总量控制。
- `webapp/yt5s_browser.py`：浏览器配置放系统临时目录，正常关闭会清理，不能覆盖强制退出。
- `webapp/bulk.py`：导入完成后保留原始 TXT/CSV；导入结果和检查点已在数据库中。
- 当前 `min_free_gb` 主要在领取后、执行前检查，不能限制多个执行同时写盘的总量，也不能保护所有临时目录。
- Compose 已对容器标准输出设置 10 MB × 3 份轮转；任务日志另需控制。

## 3. 推荐初始配置

新增“实例与环境 → 磁盘容量管理”，以下值作为 10 并发测试的初始建议，均可调整。配置以对应 GiB/MiB 整数保存，运行核算统一换算为字节，避免 GB 与 GiB 混用。

| 项目 | 建议值 | 到达限制时的行为 |
|---|---:|---|
| 可丢弃运行文件总预算 | 20 GiB | 停止准入，清理过期文件，必要时释放未完成执行的空间 |
| 测试下载及合并文件子预算 | 16 GiB | 自适应减少实际并发；已有成品登记完成后删除 |
| yt5s 浏览器临时文件子预算 | 1 GiB | 回收空闲浏览器；运行中超预算则终止该解析并稍后重新执行 |
| 全部技术日志子预算 | 512 MiB | 优先删除最旧已结束日志，运行日志按单条限额轮转 |
| 单条技术日志 | 2 MiB | 写入时持续轮转，记录“更早日志已清理” |
| 成功任务日志保留 | 24 小时 | 过期自动删除；总量限制可更早淘汰 |
| 失败任务日志保留 | 7 天 | 在日志预算内优先保留，仍接受总量限制 |
| 导入原文件和上传临时文件子预算 | 1 GiB | 拒绝或等待新上传，不删除仍可恢复的导入 |
| 单次清单上传上限 | 256 MiB | 上传过程中限制大小，返回明确说明 |
| 浏览器诊断与其他可丢弃缓存子预算 | 256 MiB | 轮转或删除最旧文件 |
| 文件系统剩余空间低水位 | 10 GiB | 自动进入磁盘等待并启动清理 |
| 文件系统剩余空间恢复水位 | 15 GiB | 清理后条件满足，自动解除磁盘等待 |
| 正常检查周期 | 5 秒 | 接近限制时提高到约 1 秒；定期后台校准目录用量 |

子预算之和小于总预算，差额保留给扫描误差、轮转、合并及临时开销。剩余空间水位是整块文件系统的保护，和应用文件预算分别判断；不能简单把两者相加作为占用上限。

20 GiB 只是可丢弃运行文件预算，不包含正式素材、配置、数据库、依赖、Docker 镜像或其他程序的数据。磁盘容量不足时应降低上述预算；不得承诺所有机器均适合此默认值。

## 4. 下载准入和运行中控制

### 4.1 先预留空间，再执行

增加进程间共享的磁盘预算服务。同一状态目录使用一个本机预算协调器和进程锁，不能让 10 个进程分别看到相同空闲空间后同时开跑。

每个执行有独立编号、所属实例、任务编号、进程身份和空间预留。已知大小时预留下载所需字节，并在 FFmpeg 合并前额外预留输出文件空间；下载与输出临时同时存在时，按峰值计算。

预留与实际占用不能重复相加：准入判断使用“已分配字节 + 各执行尚未用掉的预留 + 安全余量”，同时校验类别预算和总预算。日志、上传、浏览器也走同一个预算服务。目录大小通过增量跟踪和后台分批扫描校准，不在每秒检查中递归遍历全部历史文件。

预留记录带执行编号、进程身份和心跳并持久化；重启时先按目录实际占用与活跃执行重建，再开放准入。进程失联只标记待核对，确认无主并完成清理后才释放对应预留，避免占用被漏算；目录已删除而预留残留也应在核对后解除。

大小未知时先预留保守额度，例如每次 1 GiB，随实际大小和进度扩展预留。大小估计不能作为成功统计依据。目录测量包含分片、音视频轨道、元数据与合并输出，不仅计算最终 MP4。

无法获得预留时，等待执行机会；设置 10 并发代表最多 10 个，容量不足时实际可降到更少。极大的单个视频超出整个可用预算时，显示“需要增加磁盘预算”，避免无限重试。

### 4.2 防止全部执行持有部分空间互相等待

扩展预留失败时先暂停准入和回收可清理文件。仍不能继续时，按确定规则退出少量尚未完成的执行，例如优先释放最近开始、下载量较小的执行。

终止其 FFmpeg/浏览器等子进程，确认退出后再清理该执行目录、释放预留，让其他执行完成。不允许所有任务拿着部分空间一直等待，也不允许删除仍在写入的文件。

此情况记为实例容量等待或资源中断，不是视频/下载器失败。重新排队不消耗普通下载重试次数；同一预算下不可完成的视频需要明确标记并等待配置变化，不能不断重下。

资源中断时保存已知最低需求与预算版本；再次准入必须能满足更新后的需求，而非再次使用最初 1 GiB 的未知大小预留。需求仍未知时设置独立的资源重试退避和次数保护；反复中断后等待人工调整预算，其他可运行视频继续。该保护计数不进入下载器失败或普通重试统计。

释放空间优先供已经开始且最接近完成的执行使用，再按等待时间接纳新执行；被资源取消的执行进入冷却，不能立即抢回预留。建议同一预算版本下最多允许 3 次未知大小资源中断，此后只在预算提高、可用空间明显增加或人工重试时重新评估，不依靠定时器无限重下。

### 4.3 软件控制与硬限制

预留、写入检查和监控提供日常容量控制，但目录轮询存在检查间隔，FFmpeg 与浏览器也可能突发写入。不能声称“每 5 秒扫描一次”就能保证绝对不超限。

需要严格字节上限的 Linux/Docker 部署，应把受控文件放在启用配额的文件系统或固定容量独立分区/逻辑卷上。Docker 普通命名卷本身没有通用的容量参数，应由宿主机配置并验证配额。

配额覆盖浏览器配置、HTTP 上传临时文件及所有下载中间文件；业务配置和数据库放在保护范围外。命中硬配额的 ENOSPC/EDQUOT 必须分类为资源不足，不能继续切换下载器重试。实际部署以分配字节和文件系统剩余空间校验，不能只看文件逻辑长度。

Windows 首期提供软件控制与剩余空间保护，页面明确显示“软件限制”；若需要硬限制，使用经过验证的独立存储卷方案。

## 5. 临时目录和异常残留

### 5.1 统一受控目录

建议在状态目录内建立 `runtime/`，分别容纳 `test-downloads`、`browser-profiles`、`uploads`、`diagnostics` 等子目录。正式素材继续沿用素材目录；新旧目录都纳入用量展示。

下载执行、浏览器配置、yt-dlp 缓存、Cookie 工作副本、网页诊断和上传框架的临时文件均显式指向受控目录。浏览器缓存参数仅作为优化，不能充当硬配额。

部署迁移不移动正在运行的目录，新执行使用新布局，旧布局只对确认不再使用的目录清理。不得直接改变 Python 全局临时目录后假定所有库都会遵循；需要逐项验证，包括上传解析可能提前产生的临时文件。

### 5.2 执行隔离与清理条件

新测试目录采用 `test-downloads/<task_id>/<attempt_id>/`，避免旧执行残留和接管后的新执行共用同一目录。为每次执行登记进程创建时间和独立执行锁，任务登记同时核对原有实例租约，防止 PID 重用误判。

启动时恢复清理，运行中定期扫描。仅在以下条件全部满足时删除：

1. 路径位于明确允许的临时根目录，编号和清单合法，且不是符号链接或目录联接。
2. 当前实例/执行不持有该目录锁，没有仍在写入的子进程。
3. 没有有效运行租约，或执行已经完成；数据库不可用、身份不明时不删除不确定目录。
4. 正常完成立即清理；异常残留经过短暂宽限，例如 5 分钟，再次确认身份后清理。不能只根据文件修改时间删除长视频。

删除失败记录原因和占用大小，后续退避重试。清理器即使下载暂停或队列为空也继续运行，由每实例独立维护服务持有锁，避免依赖下载进程是否存活。

身份复核至删除完成期间，清理器持续持有目录独占锁，并在删除前复核租约与执行状态。接管必须创建新的执行编号和目录，不能重新启用已交给清理器的旧目录；旧执行的登记权限由数据库租约和实例启动编号隔离。锁获取失败立即跳过，不能只做一次“锁可用”探测后释放锁再删除。

## 6. 统计和日志保护

顺序保持为：完整下载与必要校验完成 → 幂等提交实际大小和统计 → 删除测试文件 → 登记清理结果。

为覆盖“成品已完成、统计提交前崩溃”，在提交前持久化小型完成凭据，记录执行编号、幂等标识、校验结果、文件位置和实际大小，并预留其写入空间。发现此类无主目录时先进入结果恢复队列，不能直接按垃圾删除。恢复服务取得恢复权限，核对任务仍允许完成、文件完整性、原执行身份及账本；已提交则仅清理，满足业务规则的未提交结果通过专用幂等恢复事务登记。已取消或失效执行不补造成功记录，按取消规则处理；不能确定时保留并告警，停止扩大占用。此恢复通道必须扩展现有仅允许运行所有者登记的逻辑，不能绕过租约检查。

- 未完成文件被容量管理取消时，不新增测试成功数或测试成功字节。
- 已提交统计但删除失败时，统计不回滚；标记清理待重试，不能为了重新清理而重新登记或重新下载。
- 数据库提交未确认时，通过原有幂等键核对，区分“结果未登记”和“仅文件未清理”；不能因文件存在就推断成功。
- 取消、配额错误、下载器失败、清理失败分别保存，不让资源不足污染成功率。是否启动过下载器以及资源中断需要独立结果字段；不能简单复用现有 `failed` 统计分支。
- 删除日志只影响技术排障文本。任务的时间、状态、简短错误原因、下载器、大小、统计、交付和费用继续由数据库展示。

日志使用限额写入通道承接 Python 和子进程输出，不能只在结束时处理。当前 `dup2` 和 FFmpeg 直接写文件的路径需要一起改造。丢弃过旧内容时仍必须持续排空子进程输出，防止管道阻塞下载。

日志总预算包含运行中日志和最坏轮转开销。先淘汰最旧已结束日志；极端情况下缩短运行日志保留尾部。页面读取用日志代次和偏移处理轮转，防止刷新后重复或漏读；数据库里的简短错误摘要不随日志淘汰。

## 7. 导入原文件与缓存

导入原文件在最终检查点、计数及有效视频入库成功后可删除，保留原文件名、大小、摘要、结果和无效样本。取消的导入确认进程已退出后可删除；等待恢复和仍在导入的源文件保留。

已完成导入不再提供原文件重新下载；视频 ID 导出继续使用数据库，原始 CSV 中未入库的其他列不承诺保留。界面明确这一变化。

上传期间按实例总预算预留并流式限额，包含框架临时文件，避免请求尚未进入业务处理就写满磁盘。新增上传的容量错误不创建残缺任务；已导入视频和统计不受影响。

诊断截图、网站响应样本和浏览器缓存均设置字节与时间上限。Cookie 原件、登录凭据、会话密钥、部署文件和代理配置不进入通用缓存淘汰名单；这些文件单独限制上传大小。

## 8. 磁盘等待和界面

新增实例资源状态 `disk_wait`，和用户主动暂停分开，保存原因、触发时间、用量及最近清理结果。磁盘等待不改变系统领取开关、客户任务运行意愿，也不阻塞其他健康实例。

低于 10 GiB 或预算不足时停止本机新准入；已有执行只有在预留和剩余空间允许时继续，否则有序退出并清理。达到恢复水位且至少能接纳一个执行时，才解除资源等待；用户手动暂停的实例仍保持暂停。

页面展示：

- 本机文件系统容量和剩余量；状态、临时目录和素材位于不同文件系统时分别显示。
- 各类用量、预算、预留量、活跃执行占用、可清理残留与清理失败量。
- 配置并发与实际并发，例如“设置 10，当前 6；磁盘预算限制”。
- 日志保留范围、最近释放空间、待处理文件，以及纯预览的清理清单。
- “立即清理可丢弃文件”只处理满足条件的内容；正式素材仍走现有确认流程。

## 9. 数据库和宿主机容量

MySQL 的任务明细、账本、索引和 binlog 不在本机缓存配额内。远程 MySQL 占用远端磁盘；同机部署则仍会占用同机磁盘。

第一阶段不自动删除数据库业务记录，配置容量告警、增长率与剩余可用天数监测。MySQL binlog 到期策略由数据库管理员依据备份、恢复和复制需求设置；不能由应用随意删除数据库文件。既有进度写入每约 1.5 秒更新一次，可独立评估降低频率，但终态和交付登记不能丢失。

若要求数据库也严格有上限，有两个选项：

1. 保留全部历史明细：达到数据库容量阈值停止导入和新执行，等待扩容或迁移。
2. 后续建设可核对的冷归档：将旧明细迁到独立存储，在线保留累计统计与幂等依据，并改造历史查询和导出。外部归档容量也需要规划；不能只删明细后宣称所有功能完全不变。

Docker 镜像、构建缓存、宿主机日志与开发环境 `.tools`、本地测试数据库由运维单独管理。应用清理器不自动删除这些未知归属内容。容器桌面日志也需轮转。Docker Desktop 的虚拟磁盘文件可能在内部文件删除后仍保持原体积，需区分容器内可用空间与宿主机虚拟磁盘大小。

## 10. 实施顺序

1. 容量统计和只读页面；引入每实例配置、资源状态与文件归属记录。
2. 改造日志为写入时限额，增加总量和期限；完成导入原文件清理。
3. 改造执行目录、浏览器临时目录与持续残留回收；覆盖正常、异常和重启场景。
4. 增加原子预算预留、运行中扩容、合并预留和磁盘等待；接入进程停止、任务领取、统计分类与多实例调度。
5. Docker 部署提供专用目录及可选宿主机硬配额步骤；独立验证不同文件系统与满盘行为。

建议上述控制作为同一轮完整改造交付。只增加定时删除，不能解决活跃的 10 个下载同时写满磁盘。

## 11. 验收条件

- 10 并发、混合大小及未知大小测试持续运行，应用占用达到稳定范围；测试后核对统计与完整成品实际大小一致。
- 强制结束下载进程、FFmpeg、浏览器或整个容器后，重启能回收确认无主的目录；有效运行和超长视频不被误删。
- 单视频超过预算、多个执行争抢扩容、合并峰值、上传与下载同时写盘时，不出现所有执行永久等待或无限重下。
- 硬配额测试验证写入上限；软件模式测量最大瞬时超额并明确记录，不能用轮询测试冒充硬上限保证。
- 对比清理前后任务计数、测试大小、下载器成功率、客户交付、预计费用及去重依据，业务数值保持一致；清理失败不会重复登记。
- 数据库提交成功但清理前崩溃、提交响应丢失、数据库不可用、目录被占用、系统时钟变化时，结果可恢复且不误删。
- 海量子进程输出时日志仍受控且不阻塞下载；轮转后前端日志读取正常。
- 空间恢复只解除磁盘等待，不自动恢复人工暂停实例，不启动从未开始的任务。
- 多实例各自控制本机空间；一个实例容量不足时其他实例继续处理。
- 数据库历史容量策略单独验证；不通过删除统计、账本和幂等记录实现所谓无限期有界运行。
