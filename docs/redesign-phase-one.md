# 第一阶段改造说明

本版围绕现有客户任务统一业务规则，继续保留 Flask、SQLAlchemy、MySQL 与现有下载进程。对应审查方案见 [项目审查](project-redesign-review.md)。

## 使用上的变化

- 客户任务是预计费用的唯一计算单位。全局、任务中心和旧统计入口使用同一汇总服务；每个任务按自己的单价、单位与累计交付字节计算，逐任务四舍五入到分再汇总。免费与待定单价分别展示。
- 执行会话只记录下载结果和成品大小；不再修改单价、显示会话金额或导出第二份账单。历史会话单价字段保存在数据库中以供迁移核对，不再参与当前商业统计。没有可靠客户任务归属的历史交付不补造费用。
- 客户、任务名称、备注、下载策略和单价统一在任务设置中修改。旧清单编辑 API 返回 410，引导到任务中心。旧会话更新仅允许执行备注。
- 任务设置携带 `edit_version`。并发编辑只接受一个版本；过期写入返回 409、缺少版本返回 428。页面保留输入，列出服务器最新资料，人工核对后才可继续保存。编辑版本、策略版本与清单失效代次相互独立。
- 首页按钮明确为“恢复系统领取”和“立即停止全部下载”。恢复不会开始新任务，也不会恢复暂停的实例。两个系统恢复接口共享控制服务，恢复仍检查停止中进程和素材清理；单机模式保留必要的本地环境与登录检查。
- 任务开始意愿与实际执行分开。系统暂停或没有可用实例时显示具体等待原因；Cookie、浏览器或工具问题暂停故障实例，健康实例继续。当前故障隔离粒度是整个实例，按下载器能力隔离留待后续。
- 任务列表批量读取摘要，详情独立加载。查询次数不随每页任务数增长，不再为列表的每一行加载运行视频与配置详情。

## 管理账户

未创建账户时，仅回环地址可直接访问工作台。远程浏览器被引导到 `/login`，不能读取业务 API。已有账户后，本机和远程管理页面都需要登录。

首次在 `/login` 输入初始设置码与管理员用户名、密码。设置码保存在当前管理实例状态目录的 `console-bootstrap.key`，页面显示实际路径。Docker 默认可在容器内读取 `/app/.cache/web/console-bootstrap.key`；它与 `/setup` 的部署访问码不同。

管理员可在 `/login` 的账户管理区新增账户、调整角色、停用账户或重设密码。密码使用 Werkzeug scrypt 哈希保存；账户更新使其已有登录会话失效，系统不允许停用或降级最后一个启用的管理员。

| 角色 | 权限 |
|---|---|
| 管理员 | 任务、运行控制、系统配置和账户管理 |
| 操作员 | 查看、创建及管理任务，执行系统停止和恢复，编辑执行备注 |
| 只读 | 查看任务、交付、日志和报表，不能修改或启动下载 |

账户保存在共享数据库中；不同管理实例的浏览器登录会话分别建立。节点令牌只允许实例资源与环境检查接口，不能操作客户任务和账户。首次通过反向代理公开服务前应完成管理员设置；直接请求来源以连接地址判断，不信任未经配置的转发头。HTTPS 部署可设置 `VIDEO_WEB_HTTPS=1` 启用安全会话 Cookie。

## 结构与升级

新增 `BillingService`、`ExecutionControlService`、`ConsoleAuth`，任务资料写入集中到 `Jobs.update`。

本版新增 `console_users`、`schema_migrations`；`job_profiles` 增加 `edit_version` 和 `policy_version`，旧资料默认从版本 1 开始。交付与测试表补充按视频条目查询的索引。迁移可重复执行，DDL 中断后依据实际结构继续，不回写历史客户或金额。

迁移仍由现有启动初始化触发，并使用现有 MySQL 升级锁。本版只是引入显式迁移记录；独立迁移命令、权限分离和全部历史结构迁移尚未完成。升级所有参与协作的实例前应备份 MySQL 与状态目录，避免旧版本绕过新业务约束。

CI 修正了缺失的验证脚本入口，提供 MySQL 8.4 测试服务，运行单元/集成测试与任务中心浏览器验证。MySQL 测试仅使用 `VIDEO_TEST_MYSQL_URL`，逐项创建并删除随机测试库，不使用应用连接。

## 恢复系统领取的反馈修复

恢复系统权限不会自动启用已暂停的实例，也不会开始尚未开始的客户任务。此前首页点击后没有立即刷新按钮，任务中心恢复成功也未显示返回消息，容易误以为按钮无效。

首页和任务中心现在立即显示“正在恢复…”，防止重复点击；请求等待超过 90 秒会说明结果尚未确认，并重新读取状态。恢复成功后即刻更新显示，暂停实例、无在线下载实例、任务尚未开始和没有待处理视频均提供持续提示与对应页面入口。单机模式原有环境与 Cookie 检查保留，两个恢复接口仍不改变客户任务意图及实例暂停状态。

新增只读 `/api/jobs/system/status`，系统状态接口和恢复响应也返回相同的执行条件说明。判断使用队列计数与实例心跳，不扫描待处理视频。

验证：相关回归 53 项，无失败，1 项跳过；任务中心完整浏览器验证通过；`scripts/verify_resume.py` 验证首页和任务中心的等待提示、恢复成功后实例仍暂停的说明及请求超时反馈。截图在 `.cache/validation/resume/`，回归日志为 `.cache/validation/resume-regression.log`。真实运行状态仅做只读查询，未替用户开启领取或恢复下载实例。

后续修复：“恢复下载实例”使用 `/#instances` 跳转，首页此前只处理导航按钮，缺少 `hashchange` 监听，导致首页内点击时仅改变地址而未切换内容。现已处理地址片段变化及浏览器前进、后退；实例恢复按钮增加检查中提示、超时反馈，并防止定时刷新替换等待中的按钮。恢复完成后重新读取实例和系统条件。浏览器验证已覆盖两个恢复入口的实际点击、实例检查失败后重试以及实例成功恢复后的状态更新。
