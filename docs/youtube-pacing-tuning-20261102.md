# YouTube 持续吞吐调优（2026-11-02）

目标是在同一账号近期被 YouTube 明确限流后，降低新的解析请求压力，同时允许已解析的文件继续并行传输。参数是本地观察起点，不代表 YouTube 官方安全额度，也不能保证免限流。

## 部署参数

| 项目 | 调优前 | 调优后 |
| --- | --- | --- |
| 工作进程 / 吞吐模式 | 64 / 自动 | 2 / 手动 |
| 原生传输 / 解析上限 | 默认 / 4 | 2 / 1，分开准入 |

| 本机 / 原生共享连接预算 | 默认 | 4 / 4 |
| 视频启动节奏 | 固定 3 秒 | 持久化渐进调速 |
| 正常初始 / 近期被限流后的间隔 | — | 60 / 120 秒起步 |
| 提速最小间隔 | — | 45 秒 |
| 滚动一小时 / 二十四小时预算 | 无 | 80 / 1200 次启动许可 |

保留原 Cookie、网络出口、画质、存储及字幕选择；保持 yt-dlp sleep 预设，关闭匿名重试。文件字节速度不额外限速。两个工作进程是上限，实际传输数取决于文件大小、启动间隔和源站响应。

## 调速与保护

- 当前实例与同核心 Cookie 会话各自记账，并同时通过准入；重导出的同核心凭据共用会话预算。不同会话并不证明不同 Google 账号或独立配额。
- 启动许可包括队列重试及字幕补下载；不是全部 HTTP 请求计数，yt-dlp 单次解析或传输内部仍可能请求多次。预算从启用后开始累计，不回填升级前的历史请求。
- 达到预算后保留任务等待，既不换身份重试，也不消耗下载失败次数。播放列表需先经导入展开成单视频队列，避免一个启动许可包含整张列表。
- 至少观察六小时且完成 100 个有有效文件大小的下载后，每两小时最多缩短五秒；跳过或零字节结果不加速，超时降低节奏。
- 明确账号限流停止实例领取任务，重复事件的冷却依次为一、二、四、六小时；尊重更长 Retry-After。同一事件的并发报告不重复翻倍；晚到的成功不能清除持久化冷却。
- 状态保存在现有数据库资源表，不新增 schema。启用时继承近期已记录的账号限流；切换模式后也会继承更新的旧调度器限流记录。
- 字幕补下载同样计入预算，识别账号限流文本并触发实例熔断；普通字幕 HTTP 429 在固定模式下保留原字幕通道退避行为。
