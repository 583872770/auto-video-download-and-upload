# 2026-11-08 运行优化实现与验证

本次落实一天运行检查中提出的进程预算、重复事务、等待分类及故障可回溯性优化。本文记录本地实现阶段的修改与验证；该阶段没有修改 `.env`、线上配置、容器或数据库。后续已于 2026-11-08 20:42:40（北京时间）发布到洛杉矶服务器，详见 [发布验收记录](runtime-tuning-deployment-20261108.md)。生产性能收益仍需在相近业务负载下比较，不能用本地测试代替线上测量。

## 1. 限制常驻下载进程

Cookie 池的账号会话容量与实际常驻进程数分开计算，不再将 18 个账号、每账号 2 个会话直接扩为 36 个常驻下载进程。

实际进程额度取以下约束的较小值：账号会话容量、渠道及媒体连接允许的传输容量加有限准备名额、配置的进程上限、内存估算和数据库连接预算。新增当前实例配置：

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `youtube_cookie_pool_worker_limit` | 20 | Cookie 池下载进程上限，页面可修改 |
| `youtube_cookie_pool_preparation_workers` | 4 | 有效传输容量以外的准备进程额度，页面可修改 |
| `VIDEO_DB_CONNECTION_BUDGET` | 48 | 当前实例主服务、辅助进程及下载进程的总连接预算 |
| `VIDEO_WORKER_DB_CONNECTION_BUDGET` | 48 | 下载进程连接预算，另受实例总预算约束 |
| `VIDEO_DB_AUXILIARY_CONNECTIONS` | 两个子进程池上限之和 | 为维护、字幕等两个辅助槽位预留连接 |

两个 `youtube_cookie_pool_*` 参数保存后用于后续调度；`VIDEO_*` 属于部署环境变量，修改后需重启相应实例才能生效。

默认主服务池为 5+2，子进程池为 2+0，因此默认数据库预算允许 `floor((48-7-4)/2)=18` 个下载进程。页面配置上限 20 仍可能实际只有 18 或更少。提高实例总预算前必须核对共享 MySQL 的可用连接，不能将每实例预算简单复制到 20 台服务器。

主服务显式连接池参数继续生效；下载子进程通过独立的 worker 参数配置自己的池，同时保留主服务参数以计算一致的总预算。降低额度时，多余进程完成当前任务后在下一次领取前退出；不终止正常下载。资源压力下每分钟最多收敛一次，减到原来的约 80%，健康后每分钟最多恢复一个，避免每 5 秒反弹。

## 2. 批量读取账号状态

- 一次读取池内成员，一次读取相关凭据归属；正常已绑定账号的读取不写归属表。
- 仅缓存有界的纯解析结果，仍从数据库读取成员和归属，删除、换 Cookie 和配置修改不会被授权缓存掩盖。
- 账号别名批量读取，只有首次缺失时才初始化；同名账号替换凭据后保留原有冷却及并发分组。
- 展示状态通过批量只读查询读取会话状态与有效租约使用量，不再取得全局路由写锁。
- 真正领取和准入仍保留事务、Cookie 归属检查、任务 owner、租约及实例启动代号检查。

本地 SQLite 回归中，初始化完成后的 20 成员池构造加状态快照共 5 次 SELECT，无路由写锁和写操作。MySQL 还需要数据库时钟查询；历史文件迁移检查也可能增加常数级读取。该结果不代表整个服务的 SQL 已降到每次 5 条。

## 3. 普通等待与真实失败分开

上游繁忙、调度退避、磁盘协调等本地资源等待不再写入 Cookie 失败历史或影响账号健康。任务显示等待原因和下次重试时间，正常等待不消耗视频尝试次数。403、429、认证和验证失败保留原有记录及恢复策略。

另修复兼容问题：明确选择“从不使用 Cookie”且未由账号池分配会话时，不再尝试恢复或读取选中的 Cookie 文件。

补充并发回归还复现了 Windows 临时目录创建/删除时的路径误判：原生解析可能保留 `\\?\` 前缀，或短暂返回 NTFS 的删除中目录名称。现在先规范等价的 DOS/UNC 前缀；仍不一致时最多重做 5 次完整检查，合计退避 15 ms。只有最终链接及目录范围检查全部通过才返回，稳定重定向、真实链接及父目录越界仍拒绝。Linux 路径不增加重试。针对性的实时目录竞争复现中，观察到 50 次路径拼写差异，修复后的检查没有误报。

重复的 16 进程并发回归另外捕获了 Windows 目录删除中的 `scandir` 访问拒绝。目录元数据读取对该 Windows 错误最多短暂重查 5 次；随后确认目录消失时清除本轮扫描的对应临时测量值。持续的 ACL/权限拒绝仍抛错，不能被当作 0 字节继续放行。路径误判、删除中重查、稳定重定向、越界及持续权限拒绝均有独立回归。

## 4. 明确原因、有限重试与持久汇总

错误展示区分已确认的 DRM-only、格式不可用、私密、已移除、地区限制和未收到数据块。仅有“部分格式被 DRM 跳过”不能证明全部媒体均受 DRM 限制；早先的格式警告不能覆盖最终 403、429 等错误。

“未收到数据块”按临时故障有限重试，退避从 60 秒开始翻倍，最多 300 秒，仍受任务尝试次数限制。池内任务重试固定到原 Cookie 和原实例，不通过换账号消耗其他会话；账号不可用、池被关闭或实例不匹配时给出明确提示。正常账号启动间隔及冷却仍优先执行。

日志新默认值为总预算 256 MiB、成功日志 6 小时、失败日志 7 天。已保存的旧预算和保留时长原样保留，升级不会把线上 64 MiB / 24 小时等配置自动改成新默认值。按过期、成功、未知、失败的顺序优先清理，活跃任务日志继续保护；预算或磁盘不足时仍可提前删除失败日志，并记录清理采样供页面查看。此处不增加媒体文件删除行为。

新增小表 `download_runtime_hours`，在已有任务最终结算事务内增量累计每实例、每小时的完成数、成功数、失败原因、跳过数、文件数量/字节和任务耗时；重试不作为最终失败重复统计。原任务所有权和结算幂等条件继续生效。没有扫描或回填大任务表，也不修改任务表结构。

汇总保留约 30 天，当前实例按小时清理自身过期桶。页面“系统设置 → 存储与清理 → 查看运行汇总”可查看近 1 / 7 / 30 天，读取遵守当前管理实例选择，只在打开或切换范围时请求，不增加定时轮询。范围起点按 UTC 整小时对齐；统计从新版本启用后开始，不能还原升级前一天的数据。测试模式输出包含随后删除的文件，不等于磁盘占用；成功率不包含跳过任务。
