# 下载性能复核：下一轮优化顺序

2026-10-30 复核当前工作区代码。目标按大批量视频下载解释：在画质、文件校验和任务正确性不变的前提下，提高单位时间成功完成的视频字节数。本文是代码评估，没有新增线上压测，也没有修改调度代码或生产配置。

## 已有能力

当前已包含自动传输与浏览器并发、有限的解析准备流水线、共享上游与连接许可、渠道成功率和速度反馈、Bergung/Cobalt 解析运行时复用、代理连接故障冷却。无需把这些作为尚未实现的新方案。

2026-10-29 的 15 分钟业务观测见 `300mbps-download-release-20261029.md`；它是历史窗口，不代表当前部署的速度。2026-10-30 部署后检查则实际发现临时文件分类预算等待和 TLS 连接中断，后者已改为自动重试。

## 优先优化

1. **磁盘预算与准入协同。** `webapp/disk_budget.py` 在租约开始时预留有限空间，进度/看门狗发现所需空间增加时继续申请。分类预算不足会释放任务并等待。应在解析得知文件大小后尽早估算音视频、合并峰值与已有预留；资源明显不足时限制新的准备任务，并在容量或预算变化后恢复，减少重复进程启动和解析。必须保留真实剩余空间、分类预算、原子预留及任务租约保护，不能用取消保护换速度。此项优先级最高，因为最近线上日志已有资源等待证据。

2. **代理选择使用实际下载收益。** `webapp/proxy_health.py:record` 已保存节点与下载方式的 `bytes_per_second`；`select` 当前按候选顺序选择首个未冷却节点，没有用该速度排序。可新增可选的自动择优模式，综合有效完成速度、失败率、当前负载与样本新鲜度，保留少量探索。仅在用户选择的候选节点中选路，并保持运行中的任务出口不变；固定节点和按数量轮换仍保留原含义。

3. **动态分片连接预算。** `web_worker.py:attempt` 当前按 `本机连接预算 // 当前传输额度` 限制单任务分片并发。额度 16、连接预算 32 时，单任务最多得到 2 个分片连接，即使实际只有 2 个任务在传输。可以在实际传输准入时，在总连接和上游许可内分配可用连接，为少量大文件利用空闲额度，同时确保新增任务不被已有任务长期挤占。此项只直接作用于支持分片并行的协议；普通 MP4 不会因提高 `concurrent_fragment_downloads` 自动变成多连接下载。

4. **缩短有证据支持的自动爬升。** `webapp/throughput.py` 每 5 秒采样，传输与分组调整以至少 60 秒为间隔，并逐步探索。可在健康出口、持续就绪需求、低资源压力时更快探测；稳定运行后使用较慢窗口，遇限流或压力迅速回退。不能直接统一缩短全部观察窗口，否则上游抖动和短视频完结会造成反复扩张、收缩。

## 后续实验

- 同一内容、同一格式的安全续传：当前多渠道执行设置 `continuedl=False`，业务任务每次领取还使用独立执行目录，以防跨格式拼接和失去租约的旧执行器污染成品。只有验证内容身份、格式、范围支持与租约后才能复用检查点；不能直接移除这些保护。
- 普通文件的 Range 并行：先验证真实媒体源的 `206`、`Content-Range`、内容版本与范围一致性，且纳入现有连接许可。不支持时回退单连接。公共文件测速不能代替真实视频测试。
- 其他浏览器解析器的复用：现有持久页面优化主要覆盖 Bergung/Cobalt。根据阶段耗时再评估 yt5s、yt1d，避免重复实现已有共享浏览器能力。

## 验收

按一个改动一轮比较，固定同一视频集合、画质/编码要求、保存模式、出口及其他负载，预热后交替观察至少 15–30 分钟。以成功校验字节/秒为主，同时记录媒体接收、成功率、重传、解析等待、传输等待、资源等待、CPU、内存和 I/O。统计跨窗口开始/完成文件时说明边界影响。

没有实测前不承诺提升百分比或跑满带宽。节点、源站限速、站点验证和硬件容量仍会约束上限；提高浏览器数、并发数或数据库连接池并不自动提高最终完成吞吐。
