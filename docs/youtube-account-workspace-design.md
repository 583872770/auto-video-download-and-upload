# 账号、Cookie 与下载实例的整体页面设计

此文扩展 [账号资料库设计](youtube-account-library-design.md)，页面结构以本文为准。当前交付为设计与可交互演示，不改线上界面、不导入用户实际账号。已有接口、调度和 Cookie 独占绑定规则继续复用。

## 一、导航与职责

把原先集中在“系统设置 → Cookie 与登录”的资料管理、Cookie 管理和账号调度拆清楚，集中到一个“账号管理”入口：

| 页面 | 管什么 | 范围 |
|---|---|---|
| 任务中心 | 客户任务、视频清单、失败重试 | 全局 |
| 下载工作台 | 当前下载、各 Cookie 为什么工作/等待/冷却 | 所选实例 |
| 素材库、交付与账单 | 已有成果和计费 | 沿用现有范围 |
| 账号管理 → 账号资料 | 邮箱、密码、附加信息、接码网址、实例归属 | 全局，允许按实例筛选 |
| 账号管理 → Cookie 与登录 | Cookie 上传、关联、登录检测、浏览器登录 | 全局列表，执行操作按绑定实例 |
| 账号管理 → 账号池与节奏 | 实例启用哪些 Cookie，账号启动间隔、预算、恢复说明 | 必须明确选择一个实例 |
| 下载实例 | 各实例健康、下载负载、账号容量、异常入口 | 全局 |
| 网络与代理 | 代理、节点、IPv6 源地址 | 所选实例 |
| 系统设置 | 下载策略、并发与渠道、存储清理、运行诊断 | 所选实例 |
| 部署设置 | 服务地址、数据库/Redis 等部署参数 | 所选实例，标明重启要求 |

“账号管理”的三个页签不是三份资料库。账号、Cookie、实例有统一 ID 和关联关系，其他页面只显示必要摘要并链接到同一个详情。

顶部统一区分“访问入口”和“管理对象”：访问洛杉矶前端不代表操作洛杉矶实例。全局页面显示“全部实例”；实例页面显示选择器及实例在线状态。全局页的“绑定实例”是查询筛选，不偷偷改变工作台当前管理实例。

账号管理从实例页面跳入时带该实例筛选条件，仍可切回全部。点击“账号池与节奏”才切换为明确的实例编辑范围；有未保存设置时切换实例需处理未保存修改。

## 二、账号管理

### 账号资料

默认是可搜索、分页的表格，不做 400 个大卡片。保留账号、绑定实例、Cookie 摘要、登录检测、下载状态及详情操作。未绑定、未关联 Cookie、需要登录均可一键筛选；不要增加一排与表格重复的总数卡片。

新增和批量导入是主操作。编辑、密码/附加信息查看、接码网址集中在账号详情；列表默认不返回这些明文。第三段按用户确认作为“附加信息”原样保存，后续确认用途再扩展，不提前当作二步验证密钥。

导入采用“输入 → 掩码预览 → 确认导入”，支持粘贴和 UTF-8 TXT。默认跳过重复，也可以明确更新资料；更新不覆盖既有实例归属、Cookie 关联或登录记录。含错误行时默认阻止提交，直接展示行号；批次中的重复行不默默覆盖。

### Cookie 与登录

显示所有实例的 Cookie，按实例、是否已关联账号、登录检测状态筛选。邮箱账号为主身份，Cookie 名称为凭据备注；保留“未关联资料”的历史 Cookie，避免强迫现有下载中断。

一份 Cookie 只关联一个账号；同一账号可以关联同实例的多份 Cookie。系统按名称猜测的关联只作为建议，用户确认后才写关联。已有检测只能确认会话登录，不能核验真实邮箱身份，页面不伪造系统认证。

上传与浏览器登录先明确目标账号和绑定实例；如果账号尚未绑定，先选择实例并确认。没有可选实例时显示原因，不能默认在访问入口服务器创建凭据。远程浏览器通过已有实例远程桌面入口打开，不声称会在访问者的本机直接弹出浏览器。

新 Cookie 保存后展示“已保存并关联账号”，同时明确是否加入账号池。登录检测通过不自动加入池，也不自动启动下载。“加入账号池”跳转该实例的池成员选择，并带上候选 Cookie；要点“保存账号池与节奏”才启用。

“检测登录”只由绑定实例执行。冷却时拒绝检测，离线时保留归属及上次检测时间。403/429/网络故障展示无法确认或需要验证，不直接表示密码错误或退出登录。列表刷新只读共享记录，不发登录请求。

### 账号池与节奏

顶部固定显示“正在配置：实例名称”，提供实例选择器。正文上半部是 Cookie 池启用开关和成员选择，下半部是常用节奏：

- 两次任务启动最小间隔。
- 任务结束后休息时间。
- 账号池共用启动间隔。
- 每账号任务上限。

小时/日预算、Cookie 使用策略、非池模式渐进节奏等放在高级区。池下载进程数、准备余量属于本机进程容量，迁到“并发与渠道”，在此仅显示只读摘要及入口，避免出现两个可编辑副本。

页面底部只有一个“保存账号池与节奏”，一起提交池开关、成员和该页策略。显示“已保存/有未保存修改”和生效说明。保存行为仍复用现有配置接口，但在页面上不要求再去系统设置提交第二次。跨页草稿统一归属一个实例，不能把甲实例草稿提交给乙实例。

## 三、统一账号详情

账号资料、Cookie 列表、工作台和实例页面打开同一个账号详情组件。首次打开展示“概况”，按需切换：

1. 资料：邮箱、备注、绑定实例、按权限显示/修改密码及附加信息、接码网址。
2. Cookie 与登录：关联凭据、最近检测、上传、去绑定实例登录；逐 Cookie 检测而非含糊的整账号检测。
3. 调度与记录：当前间隔、下次允许时间、冷却截止、逐档恢复的时间/成功门槛、最近异常与变更记录。

不用同时维护“Cookie 时间线”和“账号恢复”两套互不相通的长弹框。详情复用各自现有数据来源，在“调度与记录”按事件类型筛选。工作台点冷却/恢复默认进入这个页签，点邮箱默认进概况。

密码修改不代表现有 Cookie 立即有效或失效，修改后提示重新核验，不能重置冷却和历史保护。已关联 Cookie 的账号编辑实例归属被禁止；跨实例移动不是普通表单改一个字段。

弹框支持遮罩、关闭按钮、Esc；有编辑草稿时先提示。可复制邮箱，密钥按需读取；显示过的密钥在关闭时清除，不进入地址栏或浏览器持久存储。

## 四、下载工作台

保留用户要求的“一份 Cookie 一个格子”，不改成一个账号一个格子。已关联资料时主标题为邮箱，副标题为 Cookie 名称；同账号多份 Cookie 说明共用额度。未关联凭据继续使用原名称，并提供“补充账号资料”入口。

上方只保留任务控制、当前传输速度、任务成品数据及一处传输额度信息。已有“视频处理进度”不重新加入。传输上限不等于账号数，账号数也不等于正在传输数。

Cookie 格子只显示：任务阶段、当前任务数/速度、账号健康、下一次允许时间或最主要等待原因、详情入口。小时预算、滚动日预算、完整错误和恢复门槛下钻查看。原因示例：

| 状态 | 格子中的主要说明 |
|---|---|
| 正在传输 | 当前任务、速度 |
| 等待启动 | 两次启动间隔剩余 34 秒 |
| 任务结束后休息 | 休息剩余 12 秒 |
| 账号冷却中 | 冷却到 14:30，暂停新增任务 |
| 低频恢复 | 当前至少 300 秒；点击查看成功/时间门槛 |
| 未启用 | 未加入当前实例账号池 |
| 无任务 | 没有任务占用，展示实际观测到的原因 |
| 状态待更新 | 实例离线或采样过期，不能据旧数据推断正在下载 |

保留已上线的独立冷却筛选，冷却不归入“无任务”。任务阶段和账号健康分别表达；冷却时还有收尾传输，可以同时匹配两个筛选，筛选数量不宣称互斥合计。不要把“剩余等待时间为零”等同立刻能启动。

账号恢复进度、动态进程上限和资源压力仍按已有实际诊断展示，不能为了页面清爽而删除保护原因；仅将重复说明收进详情。

## 五、下载实例页面

默认使用紧凑表格或简洁行，不把每台实例所有配置展开。每行只保留：名称/在线状态、当前工作任务、传输速度、已占用/当前传输上限、启用 Cookie/核心会话数、冷却/不可用数和操作入口。

主要入口：工作台、管理账号、实例设置。地址、主机名、版本和资源限制放详情。实例选择后进入的账号页自动筛选该实例，账号池配置页明确选中该实例。

“资料账号数”“Cookie 数”“核心会话数”含义不同，不能都叫“账号数”或混用分母。默认展示启用 Cookie 和冷却摘要，展开后再看账号资料关联覆盖情况。账号未入库不表示原有 Cookie 不可用。

不在本页重复编辑账号池或节奏；所有编辑进入唯一主页面。继续保留已有实例启动/完成当前后停止/立即停止等控制及权限，不增加一键迁移 Cookie 或把任务自动交给其他实例的操作。

## 六、已有代码的调整范围

| 现有位置 | 调整 |
|---|---|
| `templates/workspace_nav.html` | 增加账号管理，明确全局与实例导航范围 |
| `templates/settings_accounts.html`、`cookie_profiles.html` | 上传、检测、登录、成员选择移入账号管理的对应页签，先提取组件再搬迁 |
| `templates/youtube_policy.html` | 节奏/预算字段迁入账号池页；本机进程容量迁到并发与渠道；源地址归网络与代理 |
| `templates/settings.html`、`settings_navigation.html`、`static/settings_tabs.js` | 删除重复的 Cookie 设置表单，只保留跳转；旧设置链接兼容到新入口 |
| `static/app.js` | 将 Cookie 资料/登录/池草稿逻辑从大文件拆入独立模块，复用统一 API 与实例上下文 |
| `static/concurrency.js` | Cookie 卡片补充账号邮箱及详情入口，保留现有状态分类和等待诊断 |
| `static/cookie_recovery.js`、相关弹框模板 | 统一到账号详情的调度与记录页签，保留历史 Cookie 无账号关联时的入口 |
| `static/fleet.js`、`templates/index.html` 实例部分 | 收紧实例行，增加对应账号和工作台入口，移除重复编辑 |
| `webapp/cookie_profiles.py`、`youtube_auth.py` | 资料关联、批量只读状态、明确绑定实例的检测；保留现有登录判定与缓存边界 |
| `webapp/fleet_routes.py`、管理台鉴权 | 全局账号库不跟实例选择自动转发；执行操作只向实际绑定实例；密码读取拒绝节点 RPC |

这是围绕账号/Cookie 工作流的重排，不重做任务中心、素材库、计费或部署功能。原接口兼容期保留；旧入口跳转不丢实例上下文。配置字段只保留一个可编辑 DOM，避免重复字段、保存覆盖或前端事件重复绑定。

## 七、落地与验收

先实现全局资料库和导入，再提取现有 Cookie 组件及账号详情，随后搬移池设置，最后接工作台/实例入口。功能全部贯通后统一切换入口，避免发布一个资料与 Cookie 完全割裂的半成品。

验收必须覆盖：从任意前端操作指定实例、全局与实例筛选互不污染、关联与独占绑定、旧 Cookie 兼容、导入特殊字符、三种资料操作及删除、单处保存、切换实例的草稿保护、迟到响应不能覆盖新实例、登录缓存失效、冷却不主动探测、权限及密钥读取、分页和后台隐藏时停止刷新。

交互演示仅用虚构邮箱和凭据，在内存模拟资料编辑与导入；它不连接生产接口，不代表新功能已经实现或部署。
