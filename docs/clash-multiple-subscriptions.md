# 网络与代理：多个订阅

“网络与代理”支持按名称保存最多 20 个订阅，每个实例独立管理。

1. 点击“新增订阅”，输入名称和 Clash / Mihomo 订阅链接，保存。
2. 首个订阅保存后自动启用；后续新增订阅只保存，不改变当前连接。
3. 在“已保存订阅”中选中条目，点击“切换到此订阅”。切换使用缓存节点，无需重新访问订阅链接。
4. 更新所选订阅时，链接留空会使用已保存的链接，填写新链接会替换该条目的链接。
5. 备用订阅可以删除；当前使用的订阅需先切换到其他订阅再删除。

每个订阅分别保留上次选择的节点、各下载进程的节点及自动轮换配置。切换后恢复这些选择，并重新计数轮换进度。不同订阅的同名节点不会继承旧订阅的测速或线路冷却结果。链接不会从读取接口回传到浏览器。

运行中的下载、未暂停的排队下载、YouTube 登录和节点测速仍遵守原有操作限制。切换不会自动恢复已暂停的下载队列。

旧单订阅在实例升级启动时自动迁移为“原有订阅”，保留节点和轮换配置，无需重新填写链接。多实例部署应更新所有会被选择操作的实例。

实现保留 `/api/clash/subscription` 的旧 POST 调用，新增 `save`、`switch`、`delete` 操作。私有元数据位于实例代理目录的 `settings.json`，节点缓存位于 `subscriptions/<id>.yaml`；当前生效配置仍使用 `nodes.yaml`、`runtime.yaml`。更新或切换失败时恢复原设置、缓存及内核运行配置。

验证入口：`tests/test_clash_subscriptions.py` 覆盖保存、缓存切换、回滚、迁移、重启、凭据保护与跨实例隔离；`scripts/verify_clash.py` 使用本地两个代理出口及真实 Mihomo，验证网页操作和实际路由，同时检查桌面及手机布局。

本轮同时修正 YouTube 检测的错误分类：原来 HTTP 拒绝、限流、超时和证书错误均显示“当前节点无法连通 YouTube”。现在分别显示 HTTP 状态、超时、TLS / 证书或服务端链路异常。该检测从运行服务的实例经过项目代理访问测试地址，与其他设备的浏览器使用的路径可能不同；检测通过也不保证视频下载通过站点验证。本轮未连接用户生产代理，不能据此确定线上那次失败的具体原因。

本地验证：代理、轮换、订阅边界及多订阅共 18 项后端回归通过；新增验证与检测分类共 9 项定向测试通过（其中包含重复执行的多订阅测试，不累加为独立用例数）。最终真实 Mihomo 浏览器验证报告：`.cache/validation/clash-ec6baf2743/report.json`；暂停队列编辑回归：`.cache/validation/rotation-unlock-c4438ee1f8/report.json`。JavaScript / Python 语法及 Git 空白检查通过。
