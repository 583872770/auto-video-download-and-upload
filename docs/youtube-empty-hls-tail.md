# YouTube 极短空尾片兼容

2026-11-09 在洛杉矶实例核实 `gJV65wL1W30`：完整 HLS 清单包含 50 片，最后一片标称 0.007 秒，反复返回 HTTP 200 空响应。前 49 片可生成 1080×1920 的完整音视频；封装后视频 260.010 秒、音频 260.017 秒，整段 FFmpeg 解码无错误。原生 yt-dlp 2026.10.26 会跳过空片但保留失败返回码，导致任务重试和 Cookie 退避。

`webapp/hls_download.py` 在原生 HLS 下载前进行限定兼容，由 `ParallelYoutubeDL` 选择使用，不替换第三方下载器、字幕、直播或普通 HTTP 下载。

- 仅处理有 `ENDLIST`、至少两片的普通 YouTube VOD 清单。加密、初始化片、字节范围、广告、时间线切换、截取下载等复杂情况继续走原生逻辑。
- 仅检查不超过 0.05 秒的末片，使用当前 yt-dlp 的 Cookie、请求头和网络配置请求一次。必须实际收到 HTTP 200 且内容为空；403、429、非空内容及不完整响应均不视为成功。
- 确认空尾片后，去除该片，重新组装其余内容，禁止跳过任何其他分片，也不复用上次留下的残片。
- 通过 ffprobe 检查所需音视频轨道，其时长须与剩余清单相差不超过 0.25 秒。清单与源视频已知时长也须相符，容许元数据的秒级取整。缺工具、缺轨道或时长不符均失败，并删除校验未通过的结果。
- 仅校验通过才返回成功，不清除 yt-dlp 的全局错误码。成功任务正常进入后处理和归档，不再因该空尾片触发任务重试或 Cookie 失败退避。

普通下载不增加媒体探测；符合极短尾片条件时增加一次尾片请求，确认空响应后增加一次有 30 秒超时的 ffprobe。生产兼容不做整段解码，避免占用下载实例大量 CPU；真实文件诊断和集成测试另行完整解码。

此修复不会批量修改历史失败任务或重置 Cookie 状态。部署后可重试相应失败任务。其他 `Did not get any data blocks` 错误仍按既有策略处理，不能仅凭报错文本认定为空尾片。

验证：`python -m unittest tests.test_hls_download tests.test_parallel_http tests.test_download_paths tests.test_download_quality tests.test_download_policy -v`。

本次本地相关测试 48 项通过；最终版本的 11 项 HLS 专项测试在 Windows 和线上 Linux / yt-dlp 2026.10.26 均通过，没有跳过。另在隔离进程中使用洛杉矶原实例、原 Cookie 和正常账号准入重新下载 `gJV65wL1W30`：修复后返回码为 0，没有跳过正常媒体片，音视频时长保持不变，完整 FFmpeg 解码返回 0、无错误。诊断任务及下载许可已释放；该验证没有替换线上运行代码。
