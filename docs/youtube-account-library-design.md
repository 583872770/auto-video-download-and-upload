# YouTube 账号管理设计

本方案基于当前共享 MySQL/Redis、所有实例兼任管理端的部署。新增全局账号资料库，复用现有实例、Cookie 库、浏览器登录和登录检测能力。功能已接入应用代码，尚未部署或导入实际账号；配置及边界见 [使用与部署说明](youtube-account-management.md)。

页面范围已扩展为统一“账号管理”，与工作台、下载实例、系统设置一起调整；页面职责及字段迁移以 [整体页面设计](youtube-account-workspace-design.md) 为准。下文的数据、导入、登录和绑定约束继续适用。

## 1. 页面与数据范围

侧边栏新增独立入口“YouTube 账号”。从任何实例前端打开都看到同一份账号库，默认展示全部账号，通过页面内的“绑定实例”筛选器查看某台服务器。该页面不跟随工作台当前选中的执行实例改变资料范围。

页面顶部：搜索账号/备注、绑定实例、登录状态、下载状态、新增账号、批量导入、刷新。

主列表保留以下列：

| 列 | 展示内容 |
|---|---|
| 账号 | 邮箱、简短备注 |
| 绑定实例 | 实例名称、在线/离线；没有绑定则显示“未绑定” |
| Cookie | 未关联、关联份数、是否已加入账号池 |
| 登录状态 | 检测结果、最近检测时间；过期结果单独标注 |
| 下载状态 | 未参与下载、正常、账号冷却中、低频恢复、暂停/不可用、状态待更新 |
| 操作 | 详情/编辑、关联 Cookie、检测登录、更多（删除） |

密码和附加信息不放在列表中，详情面板按需显示/复制。接码网址放在详情面板，支持复制和打开，不自动访问。使用测试域名绘制的结构示意：

```text
YouTube 账号                 [新增账号] [批量导入] [刷新]
[搜索账号或备注] [全部实例 ▾] [全部登录状态 ▾] [全部下载状态 ▾]

账号                    绑定实例     Cookie      登录状态                 下载状态
demo-a@example.com      洛杉矶       已关联      最近验证通过 · 10:30      正常
demo-b@example.com      洛杉矶       已关联      检测已过期 · 09:00        账号冷却中
demo-c@example.com      未绑定       未关联      未关联 Cookie             未参与下载
```

每个表单只有一个明确的提交按钮：“保存账号”“确认关联”“确认导入”。保存资料不要求再去系统设置点击保存。表格支持分页，默认每页 50 条；筛选切换回第一页，保留当前搜索条件。弹框沿用全站点击遮罩关闭、关闭按钮和 Esc 行为；存在未保存输入时提示丢弃修改。

## 2. 账号资料

| 字段 | 规则 |
|---|---|
| 邮箱账号 | 必填，去除首尾空白，以小写规范值全局唯一；不擅自合并 Gmail 的点号或别名 |
| 密码 | 新增必填；编辑留空默认保留原密码，有独立“修改密码”动作；不去除密码内的空格或特殊字符 |
| 附加信息 | 保留导入第三段原文；类型尚未确定，不解析或生成二步验证码 |
| 接码网址 | 保留第四段网址，只接受 HTTP/HTTPS；不抓取内容、不尝试接码 |
| 备注 | 可选，供搜索、记录来源或用途 |
| 绑定实例 | 可空；已关联 Cookie 时必须与 Cookie 的实际归属一致 |
| 关联 Cookie | 同一账号允许关联多份同实例 Cookie；一份 Cookie 只能关联一个账号 |

账号资料全局共享，下载策略仍按实例隔离。新增或导入资料不会自动登录、生成 Cookie、加入账号池或改变下载参数。

## 3. 登录状态的准确含义

登录和下载运行状态分开。账号可能同时是“最近验证通过”和“账号冷却中”。冷却、HTTP 429 或临时网络失败均不能直接判定退出登录。

| 登录状态 | 判断条件 |
|---|---|
| 未关联 Cookie | 只有账号资料，未关联下载凭据 |
| 待检测 | 已关联 Cookie，没有匹配该 Cookie 版本及出口配置的有效检测记录 |
| 最近验证通过 | YouTube 明确返回登录标志为真，记录尚在现有有效期内；当前实现上限为 5 分钟 |
| 检测已过期 | 过去验证通过但有效期已到；展示“上次验证通过时间”，不自动变成未登录 |
| 需要重新登录 | YouTube 明确未认可当前会话，或登录 Cookie 已无效/过期 |
| 需要网页验证 | 收到额外验证或访问限制，不能确定是否掉线 |
| 暂时无法确认 | 网络失败、请求限流、检测进行中等；保留最近一次成功检测时间作为历史信息 |

检测结果同时记录所属实例、关联 Cookie、Cookie 指纹、检测时间、有效截止时间及出口/配置版本。Cookie 更新、出口切换、关联改变后，不沿用原来的“已验证”标记。

如果一个账号关联多份 Cookie，列表展示“1/2 份近期验证通过”等摘要；详情逐份展示检测结果，不让一次失败覆盖另一份有效会话。同账号多份 Cookie 在现有核心凭据合并机制下继续共享调度限制。

当前 `webapp/youtube_auth.py` 的 `logged_in()` 只验证服务器返回的 `LOGGED_IN` 标志，不验证邮箱身份。因此首次关联 Cookie 必须由用户确认账号，页面将关联来源标注为“用户确认”，不能宣传为系统核验了真实 Google 账号。名称包含邮箱只可作为关联建议，不能自动确认。

“检测登录”由账号绑定实例通过自身代理/IPv6 出口执行，复用现有 `check_profile()`。冷却中的账号拒绝主动检测并展示剩余冷却时间；实例离线时展示无法检测，不在打开管理页面的另一台服务器上代测。只使用已保存的 Cookie，不拿密码静默尝试登录。

“去绑定实例登录”进入该实例现有浏览器登录入口。登录成功并保存 Cookie 后，选择刚保存的 Cookie 与账号关联。没有绑定实例时先绑定，不在任意实例启动登录窗口。

## 4. 绑定与删除规则

每个账号最多绑定一个实例。一个实例可绑定多个账号，满足未来 20 个实例、每实例至少 20 个账号的规模。

绑定实例是下载凭据的真实归属，不能只改一个显示名称。新增账号尚无 Cookie 时，可以选择或修改绑定实例；关联已有 Cookie 时，服务端锁定账号记录并核对 Cookie 的实际实例、是否已关联其他账号，以及核心凭据归属。

账号已有 Cookie 后，不提供直接跨实例改绑。现有 `webapp/cookie_binding.py` 的核心凭据绑定会在删除 Cookie、实例离线后继续保留，防止旧任务仍持有凭据快照时被另一实例复用。单纯解绑资料关联不能释放这项归属。跨实例迁移应作为后续明确的迁移功能，不能混进普通编辑或重复导入。

同一账号的不同 Cookie 必须关联到同一个实例。记录实例修改和关联操作使用版本号及数据库事务，两个管理端同时修改不能同时成功。既有未关联账号的 Cookie 可继续工作，逐步补充关联，不强制中断现有 18 份 Cookie。

删除前展示影响范围：账号资料、关联 Cookie、当前是否在池及是否存在运行任务。关联 Cookie 仍在下载或账号池中时，要求先移出账号池并等待任务结束。删除账号资料不静默删除 Cookie、不解除核心凭据绑定、不改变其他账号的任务。

最终删除清除密码、附加信息和接码网址密文，只保留必要的无密钥操作记录。Cookie 删除沿用独立的 Cookie 管理流程。重新导入同一邮箱也不能借此绕过已有 Cookie 实例归属。

## 5. 批量导入

支持粘贴多行或上传 UTF-8 `.txt`，兼容 BOM、Windows 换行及空行。完整格式：

```text
邮箱----密码----附加信息----接码网址：http://example.com/
```

支持仅包含前两段，第三、四段可省略；第四段接受“接码网址：”“接码网址:”或直接 HTTP/HTTPS URL。分隔符固定为四个半角减号 `----`，不会误拆密码里的 `&`、`!`、`#`。存在额外分隔符、缺失必填字段或非法网址时报告具体行号，不能静默丢弃后续字段。不可解析的密码由单条新增/编辑录入。

导入步骤：

1. 选择“先不绑定”或一个批次默认绑定实例，粘贴/上传原文。
2. 点击“预览”，展示总行数、新增、重复、格式错误及逐行结果；密码和附加信息掩码显示。
3. 默认“跳过已存在账号”。可选择“更新已有账号资料”，仅更新本次提供的字段，缺失字段保留；不覆盖绑定实例、Cookie 关联及登录检测状态。清空字段在单条编辑中明确操作。
4. 点击唯一的“确认导入”，显示新增/更新/跳过/失败数量。错误行可修改后重试；批次内重复账号同样列出，不能默认以后面的行覆盖前面的密码。

预览不写入账号，也不登录或检测。提交时重新验证全部数据、重复规则及记录版本，避免其他管理端在预览后修改数据而被覆盖。默认需处理格式错误后再提交；如支持“只导入有效行”，必须由用户明确选择，并保留错误行清单。

每次最多 1,000 行、文本最大 1 MB，足够覆盖 400 个账号。导入原文和含密钥字段不进入 URL、浏览器持久存储、应用日志或仓库。测试使用虚构账号，不把用户提供的实际账号密码写入测试样例。

## 6. 后端边界

新增 `youtube_accounts` 全局表，主要字段：`id`、`email`、`normalized_email`（唯一索引）、`secrets_ciphertext`、`key_id`、`note`、`instance_id`、`version`、`created_at`、`updated_at`。密码、附加信息和接码网址在密文载荷中保存，使用支持认证的加密并绑定账号 ID。

新增 `youtube_account_cookies` 关联表：`account_id`、`instance_id`、`profile_id`、`confirmed_by`、`created_at`；对 `(instance_id, profile_id)` 建唯一约束，对 `account_id` 建索引。绑定实例以账号记录为唯一准入依据，在同一事务中校验关联实例，不允许关联跨实例 Cookie。

加密密钥由部署端配置，同一共享账号库的所有管理实例使用同一密钥，不写入数据库或普通配置响应；提供明确的备份说明和密钥版本，以便后续轮换。缺失或不匹配时明确报错，不能回退到明文保存。保留现有管理台登录、角色和 CSRF 校验；只有管理员可以读取密码、编辑、导入、删除和改关联，只读用户只能看不含密钥的摘要。

默认列表/详情接口不返回密码及附加信息明文。管理员点击显示/复制时使用独立的 POST 接口读取，响应禁用缓存；记录操作人、账号 ID、动作和时间，不记录返回值。接码网址同样按需读取；打开网址只允许 HTTP/HTTPS，并使用 `noopener,noreferrer`。

建议接口范围：

| 接口 | 用途 |
|---|---|
| `GET /api/account-library/youtube` | 分页、搜索、实例及状态筛选 |
| `POST /api/account-library/youtube` | 新增 |
| `GET/PATCH/DELETE /api/account-library/youtube/<id>` | 查看、修改、删除资料 |
| `POST /api/account-library/youtube/import/preview` | 导入校验、掩码预览 |
| `POST /api/account-library/youtube/import` | 确认导入 |
| `POST /api/account-library/youtube/<id>/secrets` | 管理员按需查看指定密钥字段 |
| `PUT /api/account-library/youtube/<id>/cookies` | 确认 Cookie 关联 |
| `POST /api/account-library/youtube/<id>/check` | 按绑定实例检测指定关联 Cookie |

全局接口刻意不使用 `/api/youtube/...`，也不使用 `/api/youtube-accounts`：当前 `fleet_routes.py` 按 `/api/youtube` 前缀自动转发，这两种命名都会受工作台实例选择影响。新账号库直接读写共享 MySQL；仅登录/检测等执行动作转发到实际绑定实例，转发目标从数据库读取，不信任前端传入的当前实例 ID。账号密码读取接口不加入执行实例 Bearer RPC 白名单。

## 7. 查询和运行成本

账号列表不调用会物化 Cookie 文件的 `CookieProfiles.require()` 或 `profile_status()`，不逐账号发远程请求。通过分页查询、批量关联和现有共享检测记录生成状态。复用 Cookie 指纹及检测记录的语义，并统一自动检测与人工检测的状态发布，避免只有点过人工检测的账号才有记录。

账号列表打开、手动刷新、提交修改后更新；可见页面至多每 30 秒刷新当前页摘要，页面隐藏时停止刷新。刷新只读取状态，不主动请求 YouTube。登录检测按需触发，按实例限并发且同一 Cookie 合并重复检测；400 个账号不会因为打开列表同时发出 400 次登录请求。

不修改既有下载调度、账号启动间隔、冷却策略和 Cookie 绑定保护。账号资料管理对现有下载链路保持独立，只有关联校验及状态发布复用现有能力。

## 8. 验收范围

- 新增、编辑、筛选、分页、删除及重导入行为；邮箱规范化、特殊字符密码不变、编辑空密码不覆盖。
- 原示例结构、两段简化格式、BOM/CRLF、空行、重复账号、非法网址及字段数量错误的导入处理；预览和异常均不泄露密钥。
- 任意实例前端看到同一份账号资料；切换工作台实例不改变账号库范围，离线实例仍保留归属。
- 跨实例关联失败、同 Cookie 关联多个账号失败、并发改绑冲突、删除后不能绕过 Cookie 归属。
- 登录有效期、Cookie/出口变化、HTTP 403/429、网络错误、冷却及多 Cookie 汇总语义；所有主动请求都来自绑定实例。
- 未登录、只读或执行节点 RPC 不能读取密钥；CSRF、防缓存、加密密钥缺失及不匹配的处理。
- 400 个账号分页查询没有逐账号网络请求、文件写入或 N+1 查询；列表只展示少量必要数据。

实施顺序：先全局资料库及导入，再 Cookie 关联和只读状态汇总，最后接入绑定实例检测/浏览器入口和权限验收，整体完成后再部署。用户提供的 8 条实际资料由导入页面操作；本设计阶段不写入生产数据库。
