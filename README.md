# YouTube 视频下载服务

这是一个 Flask Web 下载工作台，面向批量 YouTube 视频 ID 清单。支持 yt-dlp、yt5s、downmp3 API、yt1d 的自定义尝试顺序、YouTube Cookie、Clash/Mihomo 节点、并行下载、阶段进度、素材库和交付计费统计。

项目只保留 YouTube 下载流程，正式部署使用远程 MySQL 5.7.9+ 或 MySQL 8.x。

现在推荐使用侧栏“任务中心”（`/jobs`）：每次导入创建独立客户任务，可在任务内追加、移除、清空视频，并独立开始、暂停、查看概览和预计账单。同任务内去重，不同任务可独立下载同一个 ID；任务创建时复制默认下载策略。操作与兼容说明见 [TASK_CENTER.md](TASK_CENTER.md)。原工作台保留全局资源与历史统计入口。

支持“管理与下载一体 + 多实例共享 MySQL”：每台机器都可打开管理页面并参与下载，任务、统计和计费共享，目录、Cookie 和代理按实例独立。启动后在 `/setup` 页面配置 MySQL 和实例地址，全新部署默认选择一体模式。也兼容纯管理端、纯下载实例和单机模式，完整部署和升级步骤见 [MULTI_INSTANCE.md](MULTI_INSTANCE.md)。

本版统一了任务计费、编辑版本和控制范围，并增加管理账户。未设置账户时只允许本机直接访问；访问 `/login`，使用状态目录 `console-bootstrap.key` 中的初始设置码创建管理员。创建后所有管理页面均需登录，支持管理员、操作员和只读账户。升级说明见 [第一阶段改造说明](docs/redesign-phase-one.md)。

长期运行可在“实例与环境 → 磁盘容量管理”设置临时文件总预算（默认 20 GiB）和分类上限，自动清理测试文件、缓存和日志。空间不足时等待恢复，保留下载统计及账本；容量范围与部署说明见 [DISK_MANAGEMENT.md](DISK_MANAGEMENT.md)。

## Docker 部署

项目只有一个 Compose 编排文件，内置 FFmpeg、Node.js、Mihomo、Chromium、Xvfb 和 noVNC，连接远程 MySQL：

```bash
cp .env.remote-mysql.example .env
# .env 只需按需调整宿主机端口和视频目录，数据库在页面填写
docker compose -f compose.remote-mysql.yaml config --quiet
docker compose -f compose.remote-mysql.yaml up -d --build
```

访问 `http://127.0.0.1:5000/setup`，输入启动日志中的“部署设置访问码”，在页面测试 MySQL 连接并保存。服务器部署时，可在 `.env` 设置 `WEB_BIND_IP`、`WEB_PORT` 和 `VIDEO_DOWNLOAD_DIR`。完整说明见 [DOCKER.md](DOCKER.md)、[MYSQL.md](MYSQL.md) 和 [YT5S_LINUX.md](YT5S_LINUX.md)。

## 本地启动

需要 Python 3.13+、FFmpeg、Node.js 或 Deno，以及已安装的依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe app.py
```

打开 `http://127.0.0.1:5000/setup`，输入终端打印的部署设置访问码，选择管理与下载一体（推荐）、纯管理端、纯下载实例或单机模式，再填写 MySQL。一体实例和纯下载实例填写各管理页面能访问的本机实例地址，ID 留空自动生成。PyCharm 直接运行 `app.py` 即可，无需填写角色和数据库启动参数。

首次保存会启动服务，配置保存在本机状态目录的 `deployment.json`，以后用同一条命令启动。已运行服务修改部署配置后需重启，当前下载不会被保存操作中断；工作台侧栏可重新进入“部署设置”。访问码保存在同目录 `deployment.key`，每次启动都会打印。

启动时先提供设置页，再后台连接 MySQL、检查表结构及初始化实例。终端会打印当前阶段；数据库响应慢时仍可打开 `/setup` 查看阶段和等待时间，失败后可在页面修正配置并重试。

已有 `.env` 配置仍可读取；也可用 `--env-file` 指定其他文件。页面保存配置优先于环境文件，显式 CLI 角色和实例参数优先于页面。未配置数据库时只显示设置向导，不创建业务 SQLite 数据库；已有数据库不会自动迁移。服务监听地址/端口、Docker 宿主机端口和卷映射仍由启动命令或 Compose 设置。

## 页面功能

- 首页输入固定 YouTube 前缀后的 11 位视频 ID，也支持完整链接和清单导入。
- 首页勾选下载器并排序后保存系统默认策略；客户任务在创建时复制默认策略，之后在任务设置中独立修改。每个视频按顺序尝试，成功即停止，失败则切换到下一项。画质、下载器顺序、转换超时、分片并发与重试上限支持热修改：保存后，历史清单后续领取的视频立即使用新策略，无需暂停或重启；客户任务在任务设置中独立热修改。在途视频保持领取时的配置，重试时读取最新策略。
- 导入不要求 Cookie、浏览器或代理已就绪。客户任务使用自己的下载策略，执行时从实例读取目录、Cookie 和代理；已运行的尝试保持本次配置。没有任务策略的历史清单在每次领取时读取最新全局下载策略。正式/测试模式仍沿用已激活执行会话的值，切换需停止后重新开始；客户任务在首次执行后锁定该模式。
- 按下载方式检查所需环境与登录；仅启用 downmp3 时无需浏览器、JavaScript 运行时或 YouTube Cookie，使用 ffprobe 校验成品。
- 新部署默认尽可能获取最高画质：yt-dlp 优先分辨率和帧率，不限制编码或分辨率，优先 MP4、必要时使用 MKV；yt5s 自动选网站提供下载操作的最高分辨率；downmp3 请求当前接口最高档 1080p，实际结果受视频源和第三方服务限制。升级不会覆盖数据库中已保存的全局策略和任务策略；可在下载设置和各任务设置中选择“尽可能最高画质”。已有成品不自动重新下载。
- 支持直连、手动代理、Clash 订阅代理、节点测速和自动轮换。
- 支持 1–16 个下载进程，以及单独的 yt5s 浏览器并发数。
- 支持指定目录保存、测试模式和下载统计；网盘保存暂未实现。
- 任务记录只显示已结束任务，首页只显示当前正在下载任务；素材库支持封面和视频播放。
- 素材库右上角支持“清空素材库”：先暂停全部下载，输入“清空”确认后，后台删除当前服务本机素材目录及子目录中的视频和同名配套文件，并同步索引。下载历史、客户计费和去重记录保留；搜索和分页不影响清空范围。符号链接、目录联接和无关文件不会删除。

## 添加清单、启动与结算

1. 在任务中心新建客户任务、粘贴视频 ID 或导入 TXT / CSV。首页保留快捷新建入口；创建后进入任务中心管理，新任务保持待开始。
2. 在任务设置确认下载策略和单价，再开始当前任务。系统恢复只恢复领取，不会启动新任务或恢复已暂停实例；实例故障只隔离该实例，没有可用实例时任务显示等待原因并保留运行意愿。
3. 首页只展示运行中的视频，包含解析、转换与传输阶段，并显示当前阶段用时。数据库、代理控制接口和工具状态分别显示；代理控制接口可用不等于外网下载可用。错误用简短原因提示，技术日志在任务详情中手动展开。
4. “交付与执行统计”汇总客户任务的预计费用，支持导出交付和测试文件。客户、名称、下载策略及单价统一到任务中心修改；多页面编辑发生冲突时保留输入并提示核对。测试文件删除前登记大小，单独统计、不计费。

执行会话和各下载器成功率统计继续保留，但会话不再生成账单或编辑单价。商业金额统一按客户任务汇总，包含归档和删除任务保留的历史交付；金额卡片不受执行会话筛选影响。单价留空为待定，0 为免费，历史未分类执行不补造费用。当前金额仍为预计费用，正式结算冻结属于后续阶段。

队列、任务账本和执行统计保存在数据库中。升级会增加账户表、迁移版本记录和任务编辑版本，不重建视频队列。新版页面使用 `/api/jobs/*`；`/api/downloads/resume` 与任务中心系统恢复共用控制服务。旧清单编辑接口已停用并返回 410；旧 `/api/downloads/start` 仅保留历史清单兼容用途。

## downmp3 API

在首页勾选 downmp3，调整优先级并保存下载策略。例如只勾选 downmp3、yt5s，顺序设为 downmp3 → yt5s，失败后就自动尝试 yt5s，无需 Cookie；勾选 yt-dlp 后，开始前还会检查 YouTube Cookie。下载设置默认“尽可能最高画质”（当前请求 1080p），也可指定 360p、480p、720p、1080p；转换等待上限默认 300 秒，可设为 30–1800 秒。支持视频 ID 清单和 TXT / CSV 批量导入，暂不支持播放列表。

根据 [downmp3 接入文档](https://downmp3.yt/api-documentation) 中嵌入组件的实际调用流程，后端请求 `p.savenow.to/api/v2/download` 创建转换任务，轮询 `/api/progress` 获取 MP4 链接，再使用现有传输模块保存文件、封面和元数据。转换阶段单独显示进度；下载阶段显示实际下载字节数、速度和剩余时间。所有请求使用任务当前代理节点，不向第三方发送 YouTube Cookie；不占用 yt5s 浏览器并发名额。

下载后用 ffprobe 确认文件含音视频，再登记实际字节数。下载统计按 `downmp3` 独立统计成功率、失败数、计费大小和测试大小；测试模式删除成品前保留大小记录。临时网络错误和 429 / 5xx 按队列规则退避重试，转换等待有超时上限。

该站公开文档主要描述嵌入组件，后端接口来自组件当前实现，可能发生变更、限流或要求网站验证。遇到转换或下载失败时，按页面配置继续尝试下一下载器；没有后续下载器时报告失败。停止下载、磁盘已满、权限不足及缺少运行环境不会触发切换。它没有官方批量吞吐保证，建议先验证自己的节点和清单再扩大并发。

## yt1d 网页下载

在首页下载器列表勾选 `yt1d` 并保存优先级，例如 `yt1d → downmp3 → yt5s`。默认策略只影响历史清单和新建客户任务；已有客户任务在任务设置中加入 `yt1d`。它使用 [yt1d.lol](https://yt1d.lol/) 当前网页的正常验证、解析和转换流程，无需 YouTube Cookie。不是 downmp3 的别名，执行结果与下载大小按 `yt1d` 独立统计。

下载设置和客户任务设置支持 `yt1d_quality`：`best`（默认，网站实际提供的最高档）、`360`、`480`、`720`、`1080`、`1440`、`2160`。指定档位必须由网站提供，不会把请求值当成实际成品分辨率。`yt1d_timeout` 默认 180 秒，可设 30–1800 秒，分别限制网站验证/解析和转换等待；网页导航、表单和画质查找另有短超时。保存后后续领取和重试使用新策略，在途视频保持原配置。

运行需要 Chrome/Chromium、Playwright 和 ffprobe，Linux 需要显示环境（如 Xvfb）。使用现有远程 MySQL Compose 构建即可，无需新增 Python 依赖或数据库表。yt1d 与 yt5s **共享** `yt5s_browser_count` 浏览器并发上限和磁盘预算；解析完成后由现有传输模块保存视频、封面与元数据，并用 ffprobe 检查音视频后登记交付。测试模式同样先登记实际字节再清理，不计费。

网页、验证、解析及文件传输沿用当前任务代理出口，浏览器支持无账号密码的 HTTP(S) 代理或直连。网站可能要求人工验证，可通过现有远程桌面完成；验证或转换失败会按顺序切换到下一个下载器，临时 HTTP 错误和超时使用现有退避重试。缺少浏览器、磁盘资源不足等实例环境问题保留原有等待/隔离规则。

本地验证覆盖真实 Chromium 的模拟网站表单、画质选择与转换轮询，以及实际 MP4 传输、测试清理、错误文件回退和交付去重。线上探测可打开网站，但本机无头浏览器未完成网站验证，因此尚未验证该出口上的真实 yt1d 下载成功率。

## 命令行

```powershell
# 启动 Web 服务
.\run.ps1 -Mode web

# 直接使用 yt-dlp 下载
.\run.ps1 -Mode download -Url "https://www.youtube.com/watch?v=视频ID"

# 打开独立 YouTube 登录浏览器
.\run.ps1 -Mode youtube-login

# 运行自动化测试
.\run.ps1 -Mode tests
```

YouTube Cookie 可在页面上传 Netscape 格式文件，也可使用独立浏览器登录。登录说明见 [YOUTUBE_LOGIN.md](YOUTUBE_LOGIN.md)。

## 数据迁移与容量

旧 SQLite 数据迁移到 MySQL 使用 [MYSQL.md](MYSQL.md) 中的 `scripts/migrate_mysql.py`。大批量导入、并发模型和容量边界见 [SCALING.md](SCALING.md)。

项目仅处理用户有权下载的内容。

下载器优先级也可在 YAML 中配置，例如：

```yaml
download_methods:
  - downmp3
  - yt5s
```

至少选择一个，不能重复。旧的 `download_method` 配置仍可读取；旧的 `yt5s_fallback` 自动对应 `yt5s → yt-dlp`。已导入或排队的任务在开始时读取当前已保存的顺序，运行中的任务使用本次启动配置。各下载器使用各自的画质配置；切换后重新下载，避免拼接不同编码的残留文件。
