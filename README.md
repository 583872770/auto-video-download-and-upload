# YouTube 视频下载服务

这是一个 Flask Web 下载工作台，面向批量 YouTube 视频 ID 清单。支持 yt-dlp、yt5s、downmp3 API、yt1d、Bergung / Cobalt 的自定义尝试顺序或自动择优、YouTube Cookie、Clash/Mihomo 节点、并行下载、阶段进度、素材库和交付计费统计。

项目只保留 YouTube 下载流程，正式部署使用远程 MySQL 5.7.9+ 或 MySQL 8.x。

使用流程为“任务中心新建任务 → 进入任务添加视频 → 下载工作台选择任务（必选）→ 开始下载”。视频粘贴和 TXT/CSV 导入仅在任务详情的“添加视频”中提供；下载工作台负责开始、暂停、停止和实时进度。任务资料、视频、单价和独立账单在任务内管理；下载策略、目录、登录凭据与资源配置按实例管理，在系统设置中选择实例后修改。页面职责见 [工作区页面说明](docs/workspace-layout.md)，任务操作与兼容说明见 [TASK_CENTER.md](TASK_CENTER.md)。

工作台按下载实例恢复最后成功启动的任务。切换任务只停止当前实例的旧任务；不同实例可下载不同任务，也可共同处理同一任务。下载实例页集中展示各实例的任务、实时视频、进度和速度。

支持“管理与下载一体 + 多实例共享 MySQL”：每台机器都可打开管理页面并参与下载，任务、统计和计费共享，目录、Cookie 和代理按实例独立。数据库在 `.env` 中配置，启动后在 `/setup` 页面配置实例地址和测试连接，服务固定为管理与下载一体，单台与多台使用同一套流程。旧角色配置升级时自动归一，完整部署和升级步骤见 [MULTI_INSTANCE.md](MULTI_INSTANCE.md)。

本版统一了任务计费、编辑版本和控制范围，并增加管理账户。未设置账户时只允许本机直接访问；访问 `/login`，使用状态目录 `console-bootstrap.key` 中的初始设置码创建管理员。创建后所有管理页面均需登录，支持管理员、操作员和只读账户。升级说明见 [第一阶段改造说明](docs/redesign-phase-one.md)。

长期运行可在“系统设置 → 磁盘容量管理”设置临时文件总预算（默认 20 GiB）和分类上限，自动清理测试文件、缓存和日志。空间不足时等待恢复，保留下载统计及账本；容量范围与部署说明见 [DISK_MANAGEMENT.md](DISK_MANAGEMENT.md)。

工作台的“并发与等待”显示渠道上限、共享连接、限流冷却和空间等待。系统设置可调整内置渠道额度，保存前提示与实例并发不匹配的设置。yt-dlp 默认先交付视频，再通过独立低频队列补下载指定语言字幕；可选字幕失败不影响视频成功及计费，也可选择必须完整或关闭。测试模式不创建字幕补下载任务。配置语义和验证记录见 [并发与字幕优化说明](docs/concurrency-ui-and-optimization.md)。

## Docker 部署

Compose 内置 FFmpeg、Node.js、Mihomo、Chromium、Xvfb 和 noVNC。连接已有远程 MySQL 时使用：

```bash
cp .env.remote-mysql.example .env
# 在 .env 填写 MYSQL_* 连接参数，并按需调整宿主机端口和视频目录
docker compose -f compose.remote-mysql.yaml config --quiet
docker compose -f compose.remote-mysql.yaml up -d --build
```

访问 `http://127.0.0.1:5000/setup`，输入启动日志中的“部署设置访问码”，在页面测试 MySQL 连接并保存。服务器部署时，可在 `.env` 设置 `WEB_BIND_IP`、`WEB_PORT` 和 `VIDEO_DOWNLOAD_DIR`。完整说明见 [DOCKER.md](DOCKER.md)、[MYSQL.md](MYSQL.md) 和 [YT5S_LINUX.md](YT5S_LINUX.md)。

需要一并部署 MySQL 8.4 时，使用 `compose.local-mysql.yaml`，环境模板为 `.env.local-mysql.example`，应用自动连接其中的 MySQL 服务，步骤见 [应用与 MySQL 一起部署](DOCKER.md#应用与-mysql-一起部署)。

## 本地启动

需要 Python 3.13+、FFmpeg、Node.js 或 Deno，以及已安装的依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe app.py
```

先在项目根目录 `.env` 中填写 MySQL 连接参数，PyCharm 直接运行 `app.py` 即可。打开 `http://127.0.0.1:5000/setup`，输入终端打印的部署设置访问码，配置实例名称并测试数据库连接。单台运行可不填实例地址，多台协作时填写彼此可达的本机 HTTP(S) 地址，ID 留空自动生成。数据库参数不能在页面修改。

数据库配置完整时自动启动服务。实例设置保存在本机状态目录的 `deployment.json`，其中不保存数据库连接。已运行服务修改实例设置后需重启，当前下载不会被保存操作中断；工作台侧栏可重新进入“部署设置”。访问码保存在同目录 `deployment.key`，每次启动都会打印。

启动时先提供设置页，再后台连接 MySQL、检查表结构及初始化实例。终端会打印当前阶段；数据库响应慢时仍可打开 `/setup` 查看阶段和等待时间。数据库参数错误时修改 `.env` 并重启；暂时性启动失败可在页面重试。

默认读取 `.env`，也可用 `--env-file` 指定其他文件。数据库只使用启动配置，旧页面保存的数据库参数不再生效；实例设置仍优先使用页面保存值，显式 CLI 实例参数优先于页面。未配置数据库时页面提示补齐配置文件，不创建业务 SQLite 数据库；已有数据库不会自动迁移。服务监听地址/端口、Docker 宿主机端口和卷映射仍由启动命令或 Compose 设置。

## 页面功能

- 任务详情支持输入 11 位视频 ID、完整视频链接和清单导入，工作台集中控制下载。
- 在系统设置选择下载实例，勾选下载器、排序并保存；每个实例独立保存下载顺序、画质、超时、分片并发、重试上限与正式/测试模式。修改只影响所选实例后续领取的视频，无需暂停或重启；正在执行的视频保留领取时快照，重试与跨实例接管使用当前执行实例的最新策略。
- 导入不要求 Cookie、浏览器或代理已就绪。任务只管理视频与账单，不复制或覆盖下载策略；同一任务可由不同实例按各自策略处理。旧任务和旧全局策略记录不再覆盖实例配置；正式交付与测试数据按每次实际执行模式分别记录。
- 按下载方式检查所需环境与登录；仅启用 downmp3 时无需浏览器、JavaScript 运行时或 YouTube Cookie，使用 ffprobe 校验成品。
- 新部署默认尽可能获取最高画质：yt-dlp 优先分辨率和帧率，不限制编码或分辨率，优先 MP4、必要时使用 MKV；yt5s 自动选网站提供下载操作的最高分辨率；downmp3 请求当前接口最高档 1080p，实际结果受视频源和第三方服务限制。各实例可在系统设置选择“尽可能最高画质”，已有成品不自动重新下载。
- 支持直连、手动代理、Clash 多订阅保存与手动切换、节点测速和自动轮换。在“网络与代理”中为订阅命名保存，再选择“切换到此订阅”；每个实例最多保存 20 个订阅，原有订阅会自动保留。首个订阅自动启用，新增备用订阅不改变当前连接；下载运行时需先停止领取并等待当前任务结束再切换。
- 支持 1–64 的传输并发上限，以及 yt5s、yt1d、Bergung 共享的浏览器并发数。自动模式按服务器资源分别控制解析准备和传输，支持代理故障冷却；配置及升级说明见 [自动吞吐](docs/throughput-mode.md)。
- 支持 Bergung / Cobalt 兼容渠道扩展，提供已实测入口目录和“自动”策略，按实际解析耗时、吞吐、成功率及当前负载分配任务；未知入口有限试探，相同后台共享额度，浏览器解析池复用，各渠道吞吐分别监控，见 [下载调度使用说明](docs/download-scheduler.md)。
- 支持指定目录保存、测试模式和下载统计；网盘保存暂未实现。
- 执行日志显示已结束的后台操作；下载工作台显示所选任务的实时下载进度；素材库支持封面和视频播放。
- 素材库右上角支持“清空素材库”：先暂停全部下载，输入“清空”确认后，后台删除当前服务本机素材目录及子目录中的视频和同名配套文件，并同步索引。下载历史、客户计费和去重记录保留；搜索和分页不影响清空范围。符号链接、目录联接和无关文件不会删除。

## 添加清单、启动与结算

1. 在任务中心新建客户任务、粘贴视频 ID 或导入 TXT / CSV。首页保留快捷新建入口；创建后进入任务中心管理，新任务保持待开始。
2. 在任务设置确认单价，在系统设置确认所选实例的下载策略，再到下载工作台开始当前任务。系统恢复只恢复领取，不会启动新任务或恢复已暂停实例；实例故障只隔离该实例，没有可用实例时任务显示等待原因并保留运行意愿。
3. 首页只展示运行中的视频，包含解析、转换与传输阶段，并显示当前阶段用时。数据库、代理控制接口和工具状态分别显示；代理控制接口可用不等于外网下载可用。错误用简短原因提示，技术日志在任务详情中手动展开。
4. “交付与执行统计”汇总客户任务的预计费用，支持导出交付和测试文件。客户、名称及单价统一到任务中心修改，下载策略在系统设置中按实例修改；多页面编辑发生冲突时保留输入并提示核对。测试文件删除前登记大小，单独统计、不计费。

执行会话和各下载器成功率统计继续保留，但会话不再生成账单或编辑单价。商业金额统一按客户任务汇总，包含归档和删除任务保留的历史交付；金额卡片不受执行会话筛选影响。单价留空为待定，0 为免费，历史未分类执行不补造费用。当前金额仍为预计费用，正式结算冻结属于后续阶段。

队列、任务账本和执行统计保存在数据库中。升级会增加账户表、迁移版本记录和任务编辑版本，不重建视频队列。新版页面使用 `/api/jobs/*`；`/api/downloads/resume` 与任务中心系统恢复共用控制服务。旧清单编辑接口已停用并返回 410；旧 `/api/downloads/start` 仅保留历史清单兼容用途。

## downmp3 API

在系统设置选择实例后勾选 downmp3，调整优先级并保存下载策略。例如只勾选 downmp3、yt5s，顺序设为 downmp3 → yt5s，失败后就自动尝试 yt5s，无需 Cookie；勾选 yt-dlp 后，开始前还会检查 YouTube Cookie。下载设置默认“尽可能最高画质”（当前请求 1080p），也可指定 360p、480p、720p、1080p；转换等待上限默认 300 秒，可设为 30–1800 秒。支持视频 ID 清单和 TXT / CSV 批量导入，暂不支持播放列表。

根据 [downmp3 接入文档](https://downmp3.yt/api-documentation) 中嵌入组件的实际调用流程，后端请求 `p.savenow.to/api/v2/download` 创建转换任务，轮询 `/api/progress` 获取 MP4 链接，再使用现有传输模块保存文件、封面和元数据。转换阶段单独显示进度；下载阶段显示实际下载字节数、速度和剩余时间。所有请求使用任务当前代理节点，不向第三方发送 YouTube Cookie；不占用 yt5s 浏览器并发名额。

下载后用 ffprobe 确认文件含音视频，再登记实际字节数。下载统计按 `downmp3` 独立统计成功率、失败数、计费大小和测试大小；测试模式删除成品前保留大小记录。临时网络错误和 429 / 5xx 按队列规则退避重试，转换等待有超时上限。

该站公开文档主要描述嵌入组件，后端接口来自组件当前实现，可能发生变更、限流或要求网站验证。遇到转换或下载失败时，按页面配置继续尝试下一下载器；没有后续下载器时报告失败。停止下载、磁盘已满、权限不足及缺少运行环境不会触发切换。它没有官方批量吞吐保证，建议先验证自己的节点和清单再扩大并发。

## yt1d 网页下载

在系统设置选择实例后，勾选 `yt1d` 并保存优先级，例如 `yt1d → downmp3 → yt5s`。只影响所选实例后续领取的视频。它使用 [yt1d.lol](https://yt1d.lol/) 当前网页的正常验证、解析和转换流程，无需 YouTube Cookie。执行结果与下载大小按 `yt1d` 独立统计。

实例下载设置支持 `yt1d_quality`：`best`（默认，网站实际提供的最高档）、`360`、`480`、`720`、`1080`、`1440`、`2160`。指定档位必须由网站提供，不会把请求值当成实际成品分辨率。`yt1d_timeout` 默认 180 秒，可设 30–1800 秒，分别限制网站验证/解析和转换等待；网页导航、表单和画质查找另有短超时。保存后后续领取和重试使用新策略，在途视频保持原配置。

运行需要 Chrome/Chromium、Playwright 和 ffprobe，Linux 需要显示环境（如 Xvfb）。使用现有远程 MySQL Compose 构建即可，无需新增 Python 依赖或数据库表。yt1d 与 yt5s **共享** `yt5s_browser_count` 浏览器并发上限和磁盘预算；解析完成后由现有传输模块保存视频、封面与元数据，并用 ffprobe 检查音视频后登记交付。测试模式同样先登记实际字节再清理，不计费。

网页、验证、解析及文件传输沿用当前任务代理出口，浏览器支持无账号密码的 HTTP(S) 代理或直连。网站可能要求人工验证，可通过现有远程桌面完成；验证或转换失败会按顺序切换到下一个下载器，临时 HTTP 错误和超时使用现有退避重试。缺少浏览器、磁盘资源不足等实例环境问题保留原有等待/隔离规则。

本地验证覆盖真实 Chromium 的模拟网站表单、画质选择与转换轮询，以及实际 MP4 传输、测试清理、错误文件回退和交付去重。线上探测可打开网站，但本机无头浏览器未完成网站验证，因此尚未验证该出口上的真实 yt1d 下载成功率。

## Bergung 网页下载

在系统设置选择实例后，勾选 Bergung 并保存下载顺序。它通过 `https://bergung.hoffnungfuerdiezukunft.net/` 的正常网页流程解析单个 YouTube 视频，不使用 YouTube Cookie；画质和验证等待上限按实例配置。最高画质请求网站可用的最高档，优先 AV1，成品可能是 WebM。yt5s、yt1d 和 Bergung 共享浏览器并发名额。

网站可能要求在远程桌面手动完成 Cloudflare Turnstile 验证。超时、验证失败或网站返回不支持的选择/本地处理结果时，本次下载按已保存的顺序尝试下一下载器；不能保证无人值守成功。解析出的地址交由现有传输流程下载，成品须通过 FFprobe 音视频校验后才登记交付和计费。测试模式会先登记大小再删除文件。

## 命令行

```powershell
# 启动 Web 服务
.\run.ps1 -Mode web

# 直接使用 yt-dlp 下载
.\run.ps1 -Mode download -Url "https://www.youtube.com/watch?v=视频ID"

# 打开独立 YouTube 登录浏览器
.\run.ps1 -Mode youtube-login

# 运行自动化测试
.\run.ps1 -Mode tests
```

YouTube Cookie 可在页面上传 Netscape 格式文件，也可使用独立浏览器登录。登录说明见 [YOUTUBE_LOGIN.md](YOUTUBE_LOGIN.md)。

当前 Cookie 会话对公开视频返回 `Video unavailable`，且尚未接收媒体数据时，yt-dlp 会在同一节点不带 Cookie 重试一次，保留已上传的 Cookie。明确的 Cookie 失效、登录验证或其他错误仍按原规则处理；匿名访问也失败时显示下载错误。

下载期间的 YouTube 登录预检如遇网络超时或暂时无法确认，任务会延迟 30 秒自动重试，保留任务且不暂停实例；明确登录失败仍需重新登录或验证。故障定位与重试规则见 [登录预检恢复说明](docs/youtube-auth-preflight-recovery-20261030.md)。

## 数据迁移与容量

旧 SQLite 数据迁移到 MySQL 使用 [MYSQL.md](MYSQL.md) 中的 `scripts/migrate_mysql.py`。大批量导入、并发模型和容量边界见 [SCALING.md](SCALING.md)。

项目仅处理用户有权下载的内容。

下载器优先级也可在 YAML 中配置，例如：

```yaml
download_methods:
  - downmp3
  - yt5s
```

至少选择一个，不能重复。旧的 `download_method` 配置仍可读取；旧的 `yt5s_fallback` 自动对应 `yt5s → yt-dlp`。已导入或排队的任务在开始时读取当前已保存的顺序，运行中的任务使用本次启动配置。各下载器使用各自的画质配置；切换后重新下载，避免拼接不同编码的残留文件。
